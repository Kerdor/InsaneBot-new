# Cog / Module Management

## COG-001 — Несколько источников расширений
Расширения могут загружаться из нескольких директорий с явным порядком приоритета.

## COG-002 — Временные источники
Источник расширений может существовать только до перезапуска.

## COG-003 — Отдельное хранилище сторонних расширений
Сторонние модули устанавливаются в отдельную директорию, не смешанную с core-модулями.

## COG-004 — Просмотр путей и их приоритета
Команда диагностики показывает install path, core path, временные и пользовательские пути.

## COG-005 — Проверка безопасного пути
Нельзя подключать data/core директории; подозрительный package path требует подтверждения.

## COG-006 — Поиск доступных модулей
Бот может динамически перечислять все доступные расширения и фильтровать невалидные имена.

## COG-007 — Пакетная загрузка/выгрузка/перезагрузка
Несколько модулей можно обработать одним вызовом.

## COG-008 — Детальный batch-report
Результат пакетной операции разделяется на успешные, уже активные, отсутствующие, невалидные и завершившиеся ошибкой модули.

## COG-009 — Последний traceback
Последнее внутреннее исключение сохраняется для последующего просмотра отдельной диагностической командой.

## COG-010 — Защита от конфликтов команд
При загрузке нового расширения конфликт существующей команды/alias обнаруживается и объясняется вместо тихого перезаписывания.

## COG-011 — Горячая перезагрузка импортов
Reload должен очищать/обновлять импортированные модули, чтобы изменения кода реально применялись.

## COG-012 — Инвалидация import cache
После установки нового расширения отдельно инвалидировать importlib cache.

## COG-013 — Управление путями с сохранением/без сохранения
Одна и та же команда может добавить путь временно или персистентно.

## COG-014 — Защита от невалидных Python package names
Модули с именами, которые нельзя корректно импортировать как Python identifier, автоматически исключаются.

## COG-015 — Фиксация версии расширения
Установленный модуль можно закрепить на текущем commit/revision, чтобы обычное обновление его не изменяло.

## COG-016 — Массовая pin/unpin операция
Несколько установленных модулей можно одновременно закрепить или открепить от автоматических обновлений.

## COG-017 — Отдельная проверка обновлений без установки
Бот может сначала показать, какие расширения устарели, не изменяя их состояние.

## COG-018 — Обновление с явным reload-поведением
Обновление расширений принимает отдельный флаг: перезагрузить их сразу после обновления или оставить выгруженными/в текущем состоянии.

## COG-019 — Обновление до конкретной revision
Модуль можно обновить до указанного commit/revision, а не только до HEAD ветки.

## COG-020 — Диагностика неоднозначной короткой revision
Если короткий commit SHA совпадает с несколькими объектами, бот показывает возможные кандидаты вместо произвольного выбора.

## COG-021 — Метаданные репозитория расширений
Для источника хранятся URL, ветка, авторы и описание, а команда info показывает эти данные отдельно.

## COG-022 — Установочные сообщения стороннего модуля
После установки модуль может вывести собственное install message с подстановками текущего prefix и имени бота.

## COG-023 — Защита установки соглашением
Перед добавлением стороннего репозитория/модуля бот может потребовать явного подтверждения условий установки.

## COG-024 — Переустановка зависимостей всех установленных модулей
Отдельная служебная операция может переустановить requirements и shared libraries для всех установленных расширений.
