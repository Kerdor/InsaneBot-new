# PYTHON-DISCORD INFO 2 — Дополнительные информационные механики

Уникальные механики из `python-discord/bot/exts/info/`, вынесенные отдельно, чтобы не раздувать основной файл и не дублировать уже занесённые идеи.

## PDIS-I2-001 — Raw Discord API inspector для конкретного сообщения
- Команда позволяет получить фактический raw API response выбранного Discord-сообщения.
- Сообщение можно передать аргументом либо просто вызвать команду как reply на нужное сообщение.
- Перед запросом дополнительно проверяется, имеет ли вызывающий право читать канал исходного сообщения.
- Полезно как диагностический инструмент для отладки embeds, attachments и других Discord API-полей.

## PDIS-I2-002 — Два режима представления raw-данных: human-readable и JSON
- Обычный режим форматирует вложенные структуры как человекочитаемый список полей с выравниванием ключей.
- Отдельный подкомандный режим выдаёт данные через `pprint` в форме, удобной для копирования в Python.
- В выводе отдельно нумеруются несколько embeds и attachments одного сообщения.
- Markdown-символы внутри диагностических данных экранируются, чтобы raw-ответ не ломал собственное оформление.

## PDIS-I2-003 — Автоматический paste fallback для диагностических данных
- Если raw API output не помещается в лимит Discord-сообщения, бот автоматически переносит полный результат во внешний paste-сервис.
- Пользователь получает короткое сообщение со ссылкой вместо ручного копирования огромного ответа.
- Отдельно обрабатываются ситуации, когда paste-сервис сам отклоняет слишком большой файл или недоступен.

## PDIS-I2-004 — Rules lookup одновременно по номерам и ключевым словам
- Команда правил принимает в одном запросе смесь числовых индексов и keyword aliases.
- Keywords динамически загружаются из API, поэтому их не нужно хардкодить в командном обработчике.
- Дубликаты удаляются, итоговые правила сортируются по номеру, а некорректные индексы проверяются отдельно.
- Результат выводится через paginator, поэтому несколько выбранных правил не упираются в лимит одного сообщения.

## PDIS-I2-005 — Тихий staff-alert на запросы правил обычными участниками
- Запрос конкретных правил от пользователя без staff/helper роли может создавать внутреннее уведомление для команды.
- Alert содержит автора, канал и jump URL исходного сообщения, а также номера запрошенных правил.
- В специально выбранном служебном канале такие уведомления можно не отправлять, чтобы не создавать собственный spam loop.

## PDIS-I2-006 — Frontmatter-конфигурация отдельных информационных тегов
- Каждый tag хранится отдельным ресурсом и может иметь собственные metadata.
- Поддерживаются aliases, список ролей `restricted_to` и готовая конфигурация Discord Embed.
- Поэтому один общий tag engine может содержать публичные, staff-only и оформленные особым embed образом ответы без отдельного кода для каждого тега.

## PDIS-I2-007 — Cooldown конкретного tag отдельно в каждом канале
- Cooldown хранится внутри конкретного tag как mapping `channel -> expiration`.
- Один и тот же tag может быть снова вызван в другом канале, даже если в предыдущем он ещё находится на cooldown.
- Это защищает популярные информационные ответы от повторного спама, не вводя глобальный cooldown на весь сервер.

## PDIS-I2-008 — Иерархические группы тегов с отдельным просмотром
- Tags могут находиться внутри групп, а команда с именем группы вместо tag выводит доступные элементы этой группы.
- Общий список группируется и сортируется, пустые для конкретного пользователя группы автоматически не показываются.
- Если введено имя группы без явного tag, engine сначала пытается интерпретировать его как группу, а уже затем искать tag/suggestions.

## PDIS-I2-009 — Fuzzy tag suggestions с учётом прав доступа
- При ошибке в имени tag бот не показывает произвольные совпадения: suggestions фильтруются по доступности конкретному пользователю.
- Поиск использует несколько порогов сходства и выбирает первый уровень, на котором нашлись результаты.
- Для группового и обычного имени применяются разные стратегии fuzzy matching.
- Если найдено ровно одно уверенное совпадение, tag может быть выбран автоматически вместо дополнительного вопроса.

## PDIS-I2-010 — Немедленное публичное событие при повышении уровня поддержки
- Изменение Patreon-role отслеживается через member update и сравнивает старый и новый максимальный tier.
- Уведомление отправляется только при повышении уровня, поэтому обычные изменения профиля и понижения не создают повторных сообщений.
- Это можно обобщить на любые role-based уровни поддержки, подписки или статуса пользователя.

## PDIS-I2-011 — Динамически подключаемые источники документации
- Модератор/разработчик может добавить внешний documentation inventory через команду, указав package name и URL `objects.inv`.
- Если base URL не задан, он автоматически выводится из URL inventory.
- Источник можно удалить отдельной командой, после чего inventories и соответствующий cache обновляются заново.
- Это превращает документационный модуль из набора захардкоженных сайтов в управляемый каталог внешних источников.
