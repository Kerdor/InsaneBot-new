# Access Control / Allowlist / Blocklist

Уникальные механики контроля доступа из `Cog-Creators/Red-DiscordBot`.

## ACCESS-001 — Глобальный blocklist
Глобальный список пользователей/ролей, которым запрещён запуск команд во всех серверах бота.

## ACCESS-002 — Локальный blocklist сервера
Отдельный список пользователей/ролей для конкретного сервера.

## ACCESS-003 — Глобальный allowlist
Режим, при котором запуск команд разрешён только пользователям/ролям из глобального списка.

## ACCESS-004 — Локальный allowlist
Сервер может ограничить выполнение команд только выбранными пользователями/ролями.

## ACCESS-005 — Allowlist по пользователю или роли
В списки доступа можно добавлять как конкретного пользователя, так и роль, чтобы участник наследовал доступ через роль.

## ACCESS-006 — Управление списками несколькими объектами
Добавление/удаление нескольких пользователей и ролей за один вызов команды.

## ACCESS-007 — Работа с ID без mention
Пользователя можно указать числовым Discord ID, что удобно для управления доступом к отсутствующим/неразрешённым mention-объектам.

## ACCESS-008 — Очистка списка доступа
Отдельная операция полного сброса локального allowlist/blocklist вместо ручного удаления элементов.

## ACCESS-009 — Диагностика причины отказа
При невозможности выполнить команду диагностическая система должна показывать, какой именно слой доступа сработал: глобальный/локальный allowlist, blocklist, channel/server ignore или command/cog check.

## ACCESS-010 — Безопасное восстановление доступа
Если локальный allowlist блокирует самого пользователя, диагностика должна предлагать два пути: добавить пользователя/роль в allowlist либо полностью очистить локальный allowlist.

## ACCESS-011 — Исключение владельца из обычных ограничений
Глобальные проверки доступа должны учитывать owner-level bypass, чтобы администратор бота не заблокировал себе критический доступ обычной ACL-настройкой.
