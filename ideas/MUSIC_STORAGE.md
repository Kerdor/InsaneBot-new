# MUSIC STORAGE / INFRA — Банк идей

Механики хранения и служебной инфраструктуры `ItzSudhan/Discord-MusicBot` (v5), найденные в `util/`.

- MUSIC-S001 — Общий DB manager поддерживает несколько именованных JSON-баз через единый registry `dbList.json`.
- MUSIC-S002 — Каждая именованная база хранит абсолютный путь к собственному JSON-файлу, а runtime держит данные в Map по имени.
- MUSIC-S003 — При старте registry автоматически восстанавливает подключённые JSON-базы из `dbList`.
- MUSIC-S004 — Global database существует как специальная предзарегистрированная база `global`.
- MUSIC-S005 — Запись и удаление JSON выполняются через отдельные очереди, обслуживаемые фоновым loop с периодом 100 мс.
- MUSIC-S006 — Ошибка записи базы не роняет приложение: логируется конкретный путь и причина, после чего операция возвращает false.
- MUSIC-S007 — Пути баз валидируются как строки, указывающие на `.json`, до чтения/записи/удаления.
- MUSIC-S008 — Создание базы автоматически добавляет её в persistent registry, поэтому новые базы переживают перезапуск.
- MUSIC-S009 — Удаление базы одновременно ставит файл в delete queue и убирает запись из registry.
- MUSIC-S010 — Guild DB создаётся лениво при первом getter/setter обращении, а не отдельной командой создания.
- MUSIC-S011 — Для каждой guild используется отдельный JSON-файл с именем, производным от guild id.
- MUSIC-S012 — Guild DB предоставляет специализированные getter/setter вместо выдачи наружу произвольного внутреннего объекта базы.
- MUSIC-S013 — Getter guild setting возвращает безопасное default value при отсутствии свойства.
- MUSIC-S014 — Guild DB поддерживает полное удаление всех данных конкретной guild отдельной операцией.
- MUSIC-S015 — Конфигурация загружается с fallback: сначала пытается `dev-config`, затем обычный `config`, а при отсутствии обоих возвращает понятную ошибку.
- MUSIC-S016 — `getLavalink` выбирает любой подключённый audio node из manager, абстрагируя команды от конкретного node identifier.
- MUSIC-S017 — `getChannel` централизует проверки voice access: пользователь должен быть в voice channel, совпадать с каналом бота и иметь joinable permissions.
- MUSIC-S018 — Служебный channel resolver возвращает `false` после уже отправленного пользователю error embed, позволяя вызывающим командам просто прекратить выполнение.
