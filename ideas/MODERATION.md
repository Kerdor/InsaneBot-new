# Модерация

### MOD-001 — Проверка иерархии ролей перед модерацией

### MOD-002 — Unwarn
- Снятие конкретного предупреждения.

### MOD-003 — Удаление всех предупреждений
- Полная очистка истории предупреждений пользователя.

### MOD-004 — Timeout и снятие timeout

### MOD-005 — Ticket как модерационный канал

### MOD-006 — Claim-система тикетов

### MOD-007 — Мгновенное закрытие тикета

### MOD-008 — Мгновенное удаление тикета

### MOD-014 — Keyword-фильтры

## Cog-Creators/Red-DiscordBot

### MOD-015 — Продвинутая очистка сообщений по условиям
- Последние сообщения, конкретный пользователь, текстовый фильтр, диапазон между двумя сообщениями, всё до/после сообщения.
- Reply можно использовать как границу вместо ручного ID.

### MOD-016 — Очистка сообщений самого бота
- Отдельная cleanup bot удаляет сообщения бота и команды.
- Учитываются обычные команды, алиасы и custom commands.

### MOD-017 — Очистка собственных сообщений с фильтром текста
- Можно фильтровать сообщения бота по тексту.
- При наличии Manage Messages используется bulk delete, иначе медленное удаление собственных сообщений.

### MOD-018 — Удаление дубликатов сообщений
- duplicates/spam ищет повторы среди последних сообщений.
- Оставляется первая копия.
- Сравниваются автор, текст, embeds, stickers и reference.
- Сложные сообщения с attachments/components/poll/activity исключаются.

### MOD-019 — Защита массового удаления подтверждением
- При удалении более 100 сообщений требуется подтверждение.
- Есть assume-yes контекст.
- Prompt и ответ могут удаляться после операции.

### MOD-020 — Настраиваемые уведомления после cleanup
- Можно показать количество удалённых сообщений.
- Уведомление автоматически удаляется через несколько секунд.
- Настройка отдельная для сервера.

### MOD-021 — Warning points
- Каждое предупреждение имеет числовой вес.
- Хранится суммарное количество warning points.
- Преднастроенная причина может задавать points.

### MOD-022 — Автодействия по warning points
- Именованные правила с порогом points.
- При превышении выполняется действие/команда.
- При снижении points может выполняться отдельное действие.
- Правила сортируются по порогу.

### MOD-023 — Именованные причины warn
- Причина имеет имя, описание и points.
- Warn может ссылаться на зарегистрированную причину.
- Custom reasons можно разрешить или запретить.

### MOD-024 — Независимая настройка DM для warn
- Отдельный toggle отправки предупреждения в DM.

### MOD-025 — Отдельный канал warn
- Предупреждения можно направлять в специальный канал.
- При отключении используется канал команды.

### MOD-026 — Настройка показа модератора в предупреждениях
- Имя модератора можно показывать или скрывать в DM и self-view.

### MOD-027 — Self-view warnings через DM
- Просмотр собственных предупреждений можно направлять в DM.

### MOD-028 — История usernames/display names/nicknames
- Хранятся предыдущие username, global display name и server nickname.
- Отдельная команда и отображение в userinfo.
- Последние 20 значений каждого типа.
- Вывод защищается от массовых упоминаний и вредных инвайтов.

### MOD-029 — Rename с полноценной иерархической проверкой
- Пустой аргумент снимает nickname.
- Длина 2–32 символа.
- Проверяются права бота, роль бота, роль вызывающего и владелец сервера.

### MOD-030 — Автоудаление повторяющихся сообщений в реальном времени
- Для пользователя отслеживаются подряд повторяющиеся сообщения.
- При достижении порога сообщение удаляется.
- Порог настраивается; специальное значение отключает функцию.
- История повторов хранится короткой очередью.

### MOD-031 — Два режима подсчёта упоминаний
- Можно считать все повторные упоминания или только уникальные сущности.
- Это позволяет отдельно ловить спам одного пользователя и массовые уникальные упоминания.

### MOD-032 — Reinvite после unban с цепочкой fallback
- После unban можно автоматически выдать приглашение.
- Приоритет: vanity URL → постоянный invite → временный invite.

### MOD-033 — Обязательная причина для модерационных действий
- Сервер может централизованно требовать reason для moderation actions.

### MOD-034 — Дни удаления сообщений при ban по умолчанию
- Можно задать количество удаляемых при ban дней сообщений.
- Диапазон 0–7 дней.

### MOD-035 — Default tempban duration
- Если время tempban не указано, используется серверное значение по умолчанию.
- Поддерживаются человекочитаемые составные длительности.
- Фоновая задача следит за истечением банов.

### MOD-036 — Дополнительное поле в DM о бане
- В DM о бане можно добавить отдельный настраиваемый текст.
- Например, ссылку на апелляцию или инструкции.

### MOD-037 — Ролевой mute вместо permission-based mute
- Mute может работать через специально назначенную mute-role вместо channel permission overwrites.
- Режим выбирается настройкой.

### MOD-038 — Канальный mute
- Пользователь может быть замьючен только в конкретном канале.
- Состояние mute разных каналов хранится независимо.

### MOD-039 — Автоматический unmute по времени
- Серверный и канальный mute могут иметь время окончания.
- Фоновый обработчик автоматически снимает ограничение.
- Несколько канальных mute одного пользователя можно обрабатывать группой.

### MOD-040 — Notification channel для проблем mute
- Ошибка автоматического unmute отправляется в отдельный notification channel.
- Недоступность канала не должна ломать фоновые проверки.

### MOD-041 — DM-уведомления о mute/unmute
- Mute/unmute может сопровождаться DM.
- Можно отдельно показывать модератора и причину.

### MOD-042 — Защита Administrator от mute
- Пользователь с Administrator не может быть замьючен обычной mute-операцией.

### MOD-043 — Graceful ожидание готовности moderation cog
- Команды mute ждут завершения асинхронной инициализации вместо работы с частично загруженным состоянием.
- При ошибке инициализации действие не выполняется в неконсистентном состоянии.

## codebymitch/TitanBot

### MOD-044 — Централизованный ModerationService
- Ban, kick, timeout и unban вынесены в единый сервис.
- Команды остаются тонкими orchestration-слоями.

### MOD-045 — Единая проверка иерархии модератора
- Проверка позиции высшей роли вызывающего вынесена в переиспользуемый метод.
- Server owner получает отдельный bypass.

### MOD-046 — Отдельная проверка иерархии бота
- Перед действием отдельно проверяется высшая роль самого бота относительно цели.
- Ошибка сообщает обе роли и что именно нужно переставить.

### MOD-047 — Человекоориентированные сообщения об иерархии
- Ошибка не ограничивается "permission denied": пользователю показываются названия конфликтующих ролей и направление исправления.

### MOD-048 — Безопасный moderation assert
- Иерархия модератора и бота проверяется до выполнения действия.
- Нарушение превращается в типизированную permission-ошибку.

### MOD-049 — Защита self-targeting
- Ban, kick и timeout явно запрещают модерировать самого вызывающего.

### MOD-050 — Защита bot-targeting
- Ban, kick и timeout явно запрещают применять действие к самому боту.

### MOD-051 — Запрет kick/timeout для отсутствующего участника
- Команды, работающие с Member, отдельно проверяют, что цель действительно присутствует на сервере.

### MOD-052 — Ban отсутствующего пользователя при повышенных правах
- Ban может выполняться по User, даже если Member отсутствует.
- Для такой цели требуется Server Owner, Manage Server или Administrator.

### MOD-053 — Проверка бан-листа перед unban
- Unban сначала получает текущие bans и убеждается, что пользователь действительно забанен.
- Повторный unban превращается в понятную validation-ошибку.

### MOD-054 — ID/mention нормализация для unban
- Unban принимает строку и очищает mention-формат до числового ID.
- ID валидируется по Discord-формату до обращения к API.

### MOD-055 — Поиск User перед unban
- После валидации ID бот получает актуальный User объект через client.users.fetch.
- Неизвестный ID выдаёт отдельную пользовательскую ошибку.

### MOD-056 — Case ID как результат модерации
- Ban, kick и timeout возвращают идентификатор созданного moderation case.
- Команда показывает Case ID непосредственно модератору.

### MOD-057 — Полная метаинформация moderation case
- В case сохраняются target, executor, reason и дополнительные metadata.
- Для ban отмечаются permanent и deleteDays; для timeout — durationMs.

### MOD-058 — Сохранение moderation action до/вместе с ответом
- Модерационное действие и запись в централизованный case/log pipeline связаны одним вызовом.
- Команда получает caseId как подтверждение созданной записи.

### MOD-059 — Безопасные default reasons
- Ban, kick, timeout и unban используют "No reason provided", если причина не передана.
- Warn, напротив, требует reason явно.

### MOD-060 — Warn только для участника текущего сервера
- Предупреждение не создаётся для User, который не является Member guild.

### MOD-061 — Warn требует обязательную причину
- Slash option reason помечен required и дополнительно проверяется в runtime.
- Таким образом, UI-валидация и серверная валидация дублируют защиту.

### MOD-062 — Warning counter в реальном времени
- WarningService возвращает ID нового предупреждения и актуальный totalCount.
- Модератор сразу видит номер/общее количество предупреждений.

### MOD-063 — Уникальный ID отдельного предупреждения
- Каждому warn присваивается собственный warningId, который также попадает в metadata audit-записи.

### MOD-064 — Нумерация предупреждения как порядкового события
- Для нового warn сохраняются warningNumber и totalWarns, позволяя восстановить порядок нарушений.

### MOD-065 — Фиксация времени предупреждения на стороне команды
- Warn передаёт timestamp в WarningService явно.
- История не зависит от времени форматирования интерфейса.

### MOD-066 — Ограниченный набор длительностей timeout
- Slash-команда предлагает фиксированные варианты: 5/10/30 минут, 1 час, 6 часов, 1 день, 1 неделя.
- Это снижает количество ошибок при ручном вводе времени.

### MOD-067 — Человекочитаемое отображение timeout duration
- Числовое значение timeout конвертируется обратно в название выбранного периода при ответе.

### MOD-068 — Проверка `moderatable` перед timeout
- Даже после role hierarchy бот проверяет Discord-флаг, действительно ли Member может быть timeout-нут.

### MOD-069 — Проверка `kickable` перед kick
- Перед kick проверяется фактическая возможность Discord API удалить Member.
- В ошибке объясняется типичная причина: Administrator/managed role/роль бота.

### MOD-070 — Запрет untimeout неактивного timeout
- Снятие timeout сначала проверяет `isCommunicationDisabled()`.
- Если ограничения нет, операция не отправляет лишний API-запрос.

### MOD-071 — Отдельная причина для снятия timeout
- Service-level untimeout имеет специальный default reason `Timeout removed by moderator`.
- Причина передаётся и в Discord API, и в audit log.

### MOD-072 — Mass moderation с индивидуальным результатом
- Mass kick/ban не падает целиком из-за одной цели.
- Для каждой цели отдельно фиксируется success, skipped или failed.

### MOD-073 — Массовая обработка максимум 20 пользователей
- Mass kick/ban нормализует список и ограничивает его первыми 20 ID.
- Это ограничивает размер одной операции.

### MOD-074 — Разделители пробел/запятая в массовых командах
- Один строковый параметр поддерживает одновременно пробелы и запятые как разделители.
- Mention-формы превращаются в обычные ID.

### MOD-075 — Отбрасывание невалидных ID в mass actions
- Массовая команда фильтрует пустые элементы и значения, не соответствующие числовому ID.

### MOD-076 — Защита self/bot в mass actions
- Self ID и bot ID проверяются на уровне всего входного списка до начала обработки.

### MOD-077 — Индивидуальный hierarchy skip вместо остановки mass action
- Если одна цель выше модератора или бота, она попадает в skipped, а остальные цели продолжают обрабатываться.

### MOD-078 — Проверка фактической `kickable` в mass kick
- Даже после hierarchy checks каждая цель отдельно проверяется через Discord `member.kickable`.

### MOD-079 — Последовательное выполнение массовой модерации
- Mass ban/kick выполняется по одной цели за раз.
- Это упрощает контроль частичных результатов и ошибок API.

### MOD-080 — Per-command abuse protection для mass actions
- Mass ban и mass kick ограничиваются 3 попытками за 60 секунд.
- Защита задаётся рядом с описанием команды.

### MOD-081 — Более строгий abuse limit для purge
- Purge имеет собственный лимит 5 попыток за 60 секунд.
- Abuse policy может отличаться для разных destructive-команд.

### MOD-082 — Самый высокий abuse limit для say
- Say ограничен 8 попытками за 60 секунд.
- Частота определяется отдельно от purge/mass moderation.

### MOD-083 — Purge с верхним лимитом Discord bulk delete
- Amount ограничен 1–100.
- Команда предварительно fetch-ит ровно запрошенное число сообщений.

### MOD-084 — `bulkDelete(..., true)` с игнорированием старых сообщений
- Purge использует Discord bulk deletion с фильтрацией сообщений, которые нельзя удалить bulk-операцией из-за возраста.

### MOD-085 — Автоудаление ephemeral-ответа purge
- После успешной очистки служебный ответ удаляется через 3 секунды.
- Ошибка удаления ответа только логируется debug-уровнем.

### MOD-086 — Явное предупреждение о лимите 14 дней
- Ошибка purge сообщает модератору, что сообщения старше 14 дней нельзя удалить bulk delete.

### MOD-087 — Lock через permission overwrite @everyone
- Lock не меняет настройки канала глобально, а устанавливает SendMessages=false именно для @everyone.

### MOD-088 — Проверка состояния перед lock
- Повторный lock не выполняет лишний overwrite, если @everyone уже не может отправлять сообщения.

### MOD-089 — Unlock только явного lock-состояния
- Unlock не перезаписывает разрешения, если канал уже разрешает отправку или не имеет явного запрета.

### MOD-090 — Audit reason для lock/unlock
- Permission overwrite получает reason с именем модератора.
- Причина сохраняется на стороне Discord audit log.

### MOD-091 — Контекст канала в lock/unlock audit
- В событие передаются channelId и название родительской категории.
- Это облегчает последующее расследование действия.

### MOD-092 — Staff DM с anonymous-режимом
- Staff-команда DM имеет boolean anonymous.
- В анонимном режиме получатель видит `Message from the Staff Team` вместо имени конкретного модератора.

### MOD-093 — DM-команда запрещена в личных сообщениях
- Slash-команда использует `setDMPermission(false)` и предназначена только для guild staff.

### MOD-094 — DM staff требует Moderate Members
- Отправка служебного DM доступна пользователям с Moderate Members.

### MOD-095 — Защита DM от bot targets
- Команда не отправляет служебные сообщения bot accounts.

### MOD-096 — Sanitize перед отправкой staff DM
- Markdown сообщения очищается до отправки пользователю.
- В лог попадает длина уже sanitised-содержимого.

### MOD-097 — Обработка закрытых DM
- Discord error code 50007 превращается в понятное сообщение, что у пользователя могут быть отключены личные сообщения.

### MOD-098 — Лимит DM в 2000 символов
- Staff DM проверяет длину и отказывает до API-вызова при превышении Discord message limit.

### MOD-099 — Say с выбором текстового канала
- Say может отправить сообщение в выбранный channel или использовать текущий текстовый channel по умолчанию.
- Разрешены GuildText и GuildAnnouncement.

### MOD-100 — Say не работает в неподходящем текущем канале
- Если channel option не задан и текущий канал не является текстовым/announcement, команда требует выбрать текстовый канал.

### MOD-101 — Двойная permission preflight для say
- Перед отправкой проверяются права вызывающего и самого бота в целевом канале.
- Ошибки разграничены: пользователь не может писать или бот не может писать.

### MOD-102 — Sanitized plain-message say
- Say очищает пользовательский ввод через общий sanitizeInput и повторно защищает от пустого сообщения.

### MOD-103 — Jump link после say
- После публикации бот возвращает staff-сообщение со ссылкой прямо на созданное сообщение.

### MOD-104 — Усечённая причина say в audit log
- Сообщение длиннее 200 символов не пишется целиком в reason: сохраняется первые 197 символов и `...`.
- Полная длина отдельно хранится в metadata.

### MOD-105 — Cases как отдельный просмотрщик moderation history
- Команда объединяет bans, kicks, timeouts и warnings в единый интерфейс cases.

### MOD-106 — Фильтр cases по типу действия
- Есть готовые фильтры All/Bans/Kicks/Timeouts/Warnings.
- Фильтр переводится в action-поле backend query.

### MOD-107 — Фильтр cases по пользователю
- Cases можно ограничить конкретным User ID без ручного ввода ID.

### MOD-108 — Настраиваемый limit просмотра cases
- Limit имеет диапазон 1–50 и default 10.

### MOD-109 — Пагинация cases по 5 записей
- Независимо от выбранного backend limit интерфейс показывает максимум 5 cases на страницу.

### MOD-110 — Page info button как disabled navigation state
- UI показывает `Page X/Y` отдельной disabled-кнопкой между Previous и Next.

### MOD-111 — Disable невозможной навигации
- Previous отключён на первой странице, Next — на последней.

### MOD-112 — Owner-only case navigation
- Collector принимает интеракции только от пользователя, который запустил `/cases`.
- Другим выдаётся ephemeral объяснение и предложение запустить собственный просмотр.

### MOD-113 — Автоматическое истечение case collector
- Навигация `/cases` живёт 120 секунд.
- После timeout все кнопки принудительно disabled.

### MOD-114 — User notes с типизацией
- Notes поддерживают `warning`, `positive`, `neutral` и `alert`.
- Тип хранится вместе с содержимым заметки.

### MOD-115 — User notes как отдельная история от moderation cases
- Служебные заметки хранятся per guild/user и не требуют превращения каждой заметки в ban/kick/warn case.

### MOD-116 — Четыре операции usernotes
- Единый command family поддерживает add, view, remove и clear.

### MOD-117 — Usernote ограничен 1000 символами
- Текст trim-ится и отклоняется при пустом результате.
- Слишком длинные заметки не попадают в DB.

### MOD-118 — Sanitization usernotes
- Note content проходит sanitization до сохранения.
- Это уменьшает риск вредного markdown/mention payload в staff history.

### MOD-119 — Метаданные автора и времени usernote
- Каждая note содержит note ID, author tag/id и ISO timestamp.
- История позволяет понять кто и когда оставил запись.

### MOD-120 — Newest-first usernote view
- При просмотре заметки сортируются от новых к старым.
- Пользовательский индекс соответствует именно этому отображению.

### MOD-121 — Удаление usernote через visible index mapping
- Remove не удаляет элемент по исходному DB index: команда сначала восстанавливает соответствующий note из отсортированного списка.

### MOD-122 — Clear usernotes с количеством удалённых записей
- Clear сообщает модератору, сколько notes было удалено.

### MOD-123 — Graceful moderation command errors
- Команды ловят API/service errors, логируют техническую причину и возвращают безопасное пользовательское сообщение.

### MOD-124 — Safe interaction defer для destructive moderation
- Mass actions, purge, lock/unlock, DM, cases и timeout используют helper безопасного defer.
- Если defer не удался, команда прекращает выполнение вместо попытки второго ответа.

### MOD-125 — Типизированные пользовательские ошибки
- Validation, permission, user-input и unknown ошибки проходят через общий error handler.
- Технические детали отделяются от сообщения для пользователя.

### MOD-126 — Moderation case filtering с guild isolation
- Cases запрашиваются с guild ID как обязательным scope.
- История другого сервера не должна смешиваться с текущей.

### MOD-127 — Audit metadata для массового действия
- Успешные mass ban/kick получают отдельные metadata-флаги `massBan`/`massKick`.
- Это позволяет отличить массовую операцию от обычного действия.

### MOD-128 — Частично успешный итог mass action
- Итоговый embed показывает три независимые группы: Successfully, Skipped и Failed.
- Один неудачный target не скрывает результаты остальных.

### MOD-129 — Причина каждой пропущенной цели mass action
- Для hierarchy skip возвращается конкретное объяснение роли модератора или бота.
- Для неподходящей цели фиксируется отдельная причина, например User not in server или not kickable.

### MOD-130 — Логирование каждой успешной цели mass action
- Mass ban/kick создаёт отдельное moderation event для каждой реально выполненной цели, а не одну агрегированную запись.

### MOD-131 — Permanent-флаг для mass ban
- Массовый ban явно помечается metadata `permanent: true`.
- Это отделяет его от будущих временных банов.

### MOD-132 — Delete-days параметр mass ban
- Mass ban принимает delete_days 0–7 для Discord удаления истории сообщений цели.
- Значение валидируется на уровне slash option.

### MOD-133 — Разные permission levels для moderation commands
- Kick/masskick требуют Kick Members, ban/massban/unban — Ban Members, timeout/untimeout/warn/dm — Moderate Members, purge/say/usernotes — Manage Messages, lock/unlock — Manage Channels, cases — View Audit Log.

### MOD-134 — Explicit guild-only moderation UI
- Команды, которым нужен guild context, отключают DM permission там, где это явно необходимо.

### MOD-135 — Повторная проверка permissions в runtime
- Наличие slash default permission не считается достаточным для критических channel operations: фактические права канала проверяются непосредственно перед действием.
