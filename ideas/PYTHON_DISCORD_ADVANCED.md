# PYTHON-DISCORD — Advanced ideas

Дополнительные механики из второго батча глубокого обхода `python-discord/bot`. Существующие общие системы не дублируются.

## PDIS-A001 — Учёт связанных аккаунтов с контекстом связи
- Модераторы могут связать двух пользователей как альтернативные аккаунты.
- Связь хранит автора действия, время создания/изменения и текстовый контекст/основание.
- Связь можно отдельно редактировать и удалять.
- Просмотр показывает количество связанных аккаунтов и причины связей.
- История допускает raw ID пользователей, которых уже нет на сервере.
- Команды одновременно ограничены ролью модератора и mod-channel.

## PDIS-A002 — Гибкое расписание роли с временным ручным override
- Роль moderator pings автоматически включается/выключается каждый день по расписанию.
- `off` временно отключает роль и имеет приоритет над ежедневным расписанием.
- `on` досрочно заканчивает override и возвращает пользователя к расписанию.
- `status` показывает текущее состояние и расписание, `sync` выполняет ручную ресинхронизацию.
- Состояние расписания восстанавливается после рестарта из Redis-backed cache.
- Поддерживается timezone offset и абсолютный ISO timestamp для разового отключения.
- Разовое отключение ограничено 30 днями, ежедневная смена — 1–23 часами.

## PDIS-A003 — Интерактивная help-навигация по parent/subcommand
- Кнопки в help для command group открывают help конкретной subcommand без нового сообщения.
- В help подкоманды есть кнопка возврата к родительской группе.
- Автор help имеет доступ к navigation buttons; модераторы получают дополнительный доступ.
- При вызове help из error-context навигация отключается.

## PDIS-A004 — Fuzzy command discovery с permission-aware suggestions
- При неизвестном имени help ищет похожие команды через fuzzy matching.
- В кандидаты входят команды, aliases, groups/subcommands, cogs и категории.
- Перед выдачей кандидатов учитывается доступность команды текущему пользователю.
- Слишком длинный поисковый запрос отдельно ограничивается в диагностическом сообщении.

## PDIS-A005 — Пользовательские категории help независимо от структуры extensions
- Несколько cogs могут объявить одну пользовательскую категорию и отображаться как единый раздел help.
- Категория может иметь отдельное описание.
- При отсутствии описания используется описание первого cog как fallback.

## PDIS-A006 — Массовое управление extensions с wildcard и rollback
- Load/unload/reload принимают wildcard для массовой операции.
- `*` и `**` различают только загруженные extensions и все extensions, включая выгруженные.
- Массовая операция показывает прогресс, итог `успешно / всего` и конкретные ошибки.
- Одновременная вторая операция блокируется до завершения первой.
- Неудачный reload возвращает extension к предыдущему рабочему состоянию.
- Список extensions группируется по категориям и показывает loaded/unloaded статус.

## PDIS-A007 — Multi-source latency healthcheck
- Одна ping-команда показывает время обработки команды, доступность внешнего healthcheck/API и Discord API latency.
- Ошибка внешнего HTTP-запроса отображается отдельно и не ломает остальные показатели.
- Числовые latency выводятся с единым округлением.

## PDIS-A008 — WebSocket event-rate диагностика
- Internal-инструмент считает общее число websocket events и отдельные счётчики по типам.
- Показывается среднее количество событий в секунду за время работы процесса.
- В embed выводятся наиболее частые типы событий с абсолютными значениями.

## PDIS-A009 — REPL eval с сохранением окружения и paste fallback
- Internal eval работает как REPL: нумерует выражения и сохраняет окружение между вызовами.
- Специальная команда сбрасывает историю/окружение.
- Результат форматируется отдельно как текст или Embed.
- При превышении лимитов Discord отправляется короткий preview, а полный вывод — во внешний paste-service.
- Ошибки paste-service диагностируются отдельно.

## PDIS-A010 — Source-команда с точной ссылкой на реализацию
- По имени команды, cog, tag или help можно получить ссылку непосредственно на соответствующий исходник GitHub.
- Для Python-объектов ссылка включает диапазон строк реализации.
- Для динамически созданных объектов вместо неправильной ссылки показывается понятная ошибка.

## PDIS-A011 — Нормализованные метрики Discord-событий
- Сообщения агрегируются по каналу с нормализацией имени в безопасный набор символов.
- Threads учитываются через родительский канал.
- Команды считаются отдельным counter.
- Число участников и server boosts хранятся как gauges.
- Шумные служебные/modmail-каналы могут исключаться из статистики.

## PDIS-A012 — Moderation-only echo/embed relay
- Модератор может отправить произвольный текст в текущий или указанный текстовый канал через bot-команду.
- Отдельный режим отправляет тот же текст как Embed.
- Перед отправкой в целевой канал проверяется наличие у автора права `send_messages`.
- Это полезный минимальный staff-инструмент для ручной публикации без полноценной announcement-системы.
