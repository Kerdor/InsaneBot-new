# Red-DiscordBot — уникальные находки

Этот файл содержит **только механики, которые при текущей сверке не были найдены в существующем банке идей InsaneBot-new**. Уже записанные системы намеренно не дублируются.

Правило: это не копия кода Red-DiscordBot. Фиксируются только идеи, поведение, UX и архитектурные паттерны для самостоятельной реализации.

## Команды и кастомизация

### RED-001 — Серверные и глобальные алиасы команд
- Можно создавать альтернативные имена существующих команд.
- Поддерживаются отдельные глобальные алиасы и алиасы конкретного сервера.
- Для управления есть add/edit/delete/remove/show/help/list-подобные операции.
- Имя алиаса проверяется на конфликт с существующей командой и зарезервированными именами.

### RED-002 — Алиас с заранее сохранёнными аргументами
- Алиас может хранить не только имя команды, но и аргументы.
- При вызове дополнительные аргументы пользователя дописываются к сохранённым.
- Поддерживается позиционное форматирование аргументов.

### RED-003 — Fuzzy search custom commands
- Поиск custom commands работает по приблизительному совпадению.
- Пользователь получает близкие варианты даже при неточном запросе.

### RED-004 — Randomized custom command
- Одна custom command может хранить несколько ответов.
- При вызове выбирается случайный ответ.
- Создание вариантов сделано интерактивным.
- Все варианты обязаны совместимо принимать одинаковые аргументы.

### RED-005 — Raw-просмотр custom command
- Отдельная команда показывает исходный markdown-ответ custom command для копирования.
- Для нескольких вариантов используется постраничный интерфейс.

### RED-006 — Метаданные custom command
- Для custom command сохраняются автор, список редакторов, дата создания и дата изменения.
- При редактировании новый редактор добавляется в список.

### RED-007 — Индивидуальный cooldown для custom command
- Cooldown хранится непосредственно у конкретной custom command.
- Значения можно менять при редактировании; неактивные значения удаляются.

## Warnings / модерация

### RED-008 — Warning points
- Каждое предупреждение может иметь числовой вес.
- У пользователя хранится суммарное количество warning points.
- Преднастроенные причины могут автоматически задавать своё количество points.

### RED-009 — Автодействия по warning points
- Администратор создаёт именованное правило с порогом points.
- При превышении порога выполняется заданная команда/действие.
- При последующем снижении points может выполняться отдельная команда.
- Правила сортируются по порогу.

### RED-010 — Именованные причины warn
- Причина имеет имя, описание и количество points.
- При выдаче warn можно выбрать зарегистрированную причину вместо ручного ввода всех данных.
- Есть отдельная настройка, разрешающая custom reasons.

### RED-011 — Независимая настройка DM для warn
- Сервер отдельно включает/выключает отправку предупреждения в DM нарушителю.

### RED-012 — Отдельный канал warn
- Предупреждения можно направлять в специально настроенный канал.
- Отдельно переключается использование этого канала; можно вернуть отправку в канал команды.

### RED-013 — Настройка показа модератора
- В DM предупреждения можно показывать или скрывать имя модератора.
- Та же настройка применяется при самостоятельном просмотре предупреждений пользователем.

### RED-014 — Self-view warnings в DM
- Результат просмотра собственных предупреждений можно отдельно направлять в DM или оставлять в текущем канале.

### RED-015 — История usernames/display names/nicknames
- Бот хранит предыдущие username, global display name и server nickname.
- История показывается отдельной командой и может включаться в userinfo.
- Хранятся последние 20 значений каждого типа.
- Вывод защищается от массовых упоминаний и вредных инвайтов.

### RED-016 — Rename с полноценной иерархической проверкой
- Отдельная команда изменения server nickname.
- Пустой аргумент снимает nickname.
- Проверяется диапазон длины 2–32 символа.
- Одновременно проверяются права бота, положение роли бота, положение роли вызывающего и владелец сервера.

## Reports / обращения

### RED-017 — Встроенная система пользовательских reports
- Пользователь может отправить жалобу/обращение персоналу.
- Report имеет собственный номер и хранится отдельно от обычного ticket channel.
- Можно отправить report сразу текстом или пройти интерактивный сценарий через DM.

### RED-018 — Выбор сервера для report через DM
- Если команда вызвана вне сервера, бот ищет общие серверы пользователя и бота.
- Если подходящих серверов несколько, пользователю показывается нумерованный список.
- Пользователь выбирает сервер ответом в DM.
- Отбор может учитывать наличие модератора или конкретных permissions.

### RED-019 — Антиспам для reports с несколькими временными окнами
- Для report используется отдельный антиспам.
- Одновременно учитываются короткое окно, несколько минут, час и сутки с разными лимитами.
- Нельзя начать новый интерактивный report, пока предыдущий ещё не завершён.

### RED-020 — Report с вложениями
- При отправке report бот переносит вложения пользователя вместе с текстом.

### RED-021 — DM-канал связи staff ↔ автор report
- Сотрудник может открыть communication tunnel к автору обращения.
- Сообщения из канала/треда пересылаются автору в DM.
- Tunnel может пересылать и файлы.
- В UI есть понятное состояние открытой переписки.

### RED-022 — Закрытие report communication реакцией
- Открытую переписку можно завершить реакцией ❎ на последнее сообщение.
- Закрытие доступно участникам tunnel.

### RED-023 — Номер report/ticket с постоянным счётчиком
- Для каждого сервера ведётся следующий номер обращения.
- Новый report получает последовательный номер, который можно использовать в сообщениях и аудите.

## Роли и администрирование

### RED-024 — Selfrole как toggle
- Пользователь одной командой добавляет себе разрешённую selfrole, а повторным вызовом снимает её.
- Отдельно доступны скрытые add/remove варианты.

### RED-025 — Selfrole list
- Пользователь может получить список всех ролей, которые администратор разрешил выдавать самостоятельно.

### RED-026 — Массовая настройка selfroles
- Администратор может добавить или удалить сразу несколько selfroles одной командой.
- Есть отдельная команда полного clear списка.
- Перед изменениями проверяется иерархия каждой роли.
- Перед очисткой списка используется подтверждение yes/no.

### RED-027 — Автоочистка невалидных selfroles
- При получении списка selfroles бот обнаруживает роли, которые больше не существуют.
- Невалидные ID автоматически удаляются из конфигурации.

### RED-028 — Редактирование цвета роли
- Отдельная команда меняет цвет роли через hex-значение.
- Выполняются проверки иерархии пользователя и бота.

### RED-029 — Редактирование имени роли
- Отдельная команда меняет имя существующей роли.
- Выполняются проверки иерархии пользователя и бота.

### RED-030 — Глобальное объявление по всем серверам
- Owner-команда запускает рассылку одного сообщения по всем серверам бота.
- Рассылка выполняется отдельным announcer-процессом.
- Пока объявление идёт, запуск второго блокируется.
- Есть отдельная команда cancel для остановки текущей рассылки.

### RED-031 — Канал для глобальных объявлений
- Каждый сервер может указать канал, куда направляются глобальные объявления.
- Настройку можно очистить и вернуть поведение по умолчанию.

### RED-032 — Serverlock
- Owner может включить режим, при котором бот остаётся только на уже известных серверах.
- При входе на новый сервер бот автоматически покидает его.

## Общие UX/технические находки

### RED-033 — Hidden-команды для технических/вспомогательных вариантов
- Некоторые команды существуют, но намеренно скрыты из обычной справки.
- Это позволяет оставить удобные alias/subcommand-пути, не перегружая help.

### RED-034 — Интерактивные подтверждения и меню как стандартный UX
- Для потенциально разрушительных действий используются yes/no подтверждения.
- Длинные списки и результаты выдаются через paginator/menu.

### RED-035 — Contextual locale для коммуникаций
- При пересылке сообщений между пользователем и staff бот устанавливает локаль конкретного сервера перед формированием текста.
- Это позволяет одной системе поддерживать разные языки на разных серверах.
