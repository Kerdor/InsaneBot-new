# PYTHON-DISCORD — Backend ideas

Механики backend-поверхности, найденные в `python-discord/bot` и не дублирующие общий банк.

## PDIS-B001 — Автопроверка конфигурации Discord-ресурсов при старте
- После загрузки guild bot сверяет настроенные channel IDs с реально существующими каналами.
- Отсутствующие/устаревшие записи собираются в список и выдаются как startup warning.
- Подход можно расширить на роли, категории и другие обязательные ресурсы.

## PDIS-B002 — Репозиторием управляемые event branding assets
- Event definitions и metadata автоматически обнаруживаются во внешнем GitHub repository.
- `meta.md` задаёт fallback либо year-agnostic start/end dates и Markdown description.
- Активное событие определяется по UTC-дате; интервалы, пересекающие Новый год, обрабатываются отдельно.
- При отсутствии активного события используется fallback event.
- Некорректные event directories диагностируются как misconfiguration.

## PDIS-B003 — Справедливое вращение повторяющихся assets
- Несколько icon/banner assets ротируются по итерациям использования, а не простым random.
- Выбор идёт среди assets с минимальным счётчиком; после успешного применения счётчик увеличивается.
- При изменении набора assets rotation cache переинициализируется.
- Compound SHA всех assets позволяет обнаруживать изменения удалённого набора.
- Единственный уже применённый asset повторно не используется без необходимости.
- Последнее время rotation хранится persistent, поэтому цикл переживает рестарт.

## PDIS-B004 — API sync через diff/reconciliation
- Сначала строится структурированный diff: `created`, `updated`, `deleted`, затем выполняются изменения.
- Discord objects нормализуются в hashable records для простого сравнения с внешней БД.
- User sync при подозрении на неполный Discord cache дополнительно делает `fetch_member`.
- Большие наборы синхронизируются пакетами фиксированного размера, а не тысячами параллельных запросов.
- API users читаются постранично до `next_page_no`.
- Администратор может вручную запускать отдельный sync roles/users.

## PDIS-B005 — Глобальные command guards
- Core-level check может запретить выполнение команд от bot users независимо от конкретной команды.
- Отдельный global check может запретить выполнение prefix-команд в DM.
- Это позволяет задавать базовую security policy до локальных command checks.

## PDIS-B006 — Ошибка команды с интерактивным Help
- Ошибка аргумента отправляется вместе с кнопкой, которая открывает подробный help именно вызванной команды.
- Кнопка может быть доступна автору ошибки и модераторам, а help открывается ephemeral.
- Разные типы input/API errors имеют отдельные понятные ответы и counters статистики.
- При неизвестной команде error handler может попытаться распознать специальные shorthand-команды или tags перед обычной ошибкой.

## PDIS-B007 — Контекстная диагностика неожиданных ошибок
- Unexpected error сохраняет structured context: user ID/username, command, message ID, channel ID и полный текст сообщения.
- Для guild-контекста дополнительно сохраняется jump link непосредственно на исходное сообщение.
- Ошибка одновременно получает пользовательское сообщение и структурированные данные для Sentry/logging.

## Дубликаты

Общие logging/error handling, state recovery, API layer и scheduling не размножаются без отличающего поведения; здесь сохранены только конкретные backend-паттерны.
