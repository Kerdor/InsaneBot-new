# TitanBot — Giveaways

Источник: `codebymitch/TitanBot`

- **TG-001 — Giveaway с произвольной длительностью** — длительность задаётся строкой с единицами `s/m/h/d`.
- **TG-002 — Минимальная и максимальная длительность** — ограничения вынесены в конфигурацию giveaway subsystem.
- **TG-003 — Ограничение количества победителей** — minimum/maximum winners конфигурируются отдельно.
- **TG-004 — Приз как пользовательское описание** — prize хранится текстом с лимитом длины 256 символов.
- **TG-005 — Канал публикации задаётся опционально** — giveaway можно создать в указанном text channel или текущем канале.
- **TG-006 — Только Manage Server для управления giveaway** — создание/завершение/удаление/reroll защищены ManageGuild.
- **TG-007 — Giveaway только внутри guild** — DM использование блокируется отдельной валидацией.
- **TG-008 — Дефер перед тяжёлыми операциями** — создание откладывает initial response перед отправкой сообщения и записью в БД.
- **TG-009 — Нормализованный parser длительности** — `durationString` trim-ится и разбирается regex-ом.
- **TG-010 — Защита от экстремального duration amount** — числовая часть длительности ограничена 1..999.
- **TG-011 — Валидация prize до публикации** — пустой/нестроковый/слишком длинный приз не создаёт giveaway.
- **TG-012 — Валидация winner count в двух слоях** — Discord option задаёт границы, service дополнительно проверяет значение.
- **TG-013 — Giveaway state содержит и endTime, и endsAt** — состояние допускает совместимость/переход между форматами времени.
- **TG-014 — Состояние giveaway хранит messageId** — Discord message является идентификатором конкретного giveaway.
- **TG-015 — Состояние giveaway хранит channelId и guildId** — запись самодостаточно указывает место проведения.
- **TG-016 — Хранение hostId** — автор giveaway сохраняется для последующей связи победителей с организатором.
- **TG-017 — Участники как массив ID** — entries сохраняются прямо в giveaway state.
- **TG-018 — Двойной флаг ended/isEnded** — state поддерживает два эквивалентных признака завершения.
- **TG-019 — Создание active embed** — активный giveaway показывает host, winners, entries и относительное время окончания.
- **TG-020 — Discord relative timestamp для окончания** — пользователь видит динамическое `Ends` вместо статической даты.
- **TG-021 — Интерактивная кнопка Join** — вход в giveaway выполняется через button interaction.
- **TG-022 — Кнопка End на активном giveaway** — организатор получает действие завершения прямо из сообщения.
- **TG-023 — Ended message получает другие кнопки** — после завершения Join/End заменяются на Reroll/View Winners.
- **TG-024 — Ended embed показывает победителей** — вместо времени окончания отображается список winner mentions.
- **TG-025 — Уникализация участников перед выбором** — duplicate user IDs удаляются перед random selection.
- **TG-026 — Random winner selection через shuffle** — используется перемешивание массива и выбор первых N.
- **TG-027 — Число победителей автоматически ограничивается числом участников** — service не пытается выбрать больше уникальных entries, чем существует.
- **TG-028 — Empty participant list не является исключением** — selectWinners возвращает пустой список.
- **TG-029 — Per-user/per-giveaway interaction rate limit** — ключ ограничения включает и user ID, и giveaway ID.
- **TG-030 — Очень короткий cooldown interaction** — повторные действия одного пользователя по одному giveaway ограничиваются отдельным cooldown.
- **TG-031 — Проверка rate-limit status без изменения состояния** — доступен отдельный read-only путь isUserRateLimited.
- **TG-032 — Создание сохраняется после отправки сообщения** — сначала Discord message, затем его реальный messageId записывается в state.
- **TG-033 — Ошибка сохранения giveaway не удаляет уже отправленное сообщение** — система логирует проблему и продолжает работу.
- **TG-034 — Автоматическая обработка истёкших giveaway** — фоновая проверка ищет завершившиеся записи и закрывает их без команды пользователя.
- **TG-035 — Фоновый обработчик переживает отсутствие DB** — при недоступной БД проверка просто прекращается с warning.
- **TG-036 — Фоновый обработчик обрабатывает giveaway по одному** — ошибка одного giveaway логируется отдельно и не ломает обработку остальных.
- **TG-037 — Восстановление Discord channel/message по сохранённым ID** — после restart система может найти старый giveaway и продолжить обработку.
- **TG-038 — Пропуск orphaned guild/channel/message** — отсутствующий guild/channel/message не приводит к падению всей фоновой проверки.
- **TG-039 — Автоматический выбор победителей по истечении времени** — expiration является полноценным способом завершения giveaway.
- **TG-040 — Отдельное winner announcement сообщение** — победители получают публичное поздравление и инструкцию связаться с host.
- **TG-041 — Giveaway без валидных участников явно объявляется** — вместо молчаливого завершения отправляется сообщение об отсутствии winners.
- **TG-042 — Сохранение ID сообщения с winner announcement** — `winnerPingMessageId` позволяет найти сообщение победителей позднее.
- **TG-043 — Manual end сохраняет endedBy** — система знает, кто принудительно завершил giveaway.
- **TG-044 — Manual end сохраняет participantCount** — число участников фиксируется отдельно в итоговом state.
- **TG-045 — Manual end запрещён для уже ended giveaway** — повторное завершение считается validation error.
- **TG-046 — End при недоступном channel сообщает, что state уже обновлён** — database state не теряется только из-за Discord fetch failure.
- **TG-047 — Удаление giveaway по message ID** — команда находит запись по идентификатору исходного Discord message.
- **TG-048 — Delete сначала пытается удалить Discord message** — database record не является единственным источником очистки.
- **TG-049 — Fallback поиск message по другим text channels** — если сохранённый channel недоступен, команда перебирает остальные text channels guild.
- **TG-050 — Удаление из БД проверяется повторным чтением** — после delete система убеждается, что запись действительно исчезла.
- **TG-051 — Удаление допускает уже исчезнувшее Discord message** — DB cleanup всё равно может завершиться успешно.
- **TG-052 — Delete сообщает, был ли message реально удалён** — пользователь получает различие между физическим удалением и недоступностью сообщения.
- **TG-053 — Reroll только для ended giveaway** — активный giveaway нельзя reroll-ить напрямую.
- **TG-054 — Reroll требует достаточного количества entries** — если участников меньше требуемого winner count, reroll блокируется.
- **TG-055 — Reroll заменяет winnerIds, но сохраняет participants** — повторный розыгрыш использует исходный пул участников.
- **TG-056 — Reroll сохраняет rerolledAt/rerolledBy** — аудит повторного выбора победителей.
- **TG-057 — Reroll редактирует исходный giveaway embed** — итоговое сообщение получает статус reroll.
- **TG-058 — Reroll переиспользует winner announcement message** — существующее announcement редактируется вместо обязательного создания нового.
- **TG-059 — Reroll имеет fallback при пропавшем исходном message** — winners всё равно сохраняются и announcement может быть создан/обновлён отдельно.
- **TG-060 — Reroll имеет fallback при недоступном channel** — новые winners могут быть сохранены в БД даже без публичного объявления.
- **TG-061 — Giveaway actions пишутся в audit logging** — create/delete/winner/reroll имеют отдельные event types.
- **TG-062 — Logging ошибки не ломает основную giveaway операцию** — проблемы аудита ловятся отдельно.
- **TG-063 — Giveaway embeds имеют разные состояния active/ended/reroll** — UI отражает жизненный цикл объекта.
- **TG-064 — Конфигурационные лимиты giveaway берутся из botConfig** — поведение можно менять без переписывания command logic.
- **TG-065 — Error objects несут context** — validation/permission/internal ошибки могут включать userId, guildId, messageId, channelId и другие диагностические данные.
