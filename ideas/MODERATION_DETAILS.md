# MODERATION DETAILS — Дополнительные механики

Небольшие самостоятельные механики модерации, которые важно не потерять при проектировании основной системы.

## Cog-Creators/Red-DiscordBot

### MODD-001 — Автоудаление повторов в реальном времени
- Источник: Cog-Creators/Red-DiscordBot
- После каждого сообщения бот проверяет короткую историю сообщений конкретного автора.
- Если один и тот же текст повторён подряд заданное число раз, новое сообщение удаляется автоматически.
- История хранится ограниченным deque; для каждого сервера используется собственный порог.
- Порог 2–20, значение -1 полностью отключает функцию.
- Наш вариант: ⬜
- Статус: ⬜ НЕ РЕШЕНО

### MODD-002 — Strict mention counting
- Источник: Cog-Creators/Red-DiscordBot
- В strict-режиме каждое raw-упоминание считается отдельно, включая несколько упоминаний одного пользователя или роли.
- В обычном режиме одинаковые упоминания схлопываются, и учитываются только уникальные пользователи/роли.
- Strict является отдельной настройкой mention-spam.
- Наш вариант: ⬜
- Статус: ⬜ НЕ РЕШЕНО

### MODD-003 — Проверка конфликтов порогов automod
- Источник: Cog-Creators/Red-DiscordBot
- При изменении порога autowarn/autokick/autoban бот проверяет, не получается ли новый порог выше/ниже следующего действия.
- Если уровни пересекаются или идут в нелогичном порядке, пользователь получает предупреждение о конфликте конфигурации.
- Настройка всё равно сохраняется, то есть проверка информирует, а не обязательно блокирует изменение.
- Наш вариант: ⬜
- Статус: ⬜ НЕ РЕШЕНО

### MODD-004 — DM при kick/ban с причиной
- Источник: Cog-Creators/Red-DiscordBot
- Перед kick/ban бот может попытаться отправить пользователю DM с названием сервера и причиной наказания.
- Ошибка/запрет DM не ломает саму модерацию.
- Для ban сообщение может содержать дополнительное настраиваемое поле.
- Наш вариант: ⬜
- Статус: ⬜ НЕ РЕШЕНО

### MODD-005 — Reinvite после unban с fallback-цепочкой
- Источник: Cog-Creators/Red-DiscordBot
- После unban можно автоматически пригласить пользователя обратно.
- Сначала используется vanity URL, затем подходящее постоянное приглашение, а при его отсутствии бот пытается создать временное.
- Если создать/получить приглашение нельзя, операция unban не должна ломаться из-за неудачного reinvite.
- Наш вариант: ⬜
- Статус: ⬜ НЕ РЕШЕНО

### MODD-006 — Обязательная причина moderation action
- Источник: Cog-Creators/Red-DiscordBot
- Сервер может централизованно требовать reason для moderation actions.
- При отсутствии причины действие не выполняется.
- Это отдельная серверная настройка, а не обязательный параметр каждой команды.
- Наш вариант: ⬜
- Статус: ⬜ НЕ РЕШЕНО
