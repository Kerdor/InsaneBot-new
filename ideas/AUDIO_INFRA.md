# AUDIO / MEDIA INFRASTRUCTURE — Банк идей

## AUDIO-001 — Встроенный managed media-node
Бот может самостоятельно запускать внешний media/audio node как дочерний процесс вместо обязательной ручной установки отдельного сервера.

## AUDIO-002 — Автоматическая загрузка node runtime
При необходимости backend runtime автоматически скачивается в data directory модуля.

## AUDIO-003 — Генерация конфигурации node из настроек бота
Конфигурационный файл внешнего node генерируется из текущих настроек модуля перед запуском.

## AUDIO-004 — Проверка окружения перед запуском
Перед стартом проверяются наличие Java/runtime, поддерживаемая версия и архитектура машины.

## AUDIO-005 — Кэширование результатов проверки runtime
Успешная/неуспешная проверка наличия runtime и его версии кэшируется, чтобы не запускать внешнюю проверку при каждом действии.

## AUDIO-006 — Контроль памяти дочернего процесса
Пользователь задаёт Xms/Xmx, а бот сравнивает максимальное значение с доступной памятью системы и не применяет опасную настройку.

## AUDIO-007 — Ожидание готовности по логам процесса
Готовность node определяется по специальному сообщению stdout; ранний выход и ошибка запуска превращаются в понятные состояния.

## AUDIO-008 — Мониторинг дочернего процесса
Управляющий объект отслеживает lifecycle внешнего процесса, умеет корректно завершать его и очищать связанные asyncio tasks/events.

## AUDIO-009 — Обнаружение плагинов внешнего node
Версия/название загруженных плагинов извлекаются из startup logs и доступны для диагностики.

## AUDIO-010 — Managed / unmanaged режим
Пользователь может отключить managed node и использовать внешний backend, сохраняя единый интерфейс настроек audio-модуля.

## AUDIO-011 — Полный reset настроек managed node
Отдельная операция возвращает все параметры managed backend к исходным значениям.

## AUDIO-012 — Защита от повторного запуска и повторного shutdown
Lifecycle API явно различает уже работающий node и объект, который уже был окончательно остановлен, вместо повторного запуска в некорректном состоянии.
