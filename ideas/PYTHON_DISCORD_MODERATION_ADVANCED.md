# PYTHON-DISCORD — Advanced moderation ideas

Уникальные механики из крупного обхода `python-discord/bot/exts/moderation/`. Общие предупреждения, timeout, slowmode, tickets, automod и базовый modlog не дублируются.

## PDIS-M2-001 — DEFCON: временный возрастной gate для новых аккаунтов
- Модератор задаёт минимальный возраст Discord-аккаунта, необходимый для входа.
- Порог принимает как число дней, так и duration-строку.
- Порог может автоматически отключиться в заданное время.
- При активном пороге новый участник автоматически получает DM с причиной отказа и затем kick.
- Отказ отдельно логируется, включая факт невозможности отправить DM.

## PDIS-M2-002 — DEFCON: аварийный server shutdown
- Одной административной командой сервер переводится в аварийный режим.
- Для `@everyone` одновременно отключаются отправка сообщений, реакции, сообщения в threads и подключение к voice.
- Отдельная команда восстанавливает эти permissions.

## PDIS-M2-003 — DEFCON status + живой статус канала
- Статус DEFCON показывает threshold, срок действия и текущий verification level.
- Topic специального канала автоматически отражает текущий threshold.
- Изменение DEFCON дублируется в командном канале, если команда была вызвана из другого места.

## PDIS-M2-004 — DEFCON hourly reminder без expiry
- Если опасный режим включён без срока окончания, бот автоматически напоминает модераторам о нём каждый час.
- При установке expiry или отключении threshold периодический notifier прекращается.

## PDIS-M2-005 — Persistent Voice Verify через Discord Button
- Постоянное сообщение с кнопкой `Voice Verify` переживает рестарт бота.
- Нажатие кнопки выполняет eligibility-проверки и отвечает ephemeral-сообщением.
- Уже проверенному пользователю вместо повторной операции показывается отдельная подсказка.

## PDIS-M2-006 — Многофакторный voice gate с объяснением каждой причины
- Доступ к voice зависит одновременно от давности вступления, отсутствия активного voice-infraction и минимальной активности.
- При отказе пользователю показывается список именно тех критериев, которые он не прошёл.
- Каждая причина отказа имеет собственную статистику.
- После прохождения выдаётся специальная voice-verified роль.

## PDIS-M2-007 — Одноразовый voice-gate reminder при первом входе
- Не прошедшему verification пользователю отправляется подсказка только при первом фактическом входе в обычный voice.
- Redis хранит факт уже отправленного уведомления, поэтому повторные подключения не спамят пользователя.
- Проверка и запись выполняются атомарно, защищая от гонок нескольких voice events.
- Stage channels можно исключить из этого поведения.

## PDIS-M2-008 — Полная временная тишина канала с сохранением исходных overwrites
- `silence` временно запрещает сообщения, реакции и создание/отправку в threads.
- Перед изменением сохраняются исходные permission overwrites.
- После expiry бот восстанавливает именно предыдущие значения, а не слепо выставляет permissions по умолчанию.
- Поддерживается постоянная тишина через специальный режим `forever`.

## PDIS-M2-009 — Silence для voice с принудительной синхронизацией
- Silence применяется не только к text, но и к voice channels.
- При блокировке можно либо переместить участников туда-обратно для применения новых permissions, либо окончательно выгнать их из voice.
- Если сервер не имеет AFK channel, бот способен создать временный изолированный mute-temp channel.
- Для voice silence можно отдельно блокировать `Speak` и `Connect`.

## PDIS-M2-010 — Notifier для постоянно silenced channels
- Каждый постоянно silenced channel регистрируется в notifier.
- Пока список не пуст, notifier работает; при пустом списке останавливается.
- Каждые 15 минут модераторам приходит сводка silenced channels с длительностью каждой блокировки.

## PDIS-M2-011 — Защита silence от ручного изменения permissions
- Для каждого channel сохраняется snapshot прежних overwrites.
- Если snapshot исчез, но признаки silence остались, бот не делает вид, что всё восстановил корректно.
- После аварийного восстановления выставляется предупреждение администраторам с просьбой проверить permissions вручную.
- Операции silence/unsilence защищены resource lock от одновременных конфликтующих изменений.

## PDIS-M2-012 — Просмотр и временный slowmode с возвратом к исходному значению
- Temporary slowmode хранит исходную задержку канала и автоматически возвращает её после expiry.
- Повторная установка временного slowmode не теряет первоначальное значение: используется уже сохранённый original delay.
- После рестарта expiry восстанавливается из Redis.
- `get` показывает текущую задержку и то, к какому значению/когда она вернётся.

## PDIS-M2-013 — Modlog с diff-сводкой изменений объектов
- Изменения каналов, ролей и guild settings логируются не как полные объекты, а как список `старое → новое` по изменившимся полям.
- Повторяющиеся/вложенные пути нормализуются до понятного имени свойства.
- Несколько изменений сортируются и объединяются в один компактный log entry.

## PDIS-M2-014 — Message audit trail с before/after diff
- При редактировании сообщения modlog показывает различия между старой и новой версиями, выделяя удалённые и добавленные слова.
- Длинные неизменившиеся участки сворачиваются, чтобы diff оставался компактным.
- Если обычный cached edit event недоступен, raw event используется как fallback.
- Для raw edit отдельно фиксируется, что старое содержимое недоступно из-за отсутствия кэша.

## PDIS-M2-015 — Удалённые сообщения: fallback для uncached событий
- Даже если сообщение не находилось в cache, raw delete event создаёт audit-запись с channel, message ID и временем из snowflake.
- Если сообщение было в cache, лог содержит автора, содержимое, attachments и reply-reference.
- Очень длинное содержимое не теряется: в log попадает сокращённый preview и ссылка на полный внешний архив.
- Для ответов отдельно отмечается resolved/deleted/unresolved referenced message.

## PDIS-M2-016 — Infraction safety confirmation для elevated пользователей
- Перед потенциально ошибочным наказанием участника с staff/community ролью показывается интерактивное подтверждение.
- Только вызвавший модератор и разрешённые роли могут нажать кнопку.
- Есть явные `Infract`/`Cancel` действия.
- При отсутствии ответа до timeout наказание автоматически считается отменённым.

## PDIS-M2-017 — Infraction: проверка существующего активного наказания
- Перед выдачей определённого типа наказания можно проверить активную запись этого типа для пользователя.
- При наличии существующего наказания модератор получает его ID вместо создания дубликата.

## PDIS-M2-018 — Infraction: удаление DB-записи при неудачном применении
- Сначала создаётся запись инфракции, затем выполняется Discord action.
- Если Discord action не удался, созданная DB-запись удаляется, чтобы не оставлять ложное активное наказание.
- Ошибка удаления самой записи отдельно отмечается в подтверждении и modlog.
- Перед ban/kick DM отправляется до применения наказания, чтобы не потерять возможность связаться с пользователем после удаления из guild.

## PDIS-M2-019 — Reapply infractions after restart/rejoin
- Активные infractions загружаются из API при старте и заново планируются по expiry.
- При возвращении пользователя активное наказание автоматически применяется повторно.
- Если до expiry осталось меньше минуты, вместо повторного применения наказание сразу деактивируется.
- Временные задачи удаления служебных сообщений также восстанавливаются после рестарта.

## PDIS-M2-020 — DM delivery status как часть infraction record
- Для каждой инфракции хранится, был ли пользователь успешно уведомлён в DM.
- Пользователю отправляется отдельный embed с типом, длительностью, expiry, reason и ссылкой на правила.
- Для ban используется отдельная инструкция по appeal, для warning — отдельная, для остальных infractions — общий ModMail appeal.
- Неудачный DM не считается успешной доставкой и отображается в modlog.

## PDIS-M2-021 — Безопасное управление 28-дневным timeout cap
- Timeout автоматически ограничивается Discord-лимитом.
- Ровно допустимое значение (`28d`) сохраняется как валидное, а значения на границе корректируются на минуту для обхода exclusive cap.
- Модератор получает отдельное предупреждение, если исходный срок пришлось урезать.

## PDIS-M2-022 — DM history inspector для модераторов
- Модератор может выгрузить историю DM между ботом и конкретным пользователем.
- В экспорт попадают автор, timestamp, message ID, текст, количество embeds и URLs attachments.
- История выгружается во внешний paste-service вместо попытки поместить весь архив в Discord.
- Команда ограничивает доступ одновременно ролью модератора и mod-channel.

## PDIS-M2-023 — Internal analytics query export
- Администратор может запросить сохранённый аналитический query по ID и экспортировать результат в CSV или JSON.
- CSV преобразуется в структурированные записи, JSON форматируется с отступами и сортировкой ключей.
- Результат сохраняется во внутреннем runtime-кеше и доступен для последующего internal eval.
- Отдельная команда может создать публичную share-ссылку на аналитический query.
