# TITAN SERVERSTATS — Банк идей

Находки `codebymitch/TitanBot` (main), сверенные по command/module/service/event paths.

## Команда и типы

- TSS-001 — Единая `/serverstats` команда объединяет создание, просмотр, изменение и удаление счётчиков.
- TSS-002 — ServerStats разбит на отдельные create/list/update/delete modules.
- TSS-003 — Команда требует `Manage Channels` на уровне Discord command permissions.
- TSS-004 — Каждый ServerStats handler дополнительно проверяет `Manage Channels` во время выполнения.
- TSS-005 — Счётчик может отображать общее число участников вместе с ботами.
- TSS-006 — Счётчик может отображать только людей без ботов.
- TSS-007 — Счётчик может отображать только ботов.
- TSS-008 — Тип счётчика выбирается через фиксированный список choices вместо произвольной строки.
- TSS-009 — Для разных типов используются отдельные человекочитаемые labels.
- TSS-010 — Для разных типов используются отдельные базовые имена каналов.
- TSS-011 — Для разных типов используются отдельные emoji.
- TSS-012 — Неизвестный тип имеет безопасный fallback label `Unknown`.
- TSS-013 — Неизвестный тип имеет безопасное fallback-имя `Counter`.
- TSS-014 — Неизвестный тип имеет fallback emoji `❓`.

## Создание каналов

- TSS-015 — При создании пользователь выбирает тип Discord-канала отдельно от типа статистики.
- TSS-016 — Поддерживается voice-канал как рекомендуемый вариант счётчика.
- TSS-017 — Поддерживается text-канал как альтернативный вариант счётчика.
- TSS-018 — Категория для нового счётчика обязательна.
- TSS-019 — В option категории разрешены только Discord Guild Categories.
- TSS-020 — Дополнительная runtime-проверка подтверждает, что выбранный объект действительно категория.
- TSS-021 — Новый канал создаётся непосредственно внутри выбранной категории.
- TSS-022 — Имя канала при создании начинается с базового имени типа счётчика.
- TSS-023 — Создание канала получает audit reason с тегом пользователя, создавшего счётчик.
- TSS-024 — До создания канала загружается текущий список серверных счётчиков.
- TSS-025 — Нельзя создать второй счётчик того же типа на одном сервере.
- TSS-026 — При конфликте типа пользователь получает ссылку на уже существующий канал, если он существует.
- TSS-027 — После создания канала выполняется дополнительная проверка отсутствия записи счётчика для этого channel ID.
- TSS-028 — Запись счётчика содержит уникальный ID, созданный timestamp-значением.
- TSS-029 — Запись хранит тип счётчика.
- TSS-030 — Запись хранит channel ID.
- TSS-031 — Запись хранит guild ID.
- TSS-032 — Запись хранит `createdAt` в ISO-формате.
- TSS-033 — Запись хранит флаг `enabled`.
- TSS-034 — Новый счётчик по умолчанию включён.
- TSS-035 — Сначала сохраняется запись счётчика, затем канал принудительно синхронизируется с текущим числом.
- TSS-036 — Если сохранение счётчика после создания канала не удалось, созданный канал удаляется как rollback.
- TSS-037 — Если первичное обновление имени не удалось, счётчик не откатывается, а пользователь получает предупреждение о следующем плановом обновлении.
- TSS-038 — После создания показывается Counter ID для последующего управления.
- TSS-039 — После создания показываются тип статистики, тип канала, категория и текущая ссылка на канал.
- TSS-040 — Пользователю явно сообщается период автоматического обновления — 15 минут.

## Хранение и нормализация

- TSS-041 — Список счётчиков хранится отдельно для каждого guild.
- TSS-042 — Сервис умеет читать данные из основной DB-обёртки с формой `{ ok, value }`.
- TSS-043 — Сервис поддерживает старый/прямой формат, когда DB сразу возвращает массив.
- TSS-044 — Сервис поддерживает JSON-строку как формат сохранённых счётчиков.
- TSS-045 — Сервис поддерживает legacy-объект одного счётчика вместо массива.
- TSS-046 — Невалидные DB-данные безопасно превращаются в пустой список.
- TSS-047 — Каждый счётчик проходит shape validation перед использованием.
- TSS-048 — Минимально обязательны string ID, type и channelId.
- TSS-049 — При чтении отсутствующий guildId восстанавливается из контекста guild.
- TSS-050 — При чтении отсутствующий `createdAt` восстанавливается текущим временем.
- TSS-051 — Отсутствующий boolean `enabled` нормализуется в `true`.
- TSS-052 — Необязательный `updatedAt` сохраняется при нормализации, если он есть.
- TSS-053 — Сохранение повторно sanitizes весь массив перед записью в DB.
- TSS-054 — Отсутствующая DB не приводит к исключению: чтение возвращает пустой список, сохранение — `false`.
- TSS-055 — Ошибки DB чтения логируются, а сервис возвращает безопасный пустой результат.
- TSS-056 — Ошибки DB записи логируются, а вызывающий код получает `false`.

## Подсчёт статистики

- TSS-057 — Для точного подсчёта сервис пытается получить всех участников guild через `guild.members.fetch()`.
- TSS-058 — При неудаче полного fetch используется текущий member cache как fallback.
- TSS-059 — Количество ботов считается фильтрацией member collection по `member.user.bot`.
- TSS-060 — Общее количество участников предпочитает официальный `guild.memberCount`.
- TSS-061 — Если `guild.memberCount` недоступен, total fallback-ится на размер member collection.
- TSS-062 — Количество людей вычисляется как total минус bot count.
- TSS-063 — Human count защищён от отрицательных значений через `Math.max(..., 0)`.
- TSS-064 — Сервис возвращает единый объект `totalCount`, `botCount`, `humanCount`.
- TSS-065 — Отдельная функция преобразует тип счётчика в соответствующее число.
- TSS-066 — Неизвестный тип счётчика возвращает `null`, а не ошибочное число.

## Форматирование имён

- TSS-067 — Имя канала строится по настраиваемому глобальному template.
- TSS-068 — Для имени канала предусмотрен fallback template `{name}-{count}`.
- TSS-069 — Template поддерживает placeholder `{name}`.
- TSS-070 — Template поддерживает placeholder `{count}`.
- TSS-071 — `{name}` заменяется базовым именем выбранного типа счётчика.
- TSS-072 — `{count}` заменяется строковым текущим количеством.
- TSS-073 — Оба placeholder заменяются через `replaceAll`, поэтому повторение placeholder в template поддерживается.
- TSS-074 — Конфигурация имени канала отделена от логики подсчёта.
- TSS-075 — Для сообщений ServerStats предусмотрен отдельный template resolver с произвольными replacement values.
- TSS-076 — Отсутствующий message template возвращает `null`, а не пустой текст.

## Плановое и событийное обновление

- TSS-077 — Все счётчики обновляются глобальным cron каждые 15 минут.
- TSS-078 — Планировщик использует cron expression `*/15 * * * *`.
- TSS-079 — Scheduled counter update запускается через общий safe-task wrapper.
- TSS-080 — Обновление обходит все guild из client cache.
- TSS-081 — Ошибка обработки одного guild не останавливает обновление остальных guild.
- TSS-082 — Перед плановым обновлением счётчики перечитываются из DB.
- TSS-083 — Отключённые (`enabled === false`) счётчики пропускаются плановым updater.
- TSS-084 — При удалённом channel запись счётчика считается orphaned.
- TSS-085 — Orphaned counters удаляются из сохранённого списка во время плановой очистки.
- TSS-086 — После очистки orphaned counters нормализованный список сохраняется обратно в DB.
- TSS-087 — Каждая реальная смена имени канала сопровождается logging event.
- TSS-088 — Если имя канала уже соответствует рассчитанному имени, Discord API не вызывается.
- TSS-089 — Неизменившийся счётчик не создаёт лишний audit/log event.
- TSS-090 — Если channel отсутствует в cache, updater пытается получить его через API по ID.
- TSS-091 — Если channel не удаётся получить и через fetch, update возвращает `false` без падения процесса.
- TSS-092 — Ошибка `setName` одного канала не ломает остальные операции планового цикла.

## Обновление по событиям участников

- TSS-093 — При входе участника счётчики обновляются сразу, не дожидаясь 15-минутного cron.
- TSS-094 — При выходе участника счётчики также обновляются сразу.
- TSS-095 — Join/leave counter update выполняется отдельно от welcome/goodbye pipeline.
- TSS-096 — Ошибка обновления счётчиков при join только логируется и не ломает обработку остальных join-действий.
- TSS-097 — Ошибка обновления счётчиков при leave только логируется и не ломает обработку остальных leave-действий.
- TSS-098 — Event updater также пропускает counters с `enabled === false`.
- TSS-099 — Event updater получает актуальный список counters из DB перед обработкой события.

## Просмотр списка

- TSS-100 — `/serverstats list` показывает все настроенные счётчики текущего сервера.
- TSS-101 — List command использует актуальную статистику guild при формировании результата.
- TSS-102 — List автоматически чистит записи с уже удалёнными каналами.
- TSS-103 — При наличии orphaned counters очистка выполняется до построения итогового списка.
- TSS-104 — Пустой список имеет отдельный onboarding embed вместо пустого результата.
- TSS-105 — Пустой экран объясняет доступные типы счётчиков.
- TSS-106 — Пустой экран содержит готовые usage examples команд.
- TSS-107 — List embed показывает общее количество валидных counters.
- TSS-108 — Каждый counter выводится отдельным embed field.
- TSS-109 — В поле счётчика показываются ID, type, channel, current count, status и created date.
- TSS-110 — Статус счётчика определяется по наличию `:` в имени канала как простой health heuristic.
- TSS-111 — List различает `Active` и `Not Updated` по фактическому имени канала.
- TSS-112 — В статистике списка отдельно считается число активных counters.
- TSS-113 — List показывает относительное время до следующего 15-минутного обновления через Discord timestamp.
- TSS-114 — List содержит management command hints для create/update/delete.
- TSS-115 — List embed получает timestamp создания ответа.
- TSS-116 — Для типов используется общий emoji + label display helper.
- TSS-117 — При неожиданном исчезновении channel во время построения list элемент пропускается с warning вместо падения команды.

## Обновление

- TSS-118 — Update принимает Counter ID вместо выбора channel напрямую.
- TSS-119 — Новый тип в update является optional на уровне Discord option, но runtime требует его фактического наличия.
- TSS-120 — Update сначала проверяет существование Counter ID.
- TSS-121 — Update отказывается работать с записью, чей channel уже удалён.
- TSS-122 — При смене типа проверяется отсутствие другого counter такого же нового типа.
- TSS-123 — Update сохраняет старый тип для отображения diff пользователю.
- TSS-124 — Update записывает `updatedAt` при изменении типа.
- TSS-125 — Изменение типа сохраняется в DB до обновления имени канала.
- TSS-126 — После DB update канал сразу синхронизируется с новым типом и текущим count.
- TSS-127 — Успешный update показывает old type → new type как визуальный diff.
- TSS-128 — Если rename не удался после сохранения, пользователю сообщается, что cron исправит имя позже.

## Удаление и подтверждение

- TSS-129 — Удаление счётчика требует отдельного confirmation UI.
- TSS-130 — Confirmation явно предупреждает, что Discord channel будет удалён навсегда.
- TSS-131 — Confirmation показывает Counter ID, тип и текущий channel.
- TSS-132 — Delete confirmation содержит отдельные Danger Confirm и Secondary Cancel buttons.
- TSS-133 — Custom ID delete button содержит action, counter ID и ID инициатора.
- TSS-134 — Cancel удаляет components после отмены, делая подтверждение одноразовым.
- TSS-135 — Confirm также удаляет components после завершения операции.
- TSS-136 — Delete button handler проверяет, что действие происходит внутри guild.
- TSS-137 — Delete button handler валидирует наличие action и counter ID.
- TSS-138 — Использовать confirmation buttons может только пользователь, который инициировал удаление.
- TSS-139 — Неизвестный delete action отклоняется централизованной validation error.
- TSS-140 — Реальная deletion logic вынесена в отдельную функцию `performDeletionByCounterId`.
- TSS-141 — Delete service сначала проверяет существование Counter ID.
- TSS-142 — DB-запись удаляется до попытки удаления Discord channel.
- TSS-143 — Если сохранение удалённого списка не удалось, физический channel не удаляется.
- TSS-144 — Удаление channel выполняется с audit reason, содержащим Counter ID.
- TSS-145 — Если channel уже удалён, DB cleanup всё равно считается успешным.
- TSS-146 — Ошибка удаления Discord channel логируется, но не возвращает всю DB-операцию назад.
- TSS-147 — Результат deletion различает channel deleted / failed to delete / already deleted.
- TSS-148 — Delete service обёрнут в централизованный service-boundary error wrapper.
- TSS-149 — Service error содержит guild ID, counter ID и operation context.
- TSS-150 — Ошибка DB удаления классифицируется отдельно как database error.
- TSS-151 — Button handler использует централизованный `handleInteractionError` для неожиданных ошибок.

## Interaction lifecycle и устойчивость

- TSS-152 — Create/list/update/delete используют единый safe defer lifecycle.
- TSS-153 — Ошибка defer логируется и останавливает дальнейшее выполнение конкретного handler.
- TSS-154 — Ответы редактируются через `InteractionHelper.safeEditReply`.
- TSS-155 — User-facing ошибки идут через централизованный `replyUserError`.
- TSS-156 — Permission errors отделены от user-input/database/unknown errors.
- TSS-157 — Ошибки отправки user-facing сообщения дополнительно `.catch(logger.error)`, чтобы ошибка ответа не маскировала основную проблему.
- TSS-158 — Низкоуровневые ServerStats service errors не должны приводить к падению процесса бота.
- TSS-159 — Scheduled обновление логирует guild-specific context при сбое.
- TSS-160 — Development mode содержит дополнительные debug logs для base name/current name/new name и DB операций.
- TSS-161 — Production mode не засоряется подробными debug-сообщениями.
- TSS-162 — Counter update logging ошибки не блокируют изменение имени канала.
- TSS-163 — ServerStats использует единый logging event type для изменения counter.
- TSS-164 — Лог изменения counter содержит type, count и channel.
- TSS-165 — ServerStats архитектурно отделяет Discord command UI от reusable service operations.
- TSS-166 — Delete action handler может быть зарегистрирован как отдельный reusable interaction handler.
- TSS-167 — Delete service возвращает готовое человекочитаемое сообщение вместо заставления button handler знать детали операции.
- TSS-168 — Функции получения label/base name/emoji централизованы в одном counter type config.
- TSS-169 — Добавление нового типа счётчика потенциально сводится к расширению `COUNTER_TYPE_CONFIG` + count switch + command choices.
- TSS-170 — ServerStats сочетает плановое обновление и event-driven обновление для баланса точности и нагрузки.
