# PYTHON-DISCORD MODERATION 4 — Infraction и специализированные moderation mechanics

Новые идеи из `infraction/infractions.py`, `infraction/management.py` и `infraction/superstarify.py`, сверенные с существующим moderation-банком.

## PDIS-M4-001 — Комбинированный Clean Ban
- Специализированная команда может сначала применить ban, а затем автоматически очистить сообщения нарушителя за заданное окно.
- Если отдельный cleanup-модуль недоступен, команда использует безопасный fallback через обычный ban с очисткой Discord.
- Лог очистки можно прикрепить обратно к уже созданной инфракции, не создавая вторую moderation-запись.

## PDIS-M4-002 — Compromise-response preset для скомпрометированного аккаунта
- Для типичного случая компрометации аккаунта можно иметь готовый moderation preset: фиксированный срок наказания + стандартизированное объяснение + инструкции по смене пароля/2FA + путь апелляции.
- Это превращает повторяющийся incident response в одну команду.

## PDIS-M4-003 — Shadow infractions без уведомления пользователя
- Отдельные скрытые варианты moderation action позволяют сохранить infraction в базе и применить действие, но не отправлять пользователю обычное DM-уведомление.
- Подходит для внутренних notes и специальных автоматических moderation workflows.

## PDIS-M4-004 — Контекстный выбор `last/recent` для редактирования инфракции
- Вместо обязательного ID можно использовать специальное значение `last`/`recent`, означающее последнюю инфракцию, созданную текущим модератором.
- Это ускоряет последовательные исправления только что выданного наказания и уменьшает копирование длинных ID.

## PDIS-M4-005 — Повторная отправка DM после изменения инфракции
- Для уже существующей инфракции есть отдельная команда resend.
- Повторное уведомление явно помечается как повторное и предупреждает, что исходная запись могла быть изменена.
- Скрытые infractions запрещены к повторной отправке, чтобы внутренние записи случайно не раскрывались.

## PDIS-M4-006 — Поиск infractions по regex-причине
- Историю наказаний можно искать не только по пользователю, но и по содержимому reason.
- Серверная сторона выполняет regex matching, а клиент заранее валидирует выражение и сообщает понятную ошибку при невалидном regex.

## PDIS-M4-007 — Поиск infractions по автору с управляемой сортировкой
- Можно получить все infractions, созданные конкретным moderator/actor.
- Дополнительный флаг меняет порядок выдачи с новых → старых на старые → новые.
- Это удобно для аудита действий отдельного модератора и разборов смен.

## PDIS-M4-008 — Семантические маркеры состояния в списке infractions
- Состояния, которые трудно заметить по обычному тексту, можно обозначать компактными символами прямо в списке: DM delivery failed, hidden infraction, edited duration и т.п.
- Отдельная легенда объясняет значения символов прямо в help соответствующих moderation-команд.

## PDIS-M4-009 — Автоматическое сохранение воспроизводимого forced nickname
- Для специального nickname-наказания имя выбирается детерминированно из общего списка на основе ID инфракции + ID пользователя.
- После рестарта/повторного входа можно вычислить то же имя без отдельного хранения nickname в состоянии.

## PDIS-M4-010 — Nickname enforcement как активная инфракция
- Специальное наказание может не просто один раз изменить nickname, а постоянно контролировать попытки пользователя выйти из наказания.
- `member_update` возвращает nickname к принудительному значению, если пользователь пытается изменить его вручную.
- При повторном входе активная инфракция применяется заново.

## PDIS-M4-011 — Раздельный DM и modlog для специальных наказаний
- При nickname-enforcement пользователь получает понятное объяснение старого/нового nickname, срока и ссылки на policy, а modlog получает технический infraction ID и причину изменения.
- Это разделяет user-facing сообщение и внутренний audit context.
