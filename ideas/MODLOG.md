# Modlog / Case Management

Механики управления историей модерационных кейсов, найденные в Red-DiscordBot. Отдельно от самих moderation actions.

## MODLOG-001 — Постоянная нумерация кейсов
Каждое модерационное событие получает последовательный номер внутри сервера; номер используется как стабильный идентификатор кейса.

## MODLOG-002 — Просмотр конкретного кейса по номеру
Отдельная команда показывает содержимое кейса по его номеру и сообщает понятную ошибку, если такого кейса нет на сервере.

## MODLOG-003 — Просмотр всех кейсов пользователя
Получать полную историю кейсов участника по Member либо по raw user ID.

## MODLOG-004 — Краткий список кейсов пользователя
Отдельный режим выводит кейсы компактным текстом вместо полного подробного представления.

## MODLOG-005 — Пагинация истории кейсов
Большая история автоматически разбивается на страницы; для embed-режима страницы формируются как отдельные case representations.

## MODLOG-006 — Редактирование причины кейса
Причину существующего кейса можно изменить отдельной командой. Если номер не указан, используется последний созданный кейс.

## MODLOG-007 — Иерархия прав на изменение кейса
Изменять причину может автор кейса, модератор или владелец сервера; при изменении чужого кейса сохраняется информация о том, кто внёс правку.

## MODLOG-008 — Метаданные изменения кейса
При редактировании сохраняются `amended_by` и timestamp изменения, чтобы история правок не терялась.

## MODLOG-009 — Timestamp в человекочитаемом виде
При текстовом отображении кейса рядом с содержимым показывается Discord timestamp, позволяющий клиенту автоматически отобразить локальное время.

## MODLOG-010 — Embed/non-embed представление
Case API должен уметь рендерить один и тот же кейс в embed или обычный текст в зависимости от настроек/возможностей контекста.

## MODLOG-011 — Отдельные case types для разных подсистем
Автоматические и пользовательские действия могут регистрироваться под разными именами case type с собственным названием, изображением и настройкой отображения.

## MODLOG-012 — История модерации доступна по ID без загрузки участника
Для старых/вышедших участников поиск кейсов может работать по raw user ID, даже когда полноценный Member объект недоступен.
