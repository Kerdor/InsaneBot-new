# INTEGRATIONS — Расширенные stream alerts

Специфические детали stream-monitoring из Cog-Creators/Red-DiscordBot.

## Cog-Creators/Red-DiscordBot

### STREAM-001 — Мультиплатформенный мониторинг
- Поддерживаются независимые stream providers с единым интерфейсом: Twitch, YouTube, Picarto и Kick.
- Проверка live-статуса и автоматические alerts используют общую модель Stream.
- Наш вариант: ⬜
- Статус: ⬜ НЕ РЕШЕНО

### STREAM-002 — Несколько независимых stream alerts
- Для сервера можно зарегистрировать несколько каналов/стримеров и разные Discord-каналы назначения.
- Настройки каждого monitored stream хранятся независимо.
- Наш вариант: ⬜
- Статус: ⬜ НЕ РЕШЕНО

### STREAM-003 — Периодический background polling
- Stream alerts работают через фоновую задачу с настраиваемым интервалом проверки.
- Состояние live/offline хранится между проверками, чтобы уведомлять именно о переходе в live, а не спамить при каждом poll.
- Наш вариант: ⬜
- Статус: ⬜ НЕ РЕШЕНО

### STREAM-004 — Автоматическое удаление alert после ухода стрима offline
- Для сервера можно включить autodelete.
- Когда monitored stream заканчивает трансляцию, ранее отправленное live-сообщение удаляется.
- Наш вариант: ⬜
- Статус: ⬜ НЕ РЕШЕНО

### STREAM-005 — Игнорирование YouTube rerun
- Rerun-трансляции можно исключить из автоматических уведомлений.
- Это отдельная настройка, не отключающая обычные live alerts.
- Наш вариант: ⬜
- Статус: ⬜ НЕ РЕШЕНО

### STREAM-006 — Игнорирование YouTube scheduled stream
- Запланированные будущие трансляции можно не считать live-событием для alert-системы.
- Наш вариант: ⬜
- Статус: ⬜ НЕ РЕШЕНО

### STREAM-007 — Настраиваемое упоминание при stream alert
- Можно отдельно разрешить `@everyone` и `@here`.
- Также можно настроить отдельное упоминание для конкретной роли.
- Состояние упоминаний хранится независимо для каждой роли.
- Наш вариант: ⬜
- Статус: ⬜ НЕ РЕШЕНО

### STREAM-008 — Раздельный режим mention/no-mention для live message
- Сервер может выбрать, должно ли live-сообщение содержать mention или отправляться без него.
- Переключение одного режима автоматически выключает противоположный.
- Наш вариант: ⬜
- Статус: ⬜ НЕ РЕШЕНО

### STREAM-009 — Кнопка «Watch the stream» в alert/check result
- Опционально к embed добавляется Discord link button, ведущая напрямую на stream URL.
- Кнопки можно включить отдельной серверной настройкой.
- Наш вариант: ⬜
- Статус: ⬜ НЕ РЕШЕНО

### STREAM-010 — Cooldown для дорогих stream API запросов
- Команды ручной проверки могут иметь отдельный cooldown на guild, чтобы не расходовать API quota.
- Особенно полезно для YouTube API с ограниченной квотой.
- Наш вариант: ⬜
- Статус: ⬜ НЕ РЕШЕНО

### STREAM-011 — Автоматическое обновление OAuth bearer token
- OAuth token кэшируется вместе с временем истечения.
- Перед API-запросом проверяется оставшееся время жизни; при сроке менее минуты токен обновляется.
- Наш вариант: ⬜
- Статус: ⬜ НЕ РЕШЕНО

### STREAM-012 — Миграция API credentials из cog storage в shared bot API storage
- При обновлении старые токены конкретного cog автоматически переносятся в общий storage бота.
- После успешной миграции старое локальное хранилище очищается.
- Наш вариант: ⬜
- Статус: ⬜ НЕ РЕШЕНО

### STREAM-013 — Автоматическое одноразовое предупреждение владельцу о missing secret
- Если для API есть client ID, но отсутствует secret, бот один раз уведомляет владельцев с инструкцией по исправлению.
- Повторные проверки не спамят владельцев; после исправления флаг уведомления сбрасывается.
- Наш вариант: ⬜
- Статус: ⬜ НЕ РЕШЕНО

### STREAM-014 — Уведомление владельцу при сбое API вместо падения background task
- Ошибки API классифицируются отдельно: offline, stream not found, invalid credentials, quota exceeded и generic API error.
- Ошибка одного monitored stream не должна завершать общий polling task.
- Наш вариант: ⬜
- Статус: ⬜ НЕ РЕШЕНО
