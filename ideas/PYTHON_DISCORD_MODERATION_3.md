# PYTHON-DISCORD MODERATION 3 — Дополнительные уникальные механики

Новые идеи из `modlog.py` и `infraction/_scheduler.py` / `_utils.py`, которые не вошли в предыдущий moderation-банк.

## PDIS-M3-001 — Modlog suppression tokens для служебных изменений
- Перед намеренным изменением, которое затем будет автоматически отражено Discord event listener'ом, код может зарегистрировать конкретный object/event ID как `ignored`.
- Следующий соответствующий event подавляется ровно один раз и удаляет token из списка.
- Это позволяет не дублировать ручное действие и его последующий gateway audit event.

## PDIS-M3-002 — Permission-aware modlog blacklist
- Modlog может автоматически игнорировать каналы, которые staff не имеет права видеть.
- Threads проверяются через parent channel.
- Дополнительно существует явный blacklist каналов.
- Таким образом audit-система не пытается логировать закрытые от модераторов области.

## PDIS-M3-003 — Role diff в member audit
- Изменение ролей пользователя логируется отдельными `Role added` / `Role removed` строками.
- Role changes объединяются с остальными изменениями профиля в один member-update entry.

## PDIS-M3-004 — Контекст reply в deleted-message audit
- При удалении cached message audit показывает, на какое сообщение был reply.
- Для доступного referenced message сохраняется author + jump URL.
- Для уже удалённого reference явно отображается его ID и статус Deleted Message.
- Если reference не удалось разрешить, audit фиксирует это отдельно.

## PDIS-M3-005 — Детализированный voice-state audit
- Voice changes логируются как diff отдельных свойств: channel, mute/deaf, streaming и camera/video state.
- Иконка и цвет log entry автоматически меняются в зависимости от направления изменения: вход/выход, mute/unmute и т.п.
- Шумные технические поля вроде session ID и AFK могут исключаться из diff.

## PDIS-M3-006 — Infraction lifecycle с отдельным `active` состоянием
- Инфракция не обязательно удаляется после применения/окончания: её запись остаётся в базе и получает состояние active/inactive.
- Pardon переводит active → inactive и отменяет scheduled expiry.
- У пользователя можно хранить полную историю infractions, даже если сейчас ни одна не действует.

## PDIS-M3-007 — Изменение infractions с сохранением истории
- При редактировании существующей временной инфракции можно хранить исходный `inserted_at` и отдельный `last_applied`.
- В пользовательском уведомлении изменение срока помечается как `Edited`.
- Это позволяет отличать первоначальную длительность от последующего изменения.

## PDIS-M3-008 — Pardon с отдельной причиной и отдельным уведомлением
- Pardon может принимать отдельный `pardon_reason`, не смешивая его с первоначальной причиной.
- Отправка DM о pardon может быть включена/отключена независимо от записи в modlog.
- Само подтверждение операции также может быть отключено для внутренних автоматических вызовов.

## PDIS-M3-009 — Tidy-up автоматических moderation сообщений
- Сообщения о наказаниях, созданные самим ботом вне mod-channel, автоматически планируются к удалению через заданный срок.
- Время удаления сохраняется в Redis, поэтому после рестарта задача не теряется.
- Ошибки удаления из-за archived thread, отсутствия сообщения или permissions обрабатываются отдельно.

## PDIS-M3-010 — Автоматический resync scheduler по последнему expiry
- Scheduler загружает все активные временные infractions из API.
- После планирования найденных записей он ставит дополнительную задачу на момент последнего из текущих expiry, чтобы повторно синхронизировать базу и обнаружить новые/пропущенные записи.
- Это позволяет не полагаться только на событие создания новой записи.

## PDIS-M3-011 — Infraction action как callable, а не заранее созданная coroutine
- Планировщик принимает функцию, которая создаст coroutine только если действие действительно потребуется.
- Это предотвращает `RuntimeWarning` для неиспользованной coroutine при ветвях, где инфракцию не нужно повторно применять.
- Паттерн полезен для любых отложенных условных Discord actions.

## PDIS-M3-012 — Разделение human reason и audit reason
- Инфракция может хранить официальную reason для modlog/database, но отправлять пользователю отдельный `user_reason`.
- Это позволяет адаптировать формулировку уведомления без изменения исторической записи наказания.

## PDIS-M3-013 — Различные каналы appeal в зависимости от типа наказания
- Для ban DM ведёт в отдельный appeals server.
- Для warning и других infractions используются разные инструкции ModMail.
- Ссылка на правила встраивается непосредственно в author/title embed пользователя.

## PDIS-M3-014 — Контекст автоматического наказания в обычном канале
- Если infraction выдана ботом вне mod-channel, подтверждение содержит reason и отдельно сообщает staff о необходимости review.
- Служебное сообщение затем автоматически удаляется через tidy-up scheduler.
- В mod-channel вместо этого показывается полноценная статистика total infractions пользователя.

## PDIS-M3-015 — Timeout cap с сохранением максимально близкого допустимого срока
- Для duration немного выше Discord limit срок автоматически уменьшается до безопасного значения, а не просто отклоняется.
- Ровно граничное пользовательское значение (`28d`) корректируется технически на минуту, чтобы пройти exclusive API boundary.
- Модератору явно сообщается, что исходный срок был сокращён.
