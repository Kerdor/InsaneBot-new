# PERMISSIONS — Банк идей

Отдельный слой тонкой настройки доступа к командам и модулям.

## Cog-Creators/Red-DiscordBot

### PERM-001 — Разрешение/запрет для конкретной команды или cog
- Источник: Cog-Creators/Red-DiscordBot
- Можно отдельно разрешать или запрещать использование конкретной команды либо целого cog.
- Правила задаются для пользователей, ролей, каналов и других Discord-объектов.
- Наш вариант: ⬜
- Статус: ⬜ НЕ РЕШЕНО

### PERM-002 — Иерархия применения permission rules
- Источник: Cog-Creators/Red-DiscordBot
- При конфликте правил используется предсказуемый порядок: пользователь → voice/stage-канал → текущий канал/родитель thread → роль с наивысшим подходящим приоритетом → серверный default.
- Глобальные правила проверяются раньше серверных.
- Наш вариант: ⬜
- Статус: ⬜ НЕ РЕШЕНО

### PERM-003 — Default allow/deny для команды или cog
- Источник: Cog-Creators/Red-DiscordBot
- Для команды или cog можно задать значение по умолчанию: разрешить, запретить или очистить override.
- Это позволяет строить deny-by-default/allow-by-default схемы без перечисления каждого пользователя.
- Наш вариант: ⬜
- Статус: ⬜ НЕ РЕШЕНО

### PERM-004 — Глобальные и серверные ACL независимо
- Источник: Cog-Creators/Red-DiscordBot
- Permission rules существуют отдельно на глобальном уровне и на уровне конкретного сервера.
- Сервер может уточнять глобальную политику, не изменяя её для остальных серверов.
- Наш вариант: ⬜
- Статус: ⬜ НЕ РЕШЕНО

### PERM-005 — Проверка «может ли этот пользователь выполнить команду»
- Источник: Cog-Creators/Red-DiscordBot
- Администратор может симулировать контекст другого пользователя и проверить, сможет ли он запустить конкретную команду.
- Проверка учитывает текущий сервер и канал.
- Наш вариант: ⬜
- Статус: ⬜ НЕ РЕШЕНО

### PERM-006 — Объяснение модели permissions прямо из бота
- Источник: Cog-Creators/Red-DiscordBot
- Отдельная команда объясняет порядок проверки permission rules и ограничения системы.
- Полезно для диагностики сложных ACL без чтения документации.
- Наш вариант: ⬜
- Статус: ⬜ НЕ РЕШЕНО

### PERM-007 — ACL через YAML
- Источник: Cog-Creators/Red-DiscordBot
- Permission rules можно экспортировать в YAML и импортировать обратно.
- Формат поддерживает правила для cog и команд, IDs Discord-объектов и `default`.
- Наш вариант: ⬜
- Статус: ⬜ НЕ РЕШЕНО

### PERM-008 — Полная замена ACL или частичное обновление
- Источник: Cog-Creators/Red-DiscordBot
- Импорт ACL имеет два режима: полностью заменить существующие правила или обновить только указанные в файле.
- Это позволяет использовать файл как полный профиль сервера или как частичный patch.
- Наш вариант: ⬜
- Статус: ⬜ НЕ РЕШЕНО

### PERM-009 — Защита владельца сервера от lockout
- Источник: Cog-Creators/Red-DiscordBot
- Владелец сервера не блокируется permission rules на самих командах управления permissions.
- Даже при ошибочной ACL-конфигурации остаётся путь для её исправления.
- Наш вариант: ⬜
- Статус: ⬜ НЕ РЕШЕНО

### PERM-010 — Поддержка правил для ещё не загруженных команд/cog
- Источник: Cog-Creators/Red-DiscordBot
- Permission rules сохраняются независимо от текущего состояния загрузки модуля.
- При добавлении cog или команды бот автоматически подхватывает ранее сохранённые правила.
- Наш вариант: ⬜
- Статус: ⬜ НЕ РЕШЕНО
