## `commands/🎶 Music` — новые механики / детали

### TOM-059 — Добавление предыдущего трека обратно в очередь
- `addprevious` повторно добавляет последний предыдущий трек.
- Сохраняет источник: YouTube или SoundCloud.

### TOM-060 — Добавление похожего трека по текущему
- `addsimilar` строит YouTube Radio URL от идентификатора текущего трека.
- Результат добавляется в очередь через отдельный режим `similar:add`.

### TOM-061 — Получить текущий трек в личные сообщения
- `grab` отправляет пользователю DM с карточкой текущего трека.
- Карточка содержит thumbnail, URL, длительность, автора, размер очереди, команду повторного запуска и исходный канал.
- Если DM закрыты, бот сообщает об этом в канале.

### TOM-062 — Принудительное добавление трека в начало очереди
- `playtop` принимает URL или поисковый запрос.
- Новый трек добавляется в начало очереди без ожидания конца текущего трека.
- Требует DJ-проверку.

### TOM-063 — Переместить пользователя в voice-канал бота
- `moveme` переносит пользователя в текущий voice-канал бота.
- Проверяет наличие bot voice channel, наличие пользователя в voice и свободное место.
- Не выполняет перенос, если пользователь уже находится там.

### TOM-064 — Выбор радиостанции из большого каталога
- `radio` работает с нумерованным каталогом радиостанций (в usage указан диапазон до 183).
- Станции сгруппированы по регионам/категориям.
- При отсутствии номера выводится список станций.
- Можно указать громкость; допустимый диапазон 1–150, значение по умолчанию 50.
- Радио запускается как отдельный `song:radio` источник.

### TOM-065 — Поиск радиостанций по нескольким критериям
- `searchradio` использует RadioBrowser.
- Поиск поддерживает `tag/genre`, `name`, `city`, `country`.
- До 60 результатов запрашиваются у сервиса и выводятся партиями.
- Пользователь выбирает номер станции обычным сообщением в течение 30 секунд либо вводит `end`.
- Выбранный URL запускается как radio stream.

### TOM-066 — Восстановление настроенного radio stream
- `reconnect` берёт заранее сохранённые канал и URL станции.
- При уже существующем подключённом player он уничтожается перед повторным запуском.
- Затем radio stream снова запускается в настроенном voice-канале.

### TOM-067 — Восстановление очереди после shuffle
- `shuffle` перед перемешиванием сохраняет исходный массив очереди в player state `beforeshuffle`.
- `unshuffle` восстанавливает именно сохранённый порядок.
- Если сохранённого состояния нет, команда отказывается от восстановления.

### TOM-068 — Удаление дубликатов из текущей очереди
- `removedupes` сравнивает треки по `uri`.
- Сохраняет первое вхождение каждого URL и пересобирает очередь.
- Имеет cooldown 10 секунд.

### TOM-069 — Подробный статус музыкального player
- `queuestatus` показывает единым embed состояние player.
- Включает volume, длину очереди, pruning/play-message, song loop, queue loop, autoplay, equalizer, filter, AFK mode и информацию о текущем треке.

### TOM-070 — Music Mix с преднастроенными плейлистами
- `playmusicmix` предлагает набор заранее заданных музыкальных миксов.
- Есть категории вроде NCS, Pop, Remixes, Rock, Old Gaming, Gaming, Charts, Chill, Jazz, Blues, Metal и др.
- Источники могут быть Spotify или YouTube.
- Микс запускается без активной очереди как специальный поток/плейлист.

### TOM-071 — Song of the Day
- `playsongoftheday` запускает заранее сохранённый трек из `songoftheday.json`.
- Команда не требует существующего player.

### TOM-072 — Поиск похожих треков отдельной командой
- `searchsimilar` строит YouTube Radio URL на основе identifier текущего трека.
- В отличие от `addsimilar`, команда использует режим `similar:search`, то есть предназначена для поиска/подбора похожего материала, а не просто добавления результата в очередь.

## Уже просмотрено, но без новой отдельной идеи
- `play.js` — обычное воспроизведение YouTube; базовая механика уже покрыта существующим банком.
- `playsc.js` / `searchsc.js` — SoundCloud-варианты play/search; проверены как отдельные source-варианты, но не размножены без новой отличительной механики.
- `playskip.js` — play + немедленный skip текущего трека; проверен как существующая композиция базовых play/skip.
- `pause.js`, `resume.js`, `restart.js`, `forward.js`, `rewind.js`, `seek.js`, `volume.js`, `clearqueue.js`, `removetrack.js`, `queue.js`, `stop.js` — базовые music controls; проверены, но отдельные дубли не создавались.
- `autoplay.js` — toggle autoplay; проверен и покрыт описанием TOM-069 как частью player status/существующей music-функциональности.
- `loop.js`, `loopqueue.js`, `loopsong.js`, `stoploop.js` — варианты track/queue repeat; сверены между собой и не размножены.
- `playlist.js`, `search.js` — базовые YouTube playlist/search.
- `lyrics.js` — в текущей ветке намеренно отключён из-за legal reasons.
- `searchplaylist.js` — текущая команда только сообщает о недоступности; рабочей механики поиска нет.
- `searchsc.js` — отдельный SoundCloud search source без новой логики сверх существующего поиска.
- `voteskip.js` и `removevoteskip.js` — код полностью закомментирован.

## Примечание по `move.js`
Команда заявлена как `move <from> <to>`, но фактическая реализация игнорирует переданные позиции и переносит последний элемент очереди в начало. Это отмечено как дефект реализации, а не как отдельная новая механика позиционного move.
