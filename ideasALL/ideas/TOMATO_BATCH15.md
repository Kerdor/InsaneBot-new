## TOM-228 — Планировщик периодических сообщений по дням и времени
- Сервер может хранить несколько независимых timed messages.
- Для каждого сообщения задаются канал, текст, режим Embed/обычного сообщения, часы и минуты, а также дни недели.
- Отправка выполняется общим cron-планировщиком примерно раз в минуту.
- Планировщик проверяет только серверы с настроенными timed messages и отправляет все совпавшие сообщения.
- Для Embed используется глобальная embed-конфигурация сервера.
- Планировщик работает в заданной timezone (`Europe/Berlin` в исходнике), а канал при необходимости дополнительно запрашивается из API.

## TOM-229 — Единая интерактивная Music Control Panel
- При старте трека бот может отправлять постоянное Now Playing-сообщение с двумя рядами интерактивных кнопок.
- В одной панели объединены skip, stop, pause/resume, autoplay, shuffle, song loop, queue loop, перемотка на `+10/-10 секунд` и заготовка Lyrics.
- Доступ к управляющим кнопкам проверяется: пользователь должен находиться в voice channel бота, а музыкальные действия доступны DJ или requester согласно общей DJ-проверке.
- Состояние панели динамически обновляется после pause/resume, autoplay, loop и других изменений; неактуальные кнопки могут быть disabled.
- При смене трека предыдущая панель завершается, а для нового трека создаётся новый component collector с временем жизни, привязанным к длительности трека.
- При завершении/уничтожении player панель очищается от компонентов и помечается как завершённая.
- Это именно единый UX-слой поверх уже известных отдельных музыкальных механик, поэтому skip/shuffle/loop/autoplay сами по себе повторно не выделяются.

## TOM-230 — Предварительная проверка Voice Channel перед музыкальной операцией
- Общий music player handler до запуска конкретного действия проверяет наличие voice channel у пользователя.
- Проверяется право бота `CONNECT`.
- Отдельно проверяется право `SPEAK`.
- Если пользовательский voice channel заполнен, операция блокируется, когда канал имеет ненулевой user limit и является full.
- После preflight одна точка маршрутизации передаёт управление конкретному player manager (`song`, `request`, `playlist`, `similar`, `search`, `skiptrack`, `playtop`).
- Таким образом ошибки подключения/говорения/переполнения канала обрабатываются единообразно до выполнения конкретной музыкальной команды.

### Проверенные дубли / не добавлены отдельно
- `playermanagers/playlist.js` — обычное добавление загруженного playlist в очередь и обновление Music Request/Queue Embed; новых самостоятельных механик сверх уже собранных не найдено.
- `playermanagers/search.js` — интерактивный выбор одного из первых результатов поиска через emoji и 30-секундный collector; базовая music search уже представлена в существующем банке, поэтому отдельно не размножено.
- `playermanagers/similar.js` — добавление/выбор похожих треков; соответствует уже собранным TOM-060/TOM-072.
- `playermanagers/skiptrack.js` — найденный трек ставится в начало очереди и текущий трек сразу пропускается; это вариант уже собранной механики TOM-062.
- `reactionrole.js`, ticket handlers, welcome/leave и прочие уже просмотренные functional handlers проверяются на новые варианты, но их базовые системы не дублируются.
- `erela_events` содержит большое количество уже известных playback lifecycle/update действий; отдельными ID выделены только новые UX/архитектурные варианты выше.
