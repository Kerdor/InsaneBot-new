# Tomato6966 — Batch 14

Источник: `Tomato6966/Multipurpose-discord-bot`
Ветка: `new_2025`
Область: `handlers/` — функциональные handlers, проверенные после `events/`

## TOM-217 — Voice Channel Role
- Для выбранного voice channel можно автоматически выдавать пользователю заданную роль при входе.
- При выходе из этого voice channel роль автоматически снимается.
- Конфигурация допускает несколько независимых пар `voice channel -> role`.
- Бот игнорирует собственные voice state updates и не выдаёт роль ботам.

## TOM-218 — Voice Join/Leave Message с обновлением исходного сообщения
- Для выбранного voice channel бот публикует сообщение в отдельном text channel при входе пользователя.
- ID сообщения сохраняется отдельно для пользователя.
- При выходе бот пытается изменить сохранённое сообщение на вариант `LEFT`, а если сообщение недоступно — отправляет новое.
- При этом исходная запись о сообщении удаляется из runtime-хранилища.
- Это позволяет использовать один постоянно обновляемый статус вместо отдельного сообщения на каждое событие выхода.

## TOM-219 — Anti-Self-Bot Detection с настраиваемым наказанием
- Handler проверяет `messageCreate` и `messageUpdate` на характерные rich embeds, используемые self-bot/Twitter-подобными клиентами.
- Система может выполнять `mute`, `kick` или `ban`.
- Для действия используется счётчик нарушений в коротком окне около `15 секунд`.
- В mute-варианте используется timeout на `10 минут`.
- Система может интегрироваться с общим Auto-Warn: нарушение записывается как обычный warning и затем участвует в существующих warn thresholds/roles.

## TOM-220 — Application Questionnaire через DM с защитой от параллельных заявок
- После нажатия `Apply` анкета проходит в Direct Messages пользователя.
- Вопросы задаются строго последовательно: следующий вопрос появляется только после ответа на текущий.
- На ответ каждого вопроса даётся до `5 минут`.
- На повторный запуск Application действует cooldown около `2 минут`.
- Одновременная вторая анкета одного пользователя блокируется отдельным runtime-lock.
- В ответах сохраняется текст и вложения; изображения можно включать в итог, а неподдерживаемые типы вложений помечаются как недоступные.

## TOM-221 — Epic Games Verification с DM-диалогом и проверкой аккаунта
- Верификация запускает пошаговый диалог в DM, а не собирает чувствительные данные непосредственно в публичном канале.
- Пользователь выбирает игровую платформу (`PC`, `Playstation`, `Xbox`, `Others`) и затем способ ввода (`Keyboard/Mouse`, `Controller`, `Touch`, `Others`).
- Каждое интерактивное ожидание имеет таймаут около `2 минут`.
- Epic Games username проверяется через внешний Fortnite/Epic API перед сохранением.
- Внутри одного сервера запрещается привязать один Epic username к нескольким пользователям.
- Повторное нажатие Verify обнаруживает существующую привязку и предлагает её изменить.
- При успешной привязке в отдельный log channel можно отправить username, платформу и input method.

## TOM-222 — Keyword/Custom Command Trigger без обязательного отдельного prefix-вызова
- Custom command может срабатывать по совпадению имени или alias среди токенов обычного сообщения.
- Для каждой команды можно ограничить список разрешённых каналов.
- Ответ может быть обычным сообщением или Embed.
- Поддерживается placeholder `{member}`.
- Для одной команды на один guild используется короткий runtime cooldown около `5 секунд`, предотвращающий повторную отправку на серии совпадений.

## TOM-223 — Snipe Cache последних удалённых сообщений
- При удалении сообщения handler сохраняет запись по `channel ID`.
- Для каждой записи хранятся автор/tag, user ID, avatar, текст, первая attachment и timestamp.
- На канал сохраняется ограниченный список последних удалений — до `15` сообщений.
- Отдельная `snipe`-команда может получать эти данные позже.

## TOM-224 — Автоматический Crosspost собственных Embed-сообщений в News Channel
- Если бот сам отправил Embed в Discord News Channel и сообщение допускает crosspost, handler автоматически вызывает `crosspost()`.
- Перед crosspost используется небольшая задержка, привязанная к текущему WebSocket ping.
- Таким образом объявления бота могут автоматически распространяться через публикационные каналы без отдельной команды.

## TOM-225 — Постоянный Server Deaf для самого бота
- Когда бот входит в voice channel, он автоматически включает server-deaf.
- Если кто-либо/что-либо снимает server-deaf с бота, отдельный handler повторно устанавливает deaf.
- Систему можно рассматривать как voice safety invariant для музыкального/voice-бота.

## TOM-226 — Owner DM о входе/выходе бота с сервера
- При `guildCreate` бот собирает имя/ID сервера, владельца, количество участников и текущее количество серверов бота.
- При `guildDelete` формируется аналогичный отчёт об уходе.
- Отчёт отправляется владельцам/операторам бота в DM.
- Это отдельный operational monitoring workflow, не пользовательский guild log.

## TOM-227 — Guild Chunk / Raid Diagnostic Log
- `guildMembersChunk` может логироваться как отдельное событие массовой выдачи участников.
- В лог попадает размер chunk и список участников, если их немного; при большом chunk показывается ограниченная выборка и количество остальных.
- Такой handler можно использовать как диагностический сигнал возможного raid/mass-member fetch.
