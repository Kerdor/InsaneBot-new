# Tomato6966 — Batch 9, Part 2

Источник: `Tomato6966/Multipurpose-discord-bot`
Ветка: `new_2025`

## `commands/💪 Setup`

### TOM-117 — Настраиваемый AI-Chat канал
- Администратор назначает конкретный канал, в котором бот отвечает через AI-chat.
- Систему можно отдельно включить и выключить.
- Есть отдельный просмотр текущего канала.
- Выбор канала поддерживает как mention, так и ввод ID.

### TOM-118 — Anti-Caps с процентным порогом и whitelist каналов
- Администратор задаёт максимально допустимый процент CAPS в сообщении (`0–100%`).
- При превышении сообщение не-администратора удаляется; повторные нарушения могут привести к mute.
- Можно добавлять и удалять каналы из whitelist.
- Есть отдельный лимит нарушений до mute.
- Система имеет собственный экран настроек и независимое включение/выключение.

### TOM-119 — Anti-Discord Links с whitelist каналов и серверов
- Отдельная защита от рекламных/пригласительных Discord-ссылок.
- Можно включать/выключать систему.
- Каналы можно исключать через whitelist.
- Можно whitelist-ить конкретные Discord-ссылки/серверы.
- Настраивается порог нарушений до mute.
- Есть экран текущих настроек.

### TOM-120 — Anti-Mention с лимитом упоминаний в сообщении
- Ограничивает количество member/role mentions в одном сообщении.
- Лимит задаётся администратором в диапазоне `1–100`.
- Сообщения нарушителей удаляются; повторные нарушения могут привести к mute.
- Есть whitelist каналов.
- Система отдельно включается/выключается и имеет экран настроек.

### TOM-121 — Автоматические резервные копии сервера по расписанию
- Владелец сервера может включить автоматический backup.
- Backup создаётся раз в `2 дня`.
- Старые автоматические backup'ы автоматически удаляются.
- Setup показывает команды просмотра и загрузки backup'ов.
- Для настройки требуется владелец сервера и `ADMINISTRATOR` у бота.

### TOM-122 — Auto-Delete с отдельной задержкой для каждого канала
- Можно добавить несколько каналов, в которых сообщения автоматически удаляются.
- Для каждого канала задаётся собственная задержка.
- Допустимая задержка: `3–3600 секунд`.
- Каналы можно удалять из настройки и просматривать списком.
- При просмотре показывается канал и фактическая задержка.
- Setup очищает из хранилища несуществующие каналы.

### TOM-123 — Auto-Embed для выбранных каналов
- Можно назначить несколько каналов, в которых сообщения обрабатываются системой автоматических Embed'ов.
- Каналы добавляются/удаляются независимо.
- Есть список всех настроенных каналов.
- При просмотре setup удаляет из конфигурации уже несуществующие каналы.

### TOM-124 — Автоматическая публикация мемов по минутному интервалу
- Администратор назначает канал для автоматических мемов.
- Публикация выполняется раз в `1 минуту`.
- Систему можно включить/выключить.
- Есть просмотр настроенного канала и cooldown.

### TOM-125 — Автоматическая публикация NSFW-контента в NSFW-канал
- Администратор назначает канал для автоматической публикации NSFW-изображений.
- При настройке канал проверяется на наличие NSFW-флага; обычный канал не принимается.
- Публикация выполняется раз в `1 минуту`.
- Систему можно включить/выключить и просматривать настройки.

### TOM-126 — Массовое переключение Auto-Warn правил
- Setup позволяет одним multi-select переключить сразу несколько правил Auto-Warn.
- Доступны Auto-Warn для Anti-Spam, Anti-Mention, Anti-Links, Anti-Discord, Anti-Caps, Blacklist, Ghost Ping Detector и Anti-Self-Bot.
- После операции показывается число включённых и выключенных правил.
- Auto-Warn применяется только если соответствующая защитная система сама включена.

### TOM-127 — Anti-Nuke с модульными защитами и отдельными whitelist
- Комплексная защита от разрушительных действий на сервере.
- Отдельные модули: добавление ботов, kick/ban, создание/удаление ролей, создание/удаление каналов.
- Для каждого модуля можно отдельно включать защиту и задавать whitelist пользователей/ролей.
- Для действий предусмотрены независимые пороги `за день / неделю / месяц / за всё время`.
- Для разных типов наказания можно отдельно включать `remove roles`, `kick` и `ban`.
- Некоторые модули умеют автоматически удалять созданный злоумышленником канал/роль или возвращать удалённую роль.
- Есть общий logger, отображение whitelist-изменений и режим quarantine.
- Настройка доступна только владельцу сервера (плюс специальный owner ID разработчика).
- Есть Suggested Settings и отдельная синхронизация прав quarantine-роли на каналы.

### TOM-128 — Несколько независимых Application Systems
- Один сервер может иметь до `100` отдельных Application System, выбираемых через отдельное меню setup.
- Каждый номер (`apply1`, `apply2`, …) хранится как самостоятельная конфигурация.
- Для каждого Application System можно отдельно настраивать каналы, вопросы, роли, сообщения и варианты результата.

### TOM-129 — Автоматическое создание полного Application-раздела
- Setup может сам создать категорию `Applications` и связанные текстовые каналы.
- Создаются отдельные каналы для старта заявки и завершённых заявок.
- Для каналов сразу задаются permission overwrites: обычные участники не могут писать в стартовый канал, а бот сохраняет необходимые права.
- В стартовый канал бот автоматически отправляет Embed с кнопкой запуска заявки.

### TOM-130 — Кастомный дизайн Application-панели
- При создании Application System администратор задаёт цвет Embed в формате `#RRGGBB`.
- Затем задаёт произвольное описание панели.
- Панель сохраняется как сообщение, к которому привязана кнопка `Apply`.

### TOM-131 — Настраиваемая Application-анкетa
- Для каждого Application System хранится список вопросов.
- Вопросы можно редактировать, добавлять и удалять отдельно.
- Начальная конфигурация содержит placeholder-вопрос, который затем можно заменить.

### TOM-132 — Раздельные сообщения результата Application
- Отдельно настраиваются сообщения для `accept`, `deny` и перенаправления пользователя в ticket.
- Сообщение ticket поддерживает обращение к пользователю через `{user}`.

### TOM-133 — Роли Application: временная и роль после принятия
- При начале заявки пользователю может выдаваться отдельная временная роль.
- При принятии заявки назначается отдельная accept-role.
- Роли задаются независимо для каждого Application System.

### TOM-134 — Пять настраиваемых вариантов результата Application
- Для одного Application System предусмотрены пять независимых вариантов результата (`one`–`five`).
- Каждый вариант имеет собственную роль и сообщение.
- Для каждого варианта можно отдельно включить изображение и задать его URL.

### TOM-135 — Last Verify для Application
- Для Application System можно включить/выключить повторное отображение последнего verification-сообщения пользователю.
- Состояние хранится отдельно для каждого Application System.

### TOM-136 — Auto-Support с несколькими независимыми конфигурациями
- На сервере можно создавать отдельные Auto-Support System (`autosupport1`, `autosupport2`, …), выбирая конфигурацию через setup.
- Каждая конфигурация хранит собственные channel/message IDs и набор опций.
- В интерфейсе setup предусмотрены отдельные операции отправки, добавления, редактирования и удаления опций.

### TOM-137 — Меню Auto-Support с до 25 вариантов
- В одной Auto-Support конфигурации можно хранить до `25` вариантов ответа.
- Для каждого варианта задаются `value`, `description`, emoji и ответное сообщение.
- При публикации бот автоматически строит select-menu из сохранённых вариантов.

### TOM-138 — Настраиваемый ответ Auto-Support с выбором Embed
- Для каждой Auto-Support опции отдельно выбирается, отправлять ли ответ внутри Embed или обычным сообщением.
- Ответ сохраняется как произвольный текст и может содержать `{user}`.

### TOM-139 — Переустановка Auto-Support панели в выбранный канал
- Setup позволяет повторно отправить конфигурационную панель, задав новый текст и канал.
- После отправки сохраняются IDs сообщения и канала, чтобы система могла управлять созданной панелью.

### TOM-140 — Пользовательские Custom Commands с лимитом
- Сервер может создавать собственные команды, которые возвращают заданный текст.
- В этой реализации установлен лимит `25` custom commands на сервер.
- Каждая команда хранит имя, output и настройку `embed`.
- Команды можно создавать, удалять и просматривать через отдельный setup-интерфейс.

### TOM-141 — Выбор формата ответа Custom Command
- При создании Custom Command администратор отдельно выбирает: ответ обычным сообщением или Embed.
- Выбранный формат сохраняется вместе с командой.

### TOM-142 — Настройка общего цвета Embed'ов сервера
- Администратор может менять глобальный цвет Embed'ов через интерактивный setup.
- Поддерживаются Discord color names, HTML/Hex (`#RRGGBB`), hex-нотация `0x...` и `RANDOM`.
- Валидация выполняется через Discord.js `resolveColor`.

### TOM-143 — Настраиваемая иконка футера Embed'ов
- Глобальная footer icon может задаваться URL-ом или изображением из вложения сообщения.
- Разрешаются PNG/JPG/JPEG; для URL дополнительно проверяется HTTP(S) и расширение изображения.
- После изменения setup показывает актуальный вид Embed.

### TOM-144 — Настраиваемый текст футера Embed'ов
- Администратор может задать произвольный глобальный текст footer для Embed'ов.
- Изменение сразу сохраняется в guild-настройках.

### TOM-145 — Глобальное включение/выключение thumbnail в Embed'ах
- Setup позволяет одним переключателем включить или отключить использование thumbnail.
- При включении thumbnail использует настроенную footer icon либо avatar бота как fallback.

## Примечания
- `setup-antimassmention.js`, `setup-antimasspings.js` и `setup-antipings.js` — redirect на `setup-antimention.js`, отдельно не считаются.
- `setup-auditlog.js` — redirect на `setup-logger.js`, отдельно не считается.
- `setup-blacklist.js` не добавлен повторно как отдельная система: базовая blacklist уже есть; batch-add через запятые и полный reset списка отмечены как проверенные детали без отдельного ID.
- `setup-antispam.js` сверён с уже добавленным `TOM-111`; новых самостоятельных механик не добавлено.
