# PYTHON-DISCORD CORE UTILS — shared infrastructure mechanics

Новые механики из `bot/utils/*`, `bot/pagination.py`, `bot/errors.py` и startup bootstrap `bot/__main__.py`. Дубликаты с уже существующим банком не повторяются; здесь оставлены именно дополнительные варианты поведения/архитектуры.

## PDIS-CU001 — Контекстная блокировка ресурса
- Любую команду/операцию можно сделать mutually exclusive для конкретного ресурса: пользователя, канала, тикета, сообщения, задачи и т. п.
- Один namespace изолирует одинаковые ID разных типов.

## PDIS-CU002 — Два режима блокировки: пропустить или ждать
- Операция может либо немедленно завершаться при занятом ресурсе, либо ждать освобождения.
- Это позволяет различать фоновые best-effort задачи и критические последовательные операции.

## PDIS-CU003 — Явная ошибка занятого ресурса
- Вместо тихого пропуска операция может вернуть структурированную ошибку с типом и ID заблокированного ресурса.
- Подходит для UX «эта сущность сейчас редактируется другим действием».

## PDIS-CU004 — Динамический ключ блокировки из аргументов команды
- ID ресурса вычисляется из именованного или позиционного аргумента команды.
- Функция вычисления ключа может быть асинхронной.

## PDIS-CU005 — Общий счётчик активных держателей + ожидание полного завершения
- Для группы операций можно отслеживать количество активных держателей и дать отдельным задачам `wait()` до момента, когда все завершатся.
- Это полезно для безопасного shutdown/reload и последовательных фаз обслуживания.

## PDIS-CU006 — Кольцевой bounded message cache
- Кэш сообщений работает как circular buffer с постоянными append/prepend/pop и фиксированным максимумом.
- При переполнении автоматически вытесняется старейшая запись.

## PDIS-CU007 — O(1) поиск сообщения по Discord ID
- Помимо последовательного кэша хранится mapping `message_id → index`, поэтому поиск конкретного сообщения не требует прохода по истории.

## PDIS-CU008 — Metadata рядом с cached message
- Для сообщения можно хранить отдельный metadata payload и получать его по ID.
- Metadata обновляется независимо от объекта сообщения.

## PDIS-CU009 — Slice/negative-index API поверх ring buffer
- Внутренняя кольцевая структура полностью скрывается: наружу отдаётся обычная индексация, отрицательные индексы и срезы.
- Это позволяет использовать bounded cache как обычную коллекцию.

## PDIS-CU010 — Update-if-cached
- Обновление сообщения возвращает boolean: запись найдена и обновлена или сообщения уже нет в кэше.
- Удобно для best-effort обработки edit events без исключений.

## PDIS-CU011 — Whitelist команд сразу по channel/category/role
- Доступ к конкретной команде можно разрешать по нескольким независимым измерениям контекста: канал, категория или роль.
- Любое совпадение даёт доступ.

## PDIS-CU012 — Автоматический redirect при неправильном контексте
- При попытке использовать команду вне whitelist бот сообщает правильный канал и ведёт пользователя туда.
- Redirect-канал автоматически добавляется в whitelist, чтобы настройка не противоречила сама себе.

## PDIS-CU013 — Тихие context checks для скрытых команд
- Для отдельных команд проверка контекста может не отправлять пользователю вообще никакой ошибки.
- Полезно для служебных/антиабузных команд, существование которых не нужно раскрывать.

## PDIS-CU014 — Role bypass поверх cooldown
- Обычный cooldown применяется ко всем пользователям, кроме заданного набора ролей.
- Проверка cooldown выполняется после успешного parsing аргументов, поэтому ошибочный ввод не расходует лимит.

## PDIS-CU015 — Реакционный access-control helper
- Реакция принимается только если совпали message ID, emoji и разрешённый пользователь; модераторы могут иметь bypass.
- Чужая подходящая реакция автоматически удаляется.

## PDIS-CU016 — Реакционный deletion workflow с expiry
- Сообщение получает trash reaction, доступную указанным пользователям/модераторам.
- После timeout реакции очищаются; при успешной реакции сообщение удаляется.
- Уже удалённое сообщение считается нормальным завершением, а не аварией.

## PDIS-CU017 — Attachment relay с автоматическим split
- Вложения при пересылке отправляются отдельными сообщениями, чтобы легче соблюдать Discord file-size limits.
- Слишком большие файлы можно вместо этого собрать в embed со ссылками.

## PDIS-CU018 — Fallback для частично неудачного attachment relay
- Ошибка одного вложения не ломает пересылку остальных.
- Большой файл может автоматически перейти из upload в link/embed fallback, а остальные продолжить отправляться.

## PDIS-CU019 — Уникальные reaction voters с фильтрами
- Можно посчитать не количество реакций, а число уникальных пользователей, причём отдельно фильтровать reaction и user.
- Поддерживается явный выбор, считать ли ботов.

## PDIS-CU020 — Безопасное webhook username sanitization
- Перед отправкой через webhook имя автора автоматически преобразуется так, чтобы обойти Discord-ограничение на зарезервированное имя `Clyde`.
- Это можно применять централизованно ко всем relay-интеграциям.

## PDIS-CU021 — Log API с несколькими каналами представления
- Один helper строит стандартизированный log embed: title/icon, colour, timestamp, footer, thumbnail, content, files и дополнительные embeds.
- Можно отдельно указать timestamp события вместо времени отправки.

## PDIS-CU022 — Автоматический mention только в логах определённого типа
- Для критических логов helper может сам добавить moderator-role mention, не меняя основной текст события.
- Длинный content автоматически обрезается до Discord limit.

## PDIS-CU023 — Централизованный архив удалённых сообщений
- История удалённых сообщений отправляется в API вместе с actor, временем создания записи, автором, каналом, embeds и attachments.
- Ответ API превращается в прямую ссылку на web-view архива.

## PDIS-CU024 — Reply-aware bot response
- Если пользователь вызвал команду в reply, бот может ответить именно на исходное сообщение.
- При недоступной/удалённой reference бот безопасно отправляет обычное сообщение без reply.

## PDIS-CU025 — Запрет reply на собственное сообщение автора
- Reference helper игнорирует reply на сообщение самого автора, чтобы не создавать бессмысленный self-context.

## PDIS-CU026 — Универсальные Discord timestamp formats
- Единый helper поддерживает date/time, short date, date, time, seconds и relative timestamp formats.
- Команды не должны вручную собирать Discord `<t:...>`.

## PDIS-CU027 — Humanized duration с ограничением точности и числа единиц
- Длительность можно показывать в человекочитаемом виде с заданной минимальной точностью (`minutes`, `seconds` и т. д.) и максимумом отображаемых единиц.
- Поддерживаются как абсолютные, так и направленные значения.

## PDIS-CU028 — Duration parser с несколькими единицами и строгим порядком
- Строка длительности принимает years/months/weeks/days/hours/minutes/seconds с короткими и длинными обозначениями.
- Неправильный порядок единиц отклоняется целиком вместо неоднозначного разбора.

## PDIS-CU029 — Унифицированное отображение expiration state
- Любой expiry автоматически представляется как `Permanent`, `Expired` либо Discord relative timestamp.
- Это даёт единый UX для timeout/infraction/temporary role/reminder и других временных сущностей.

## PDIS-CU030 — Формат «timestamp + remaining duration»
- Для временной сущности можно одновременно показать точный Discord timestamp и человекочитаемый оставшийся срок.
- Полезно для moderation, событий и scheduled tasks.

## PDIS-CU031 — Конвертация relative duration в абсолютный expiry
- Duration и готовый expiry могут иметь общий интерфейс: система возвращает пару `(origin, expiry)`.
- Origin можно явно передать для тестов/исторических операций вместо использования текущего времени.

## PDIS-CU032 — Пагинация с user restriction и role allowlist
- Пагинатор может ограничивать управление конкретным пользователем либо набором ролей.
- Это предотвращает вмешательство других пользователей в интерактивный интерфейс.

## PDIS-CU033 — Автоудаление интерактивной пагинации
- После timeout paginator прекращает принимать управление; отдельная delete reaction позволяет пользователю убрать интерфейс.

## PDIS-CU034 — Startup как набор обязательных внешних зависимостей
- Перед запуском бота централизованно создаются HTTP session, Redis session и API client, а зависимости передаются в Bot.
- Ошибка подключения Redis/API превращается в контролируемую startup failure вместо частично работающего бота.

## PDIS-CU035 — Разные startup error messages по классу причины
- Сетевая ошибка site API, ошибка Redis и неизвестная startup failure получают разные диагностические сообщения и общий fatal logging.

## PDIS-CU036 — Development mode с безопасным отключением StatsD
- В debug StatsD направляется на localhost: поскольку UDP не сообщает об ошибке недоступного порта, это фактически отключает статистику без отдельного feature flag.

## PDIS-CU037 — Минимизация Discord intents на production startup
- Необязательные intents отключаются централизованно (`presences`, DM typing/reactions, invites, webhooks, integrations), уменьшая лишний event traffic.

## PDIS-CU038 — Централизованный AllowedMentions с role allowlist
- Бот глобально запрещает everyone mentions, но разрешает контролируемый набор moderator roles.
- Это снижает риск случайных массовых упоминаний во всех модулях сразу.

## PDIS-CU039 — Explicit semantic exceptions для конфигурации
- Ошибки вроде invalid role, invalid infraction, branding misconfiguration и locked resource представлены отдельными типами, а не строками.
- Это позволяет error handler принимать разные решения по классу проблемы.

## PDIS-CU040 — Защита decorator globals для Discord annotation resolution
- При обёртывании command function можно переносить globals исходной функции, чтобы forward references в type annotations продолжали разрешаться корректно.
- При конфликте имён, используемых аннотациями, система явно выбрасывает специализированную ошибку вместо тихой подмены типа.
