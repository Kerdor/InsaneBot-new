# TitanBot Services — service-layer mechanics

Источник: `codebymitch/TitanBot`
Каталог: `src/services/`

## Service architecture

- **TSVC-001** — Вынос бизнес-логики из command/event слоя в отдельные сервисы.
- **TSVC-002** — Единый service boundary для преобразования неожиданных ошибок в типизированные сервисные ошибки.
- **TSVC-003** — Автоматическое оборачивание всех методов service-класса через `wrapServiceClassMethods`.
- **TSVC-004** — Настраиваемый service/operation/userMessage/context при оборачивании ошибок.
- **TSVC-005** — Разделение технического сообщения ошибки и пользовательского сообщения.
- **TSVC-006** — Контекст операции (`guildId`, `userId`, operation и т. п.) прикрепляется к сервисной ошибке.
- **TSVC-007** — Локальное подавление ожидаемых ошибок в фоновых сервисах вместо падения всего цикла.
- **TSVC-008** — Сервис может возвращать структурированный `status`/`reason`, а не бросать ошибку для штатных отрицательных результатов.
- **TSVC-009** — Фоновые reconciliation-сервисы возвращают сводный объект со счётчиками обработанных/исправленных/ошибочных элементов.
- **TSVC-010** — Каждый guild обрабатывается независимо внутри фоновой reconciliation-процедуры.

## Applications

- **TSVC-011** — Централизованная санитизация текста заявки с отдельными лимитами для вопроса и ответа.
- **TSVC-012** — Санитизация Markdown заявки перед сохранением в БД.
- **TSVC-013** — Обязательная проверка наличия guild/user/role перед созданием заявки.
- **TSVC-014** — Заявка должна содержать непустой массив ответов.
- **TSVC-015** — Ответ заявки имеет минимальную длину, чтобы отсеивать бессодержательные ответы.
- **TSVC-016** — Разные максимальные длины вопроса и ответа.
- **TSVC-017** — Пользователь не может иметь одновременно несколько pending-заявок.
- **TSVC-018** — После создания заявки сервис возвращает созданную сущность целиком.
- **TSVC-019** — Одна заявка не может быть обработана повторно после смены статуса.
- **TSVC-020** — Действия review ограничены фиксированным набором `approve`/`deny`.
- **TSVC-021** — Причина review обрезается до отдельного лимита и получает fallback при отсутствии причины.
- **TSVC-022** — Менеджер заявки определяется через `ManageGuild` или специальные manager roles.
- **TSVC-023** — Настройки заявок валидируются до сохранения: канал, роли, вопросы.
- **TSVC-024** — Настройки вопросов нормализуются и ограничиваются по длине на уровне сервиса.
- **TSVC-025** — Сервис заявок поддерживает отдельный список заявок пользователя и отдельное получение одной заявки.
- **TSVC-026** — Ошибка чтения списка заявок преобразуется в специализированную database-ошибку.

## Birthday service

- **TSVC-027** — Проверка даты использует реальный календарь текущего года, а не только диапазоны месяца/дня.
- **TSVC-028** — Некорректный 29 февраля автоматически отклоняется в невисокосном году.
- **TSVC-029** — Сервис возвращает одновременно числовой месяц и локализованное имя месяца.
- **TSVC-030** — Список дней рождения сортируется сначала по месяцу, затем по дню.
- **TSVC-031** — `getUpcomingBirthdays` переносит уже прошедший день рождения на следующий год.
- **TSVC-032** — Предстоящие дни рождения получают вычисленное количество дней до события.
- **TSVC-033** — Список предстоящих дней рождения ограничивается параметром `limit`.
- **TSVC-034** — Удаление отсутствующего дня рождения возвращает штатный `not_found`, а не исключение.
- **TSVC-035** — Ежедневный birthday job сначала снимает старые birthday-роли из tracking-state.
- **TSVC-036** — Tracking-state хранится отдельно от канонического хранилища дней рождения.
- **TSVC-037** — Birthday job работает только для серверов с настроенным каналом объявлений.
- **TSVC-038** — Birthday role является необязательной: объявление работает и без роли.
- **TSVC-039** — Отсутствующий участник пропускается без остановки обработки остальных дней рождения.
- **TSVC-040** — Ошибка добавления/снятия роли одного пользователя не ломает birthday-цикл сервера.
- **TSVC-041** — Ошибка обработки одного guild не останавливает ежедневную обработку остальных guild.

## Command access

- **TSVC-042** — Реестр доступных команд строится непосредственно из `client.commands`.
- **TSVC-043** — Реестр включает обычные команды, subcommands и вложенные subcommands.
- **TSVC-044** — Для каждой команды сохраняются категория, описание, protected-флаг и признак subcommand.
- **TSVC-045** — Protected-команды нельзя отключить даже если их имя присутствует в disabled-конфиге.
- **TSVC-046** — Отключение subcommand учитывает одновременно собственное имя и состояние parent command.
- **TSVC-047** — Отключение категории не требует перечисления всех команд вручную.
- **TSVC-048** — Reset категории удаляет только индивидуальные отключения её команд.
- **TSVC-049** — Registry snapshot показывает общее число команд и enabled/disabled totals.
- **TSVC-050** — Snapshot дополнительно содержит списки включённых и выключенных команд для каждой категории.
- **TSVC-051** — Категорию можно разрешить по key, folder name или display name.
- **TSVC-052** — Старый конфигурационный формат toggle-массивов нормализуется в объект boolean flags.
- **TSVC-053** — Управление доступом хранится отдельно для команд и категорий.

## Guild config service

- **TSVC-054** — Один сервис объявляется единственным местом чтения/записи guild configuration.
- **TSVC-055** — `getGuildConfig` нормализует сохранённую конфигурацию через единые defaults.
- **TSVC-056** — `updateGuildConfig` объединяет текущую конфигурацию с partial updates перед нормализацией.
- **TSVC-057** — `patchGuildConfig` поддерживает частичное обновление вложенных объектов.
- **TSVC-058** — Nested patch использует отдельный deep-merge для объектов, но не объединяет массивы.
- **TSVC-059** — Перед сохранением patch выполняется полная schema validation.
- **TSVC-060** — Можно читать/изменять отдельный config value без работы со всей конфигурацией вручную.
- **TSVC-061** — Сервис конфигурации защищает специальные ключи `__proto__`, `prototype`, `constructor`.
- **TSVC-062** — Защищённые служебные поля конфигурации нельзя изменять через generic setting API.
- **TSVC-063** — Значения channel-type валидируются не только по ID, но и по существованию канала.
- **TSVC-064** — Для channel setting дополнительно проверяется подходящий тип канала.
- **TSVC-065** — Значения role-type проверяют существование роли и её положение относительно высшей роли бота.
- **TSVC-066** — Для строковых настроек задаются независимые min/max length правила.
- **TSVC-067** — Числовые настройки имеют централизованные min/max ограничения.
- **TSVC-068** — Zod-схемы используются для точечной валидации значений конфигурации.
- **TSVC-069** — Legacy logging keys автоматически мигрируются в новую вложенную logging-конфигурацию при обновлении.
- **TSVC-070** — Legacy `logIgnore` переносится внутрь `logging.ignore`.
- **TSVC-071** — Legacy `logChannelId`/`reportChannelId` преобразуются в отдельные logging destinations.
- **TSVC-072** — Обновление настройки возвращает old value, new value и обнаруженные конфликты.
- **TSVC-073** — Сервис умеет обнаруживать логические конфликты между настройками и возвращать их вызывающему коду.
- **TSVC-074** — Bulk update валидирует все поля до сохранения итоговой конфигурации.
- **TSVC-075** — Bulk update возвращает applied/failed результаты и отдельные счётчики.
- **TSVC-076** — История изменений конфигурации хранится отдельно на guild в bounded in-memory buffer.
- **TSVC-077** — История конфигурации имеет максимальный размер 100 записей и удаляет самые старые.
- **TSVC-078** — Историю можно получить с ограничением количества и в обратном хронологическом порядке.
- **TSVC-079** — Reset настройки является отдельной операцией с отметкой `isReset` в истории.
- **TSVC-080** — Для bulk update каждая изменённая настройка получает отдельную запись истории.
- **TSVC-081** — Config summary преобразует channel/role IDs в человекочитаемые name + status.
- **TSVC-082** — Config summary явно отмечает удалённые/отсутствующие Discord-объекты как `Missing`.
- **TSVC-083** — Generic config API может требовать `Administrator` или `ManageGuild` через единый permission helper.

## Counting service

- **TSVC-084** — Counting state нормализуется через defaults при каждом чтении.
- **TSVC-085** — Некорректная counting system автоматически откатывается к decimal.
- **TSVC-086** — Некорректный leaderboard state нормализуется в пустой объект.
- **TSVC-087** — Counting state хранится по guild-specific storage key.
- **TSVC-088** — Reset counting сохраняет настройки системы, но сбрасывает next number, last user и current streak.
- **TSVC-089** — Best streak намеренно не сбрасывается при обычном reset.
- **TSVC-090** — Правильный count одновременно обновляет leaderboard, last user, current streak, best streak и next number.
- **TSVC-091** — Counting service предоставляет единый список доступных систем для UI.
- **TSVC-092** — Для Roman/Alphabet ввод сравнивается без учёта регистра.
- **TSVC-093** — Math counting допускает как выражение, так и равенство `left=right`, если результат совпадает с ожидаемым числом.
- **TSVC-094** — Leaderboard строится из storage state и ограничивается top 10.
- **TSVC-095** — Отсутствующий member заменяется прямым mention по user ID.
- **TSVC-096** — Ошибка чтения counting state не ломает вызывающую команду: сервис возвращает нормализованные defaults.

## Economy service

- **TSVC-097** — Экономические операции централизованы в сервисном классе с единым набором cooldown constants.
- **TSVC-098** — Перед арифметикой баланс проверяется на `Number.isSafeInteger` и неотрицательность.
- **TSVC-099** — Суммы операций принимаются только как целые положительные числа.
- **TSVC-100** — Ввод суммы ограничивается `Number.MAX_SAFE_INTEGER`.
- **TSVC-101** — Transfer загружает данные отправителя и получателя параллельно.
- **TSVC-102** — Самоперевод запрещён на уровне service, независимо от UI.
- **TSVC-103** — Transfer проверяет достаточность wallet до изменения обеих сторон.
- **TSVC-104** — При ошибке записи получателя сервис пытается откатить уже изменённый wallet отправителя.
- **TSVC-105** — Если rollback тоже не удался, сервис явно логирует состояние потенциальной несогласованности данных.
- **TSVC-106** — Экономические операции пишут transaction logs с типом операции, delta, before/after и timestamp.
- **TSVC-107** — Daily возвращает не только заработанную сумму, но и время следующего доступного claim.
- **TSVC-108** — Deposit учитывает отдельную bank capacity перед изменением wallet/bank.
- **TSVC-109** — Withdraw отдельно проверяет безопасный итоговый wallet после снятия денег из банка.
- **TSVC-110** — Универсальный cooldown checker вычисляет remaining, formatted и nextAvailable.
- **TSVC-111** — Форматирование cooldown автоматически выбирает часы/минуты/секунды.
- **TSVC-112** — Вспомогательные add/remove money позволяют другим системам проводить экономические изменения с указанием source/reason.

## Giveaway service

- **TSVC-113** — Duration parser поддерживает секунды, минуты, часы и дни с глобальными min/max ограничениями.
- **TSVC-114** — Duration amount ограничен отдельным числовым диапазоном до перевода в миллисекунды.
- **TSVC-115** — Prize имеет собственный лимит длины.
- **TSVC-116** — Winner count ограничивается конфигурационными minimum/maximum.
- **TSVC-117** — Winner selection сначала дедуплицирует участников.
- **TSVC-118** — Количество победителей автоматически уменьшается до числа уникальных участников.
- **TSVC-119** — Giveaway interaction rate limit ключуется одновременно user + giveaway.
- **TSVC-120** — Фоновый giveaway checker сначала проверяет наличие DB, guild, channel и message и пропускает недоступные сущности.
- **TSVC-121** — Один сломанный giveaway не останавливает обработку остальных завершившихся giveaway.
- **TSVC-122** — Результат выбора победителей сохраняется в giveaway state вместе с endedAt/endedBy/participantCount.
- **TSVC-123** — После окончания giveaway обновляется исходный embed и его интерактивные кнопки.
- **TSVC-124** — Победители получают отдельное публичное announcement-сообщение.
- **TSVC-125** — Ошибка audit logging не ломает завершение giveaway.

## JoinToCreate service

- **TSVC-126** — Template validator использует Unicode NFKC normalization.
- **TSVC-127** — Из шаблонов удаляются control/invisible characters.
- **TSVC-128** — Unknown placeholders отклоняются до создания канала.
- **TSVC-129** — Запрещённые `@`, `#`, `:`, backtick символы блокируются на уровне шаблона.
- **TSVC-130** — Значения placeholders очищаются отдельно перед подстановкой.
- **TSVC-131** — Значение каждого placeholder ограничивается отдельным лимитом длины.
- **TSVC-132** — После подстановки выполняется второй раунд sanitization и нормализации пробелов.
- **TSVC-133** — Пустое итоговое имя заменяется на безопасный fallback.
- **TSVC-134** — На уровне сервиса существует отдельная проверка bitrate range.
- **TSVC-135** — User limit `0` имеет специальную семантику unlimited.
- **TSVC-136** — Guild не может иметь второй trigger channel, пока первый не удалён/изменён.
- **TSVC-137** — Настройки конкретного trigger channel могут переопределять глобальные defaults.
- **TSVC-138** — У channel-specific config сохраняются `createdAt`/`updatedAt` timestamps.
- **TSVC-139** — Удаление trigger чистит не только trigger list, но и channelOptions/temporaryChannels, связанные с ним.
- **TSVC-140** — `isTriggerChannel` при ошибке чтения безопасно возвращает false.
- **TSVC-141** — Конфигурационные изменения JoinToCreate логируются через общий logging service.
- **TSVC-142** — Ошибка logging JoinToCreate не ломает основную конфигурационную операцию.

## Verification service

- **TSVC-143** — Verification имеет отдельный cooldown tracker по паре guild:user.
- **TSVC-144** — Помимо cooldown существует отдельный sliding-window tracker количества попыток.
- **TSVC-145** — Лимит попыток и окно попыток настраиваются независимо.
- **TSVC-146** — Verification trackers периодически очищаются по таймеру, а не только при каждом запросе.
- **TSVC-147** — Для in-memory trackers задан максимальный размер записей.
- **TSVC-148** — При переполнении tracker удаляются самые старые ключи.
- **TSVC-149** — Auto-verify может использовать отдельную роль, отличную от основной verification role.
- **TSVC-150** — Auto-verify поддерживает критерий возраста аккаунта.
- **TSVC-151** — Auto-verify поддерживает критерий размера сервера.
- **TSVC-152** — Auto-verify поддерживает режим без дополнительных критериев.
- **TSVC-153** — Auto-verify возвращает machine-readable reason при отказе, а не только boolean.
- **TSVC-154** — Ошибка auto-verify преобразуется в typed error, но наружу возвращается безопасный `auto_verify_error` result.
- **TSVC-155** — Auto-verify может отправлять пользователю DM после успешной проверки.
- **TSVC-156** — Перед verification проверяется существование role/channel и необходимые channel permissions.
- **TSVC-157** — Перед выдачей роли отдельно проверяются ManageRoles и hierarchy.
- **TSVC-158** — Уже верифицированный пользователь возвращает `already_verified` без повторной выдачи роли.
- **TSVC-159** — Снятие verification принимает moderatorId и reason и записывает их в audit context.
- **TSVC-160** — Verification может вести отдельный audit trail всех операций.

## Panel health / reconciliation

- **TSVC-161** — Один panel-health сервис проверяет сразу ticket, verification и reaction-role panels.
- **TSVC-162** — Health check отличает healthy, deleted panel, missing channel и recovered message ID.
- **TSVC-163** — При обнаружении нового message ID сервис может восстановить ID в конфигурации без пересоздания панели.
- **TSVC-164** — Для reaction-role panel при восстановлении ID переносится DB record со старого key на новый.
- **TSVC-165** — Старый reaction-role storage key удаляется после успешного восстановления.
- **TSVC-166** — Reconciliation возвращает отдельные counters по guilds/panels/healthy/deleted/missing/recovered/errors.
- **TSVC-167** — Удалённая панель не восстанавливается автоматически: состояние помечается для ручного repost.
- **TSVC-168** — Ошибка проверки одной панели не останавливает остальные панели того же guild.
- **TSVC-169** — Ошибка проверки одного guild не останавливает health scan остальных guild.

## Level role sync

- **TSVC-170** — Startup reconciliation может заново выдать level reward роли пользователям на основе сохранённого level state.
- **TSVC-171** — Service умеет перечислять user IDs через DB prefixes вместо заранее сохранённого списка пользователей.
- **TSVC-172** — Поддерживаются одновременно canonical и legacy DB prefixes для миграционной совместимости.
- **TSVC-173** — User IDs из DB keys дополнительно проверяются regex на Discord snowflake-подобный формат.
- **TSVC-174** — Отсутствующие reward roles автоматически удаляются из leveling config во время reconciliation.
- **TSVC-175** — После очистки отсутствующих ролей обновлённая leveling config сохраняется обратно.
- **TSVC-176** — Re-award проверяет, что пользователь ещё не имеет роль, прежде чем выдавать её.
- **TSVC-177** — Ошибка выдачи reward одному пользователю увеличивает error counter, но не прерывает остальные выдачи.
- **TSVC-178** — Role sync можно запускать как для одного guild, так и для всех guild.

## Cross-service resilience

- **TSVC-179** — Фоновые сервисы предпочитают `continue`/summary вместо падения всего batch при единичной ошибке.
- **TSVC-180** — Сервисы возвращают причины штатного отказа (`not_found`, `criteria_not_met`, `already_verified`, etc.) для удобного UI.
- **TSVC-181** — Сервисный код проверяет Discord entity existence непосредственно перед критической операцией, даже если ID есть в config.
- **TSVC-182** — Cache-first + API-fetch fallback используется для guild/member/channel/role объектов.
- **TSVC-183** — DB readers терпимо относятся к нескольким историческим форматам данных и нормализуют их в единый runtime shape.
- **TSVC-184** — Сервисы допускают миграционные legacy keys/prefixes без немедленного разрушения старых данных.
- **TSVC-185** — Audit/logging операции вызываются после основной операции и изолируются от её успеха.
- **TSVC-186** — Service methods сохраняют machine-readable result fields, пригодные для UI без повторного анализа текста ошибки.
- **TSVC-187** — Конфигурационные сервисы отделяют normalization, validation, persistence и audit trail.
- **TSVC-188** — In-memory state для rate limits/history имеет явные bounds и cleanup-политику.
- **TSVC-189** — Service-level validation не полагается только на Discord command option validation.
- **TSVC-190** — Service API можно переиспользовать несколькими UI: slash commands, buttons, events и background jobs.
