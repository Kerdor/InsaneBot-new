# Tomato6966 — Batch 8

Источник: `Tomato6966/Multipurpose-discord-bot`
Ветка: `new_2025`

## `commands/👑 Owner`

### TOM-093 — Смена аватара бота
- Owner может изменить аватар бота по URL изображения или прикреплённому изображению.
- Перед применением проверяется формат изображения.
- Изображение скачивается локально и передаётся в Discord API.

### TOM-094 — Смена имени бота
- Owner может изменить username бота.
- Есть проверка наличия нового имени и ограничение длины до 32 символов.

### TOM-095 — Глобальная смена префикса
- Owner может изменить глобальный prefix бота.
- Новый prefix сохраняется в конфигурационном файле.
- Проверяется единственный аргумент и максимальная длина prefix в 5 символов.
- Guild-level prefix может иметь собственную настройку и не обязан совпадать с глобальной.

### TOM-096 — Интерактивная настройка статуса бота
- Owner получает select-menu для выбора части статуса без передачи большого набора аргументов одной командой.
- Можно отдельно менять два текста статуса, тип активности, Twitch URL и online/idle/dnd state.
- Поддерживаются типы `PLAYING`, `WATCHING`, `STREAMING`, `LISTENING`, `COMPETING`.
- Для текстов поддерживаются placeholders: prefix, количество guilds/members, дата/время создания, имя/tag бота, количество команд, использованных команд и проигранных песен.
- Тексты ограничиваются 128 символами и сохраняются в конфигурации.
- Для Twitch URL проверяется URL и наличие Twitch-ссылки.
- Компонентный UI разрешает взаимодействие только пользователю, запустившему команду; остальные получают отказ.

### TOM-097 — Управление списком владельцев бота
- Owner может интерактивно добавлять и удалять других owners.
- Новый owner выбирается через упоминание пользователя и сохраняется в `ownerIDS`.
- При удалении нельзя удалить самого себя.
- Нельзя удалить исходного/защищённого владельца.
- Отдельный пункт показывает текущего original owner и остальных owners.

### TOM-098 — Выход бота с указанного сервера
- Owner указывает Guild ID, после чего бот покидает выбранный сервер.
- Перед выходом проверяется наличие guild в кэше.

### TOM-099 — Перезагрузка одной команды без перезапуска бота
- Owner указывает имя команды или её alias.
- Команда удаляется из require cache, перечитывается с диска и заново помещается в коллекцию команд.
- Позволяет обновить конкретную команду без полного рестарта процесса.

### TOM-100 — Полная перезагрузка всех команд
- Очищаются коллекции commands и aliases.
- Все `.js` команды перечитываются с диска с предварительным удалением из require cache.
- Aliases каждой команды заново регистрируются.
- После завершения бот сообщает количество загруженных команд.

### TOM-101 — Полная горячая перезагрузка runtime бота
- Предусмотрена перезагрузка не только команд, но и handlers/events/social handlers.
- Перед повторной загрузкой очищаются require cache, listeners и периодические jobs.
- Затем заново запускаются базовые handlers, social logs и остальные handlers.
- В текущей ветке команда фактически отключена ранним `return`; идея зафиксирована как архитектурный вариант, а не как рабочая команда.

### TOM-102 — Перезапуск процесса бота через process manager
- Отдельная команда использует PM2 для перезапуска процесса бота.
- Это отличается от внутреннего hot-reload: перезапускается сам процесс.
- В текущем файле идентификатор PM2-процесса указан как placeholder.
- В коде отсутствует owner-check, что является проблемой безопасности и не считается корректной моделью доступа.

### TOM-103 — Глобальная/серверная публикация Slash Commands
- Owner может развернуть slash commands глобально или только в конкретной guild по Guild ID.
- Используется единый набор `client.allCommands`.
- Для global deploy показывается количество команд и subcommands; для guild deploy результат привязан к конкретному серверу.
- Глобальное обновление отдельно предупреждает о задержке распространения Discord.

### TOM-104 — Полный сброс данных сервера с подтверждением
- Owner может удалить практически все сохранённые данные guild сразу.
- Сбрасываются настройки, premium/stats, JTC, setups, saved queues, moderation actions, profiles, applications, points, reaction roles, rosters, social logs, blacklist, custom commands, keywords и другие связанные хранилища.
- Перед удалением требуется явное подтверждение `yes`.
- Операция ограничена owner-доступом.

### TOM-105 — Интерактивное управление рекламной системой бота
- Owner через select-menu может включать/выключать глобальную рекламу.
- Состояние сохраняется в `advertisement.json`, после чего runtime-настройки `client.ad` обновляются.
- Отдельный пункт показывает текущее состояние рекламы, статус, рекламный текст и параметры отображения.
- Компонентное меню принимает выбор только от пользователя, запустившего setup.

### TOM-106 — Owner diagnostic card бота и окружения
- Owner-команда выводит диагностическую информацию о runtime: рабочий путь, часть сетевой информации, команду PM2, данные Discord Application и настройки public bot.
- При доступности application API показываются имя, владелец/команда, иконка, public/private состояние и описание приложения.
- Это скорее диагностический инструмент владельца, чем пользовательская функция.

## Примечания по дубликатам и состоянию
- `addmoney.js` и `removemoney.js` не добавлены: совпадают с существующими `ECON-014–016`.
- `changeprefix.js` частично пересекается с серверной настройкой prefix, но здесь отдельно зафиксирована именно **глобальная** смена prefix.
- `restartbot.js` зафиксирован как process-manager restart, несмотря на небезопасное отсутствие owner-check.
- `stopbot.js` не добавлен: фактический PM2 stop-код недостижим из-за раннего `return`, команда отключена.
- `reloadbot.js` не считается рабочей hot-reload-командой в текущей ветке, но её архитектурный механизм сохранён в TOM-101.
- `detailedeval.js` и `eval.js` не добавлены как отдельные пользовательские системы: это owner developer/debug tooling; существенный вариант подробного вывода eval уже выражен в существующей инфраструктуре/диагностике.
