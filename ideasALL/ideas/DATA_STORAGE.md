# DATA / STORAGE — Банк идей

## DATA-001 — Изолированное хранилище данных каждого модуля
Каждый модуль получает собственную директорию данных, чтобы его файлы не смешивались с данными других систем.

## DATA-002 — Хранилище core отдельно от пользовательских модулей
Системные данные и данные расширений физически разделены разными путями.

## DATA-003 — Bundled data только для чтения
Статические файлы, поставляемые вместе с модулем, рассматриваются как read-only assets и не используются для хранения изменяемого состояния.

## DATA-004 — Несколько экземпляров бота
Конфигурация должна поддерживать независимые bot instances с отдельными именами и data paths на одной машине.

## DATA-005 — Временный экземпляр для запуска без постоянного состояния
Можно создать temporary instance с временной директорией и storage-конфигурацией; его данные удаляются после завершения жизненного цикла/перезапуска.

## DATA-006 — Абстракция типа хранилища
Бизнес-логика модулей не должна зависеть от конкретного backend хранения: тип storage и его параметры задаются конфигурацией.

## DATA-007 — Дефолтная конфигурация bootstrap
Минимальная конфигурация содержит базовый data path и относительные пути для core/cog данных и может быть создана автоматически.

## DATA-008 — Глубокая копия storage details
Параметры backend передаются как отдельный набор storage details, а наружу выдаётся копия, чтобы вызывающий код не менял внутреннюю конфигурацию напрямую.

## DATA-009 — Версионирование схемы конфигурации
У persistent-конфигурации хранится schema version; миграции выполняются при загрузке и затем версия обновляется.

## DATA-010 — Lock на миграцию конфигурации
Миграция данных защищается общей блокировкой, чтобы параллельная загрузка/выгрузка одного модуля не запустила миграцию дважды.

## DATA-011 — Явная проверка bootstrap-состояния
Доступ к data path до загрузки базовой конфигурации должен завершаться понятной ошибкой, а не молчаливым созданием данных в неправильном месте.

## DATA-012 — Доступ к данным модуля через его экземпляр
API хранения может автоматически определять имя/директорию модуля из его класса, уменьшая риск ручного указания неправильного пути.
