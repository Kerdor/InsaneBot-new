# Tomato6966 — Batch 12

## Database / persistence architecture

### TOM-198 — Разделение Enmap-баз по доменам и отдельным каталогам
- Каждый логический тип данных хранится в отдельной Enmap-базе.
- Для баз задаются собственные `name` и `dataDir`.
- Домены разнесены по каталогам: economy, premium, stats, settings, setups, queuesaves, warns, ranking, reactionrole, social_log, blacklist, customcommands, keyword и т.д.
- Это позволяет не смешивать настройки, статистику, экономику и другие подсистемы в одном хранилище.

### TOM-199 — Масштабирование конфигурационных систем через numbered slots
- Архитектура заранее рассчитана на множество независимых конфигураций одного типа.
- В коде предусмотрены варианты `jtc1...jtc100`, `roster1...roster100`, `autosupport1...autosupport100`, `menuticket1...menuticket100`, `menuapply1...menuapply100`, `apply1...apply100`.
- Это не отдельная пользовательская функция, а архитектурный паттерн хранения до 100 независимых конфигураций одной системы.

### TOM-200 — Инициализация схемы данных через ensure/default records
- При запуске базы заранее создаются обязательные записи с начальными значениями.
- Примеры: глобальная статистика, premium list, mutes, AFK reminders и массивы ticket/apply/menu-ticket систем.
- Позволяет остальным модулям рассчитывать на существование базовой структуры данных без ручного создания при первом использовании.

## Проверка `databases/`
- Директория содержит Enmap/SQLite runtime-хранилища и placeholder-файлы, а не самостоятельные команды или обработчики.
- `enmap.sqlite` и WAL-файлы являются бинарными артефактами состояния; новой пользовательской механики сами по себе не содержат.
- `handlers/loaddb.js` проверен полностью и является источником архитектурных деталей выше.
