# GAwesomeBot — Database

> Механики и архитектурные идеи, найденные в `GAwesomeBot/bot/Database/`.
> Это не копирование реализации, а идеи для собственной архитектуры InsaneBot.

## Database / ODM

### GAB-DB-001 — Собственный слой доступа к БД
- Источник: `Database/Driver.js`, `Model.js`
- Категория: Архитектура
- Описание: Бот работает не напрямую с MongoDB во всех местах, а через собственный слой Model/Document/Query.
- Механики / детали: единая точка доступа к коллекциям, единый API, централизованные ошибки.
- Наш вариант: отдельный `database/` слой, скрывающий конкретный движок БД.
- Статус: ⬜ НЕ РЕШЕНО

### GAB-DB-002 — Инициализация всех моделей одной процедурой
- Источник: `Driver.js`
- Категория: База данных
- Описание: запуск БД создаёт и регистрирует все модели сразу.
- Механики / детали: Servers, Users, Gallery, Blog, Wiki, Traffic и т. д.
- Наш вариант: единый startup database initializer.
- Статус: ⬜ НЕ РЕШЕНО

### GAB-DB-003 — Глобальный контейнер моделей
- Источник: `Driver.js`
- Категория: Архитектура
- Описание: модели и соединение доступны через единый контейнер Database.
- Механики / детали: единообразные имена коллекций, отдельные алиасы.
- Наш вариант: dependency container вместо разбросанных глобальных подключений.
- Статус: ⬜ НЕ РЕШЕНО

### GAB-DB-004 — Модель как абстракция коллекции
- Источник: `Model.js`
- Категория: База данных
- Описание: Model предоставляет стандартные операции над коллекцией.
- Механики / детали: find, findOne, count, aggregate, update, insert, delete, create.
- Наш вариант: единый repository/model API.
- Статус: ⬜ НЕ РЕШЕНО

### GAB-DB-005 — Цепочный Cursor API
- Источник: `Cursor.js`
- Категория: База данных
- Описание: результаты поиска можно настраивать цепочкой методов.

- Наш вариант: поддержать chainable query API там, где это действительно упрощает код.

- Наш вариант: repository возвращает типизированные domain objects.
- Статус: ⬜ НЕ РЕШЕНО

### GAB-DB-007 — Document как объект с поведением
- Источник: `Document.js`
- Категория: База данных
- Описание: запись БД представляется объектом, который умеет валидироваться, сохраняться и запускать query.
- Механики / детали: `save`, `validate`, `cache`, `query`, `toObject`.
- Наш вариант: domain model с явным lifecycle.

### GAB-DB-008 — Отложенное сохранение изменений
- Источник: `Document.js`
- Категория: База данных
- Описание: изменения документа сначала накапливаются, а запись выполняется при `save()`.
- Механики / детали: pending operations хранятся отдельно от данных документа.
- Наш вариант: использовать для составных изменений, если это не усложняет систему.
- Статус: ⬜ НЕ РЕШЕНО

### GAB-DB-009 — Батчинг атомарных операций документа
- Источник: `Document.js`
- Категория: Надёжность
- Описание: несколько изменений объединяются в MongoDB operations перед сохранением.
- Механики / детали: `$set`, `$inc`, `$unset`, `$push`, `$pull`, `$pullAll`.
- Наш вариант: атомарные обновления вместо полного перезаписывания записи.
- Статус: ⬜ НЕ РЕШЕНО

### GAB-DB-010 — Слияние конфликтующих atomic operations
- Источник: `Document.js`
- Категория: Надёжность
- Описание: слой БД пытается объединять совместимые операции над одним путём и устранять конфликтующие операции.
- Механики / детали: отдельная логика `_mergeAtomics`.
- Наш вариант: централизованный механизм нормализации update operations.
- Статус: ⬜ НЕ РЕШЕНО

### GAB-DB-011 — Атомарный increment
- Источник: `Document.js`, `Query.js`
- Категория: База данных
- Описание: числовые счётчики обновляются через инкрементальную операцию, а не чтение+полную запись.
- Механики / детали: накопление нескольких `inc` может объединяться.
- Наш вариант: использовать для XP, сообщений, статистики, экономики и счётчиков.
- Статус: ⬜ НЕ РЕШЕНО

### GAB-DB-012 — Cache hook на уровне документа
- Источник: `Document.js`, `Model.js`
- Категория: Производительность

- Механики / детали: проверка существования записи, принудительное обновление cache.
- Наш вариант: кэшировать только горячие сущности с контролем инвалидирования.
