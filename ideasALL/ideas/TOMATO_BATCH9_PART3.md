# Tomato6966 — Batch 9, Part 3

Источник: `Tomato6966/Multipurpose-discord-bot`
Ветка: `new_2025`
Раздел: `commands/💪 Setup`

### TOM-146 — Интерактивная смена языка бота с reset и просмотром
- Setup открывает select-menu с действиями `Change Language`, `Reset Language`, `Settings` и `Cancel`.
- Доступны несколько языков, включая English, German, French, Italian, Spanish, Hindi, Dutch, Turkish и Persian/Iran.
- Выбор языка выполняется отдельными кнопками.
- После выбора UI блокируется, а collector имеет ограниченное время жизни.
- Отдельно доступен возврат к английскому по умолчанию и просмотр текущего языка.

### TOM-147 — Отдельный лог выполнения административных команд
- Сервер может назначить отдельный канал, куда отправляется информация о выполнении Admin-команд.
- Система независимо включается и выключается.
- Есть отдельный просмотр текущего канала.
- Настройка выполняется через интерактивный select-menu и ограничивается инициатором.
- Это отдельный тип command-execution logging, не общий Audit Logger.

### TOM-148 — До 25 независимых Member Counter систем
- На одном сервере можно настроить до `25` отдельных member-counter конфигураций.
- Для каждой системы отдельно хранится канал и шаблон его имени.
- Настройка выбирает конкретный номер counter через multi-page/select UI.
- При изменении можно показать текущее имя канала и заменить его новым шаблоном.

### TOM-149 — Шаблоны Member Counter с большим набором серверных счётчиков
- Имя counter может содержать placeholders для общего числа пользователей, людей, ботов и их online/idle/dnd/offline состояний.
- Доступны отдельные placeholders для members без ботов.
- Можно получать количество каналов, text/voice/stage/news/category/thread, открытых/архивных threads и ролей.
- Шаблон ограничен `32` символами Discord channel name.
- Это позволяет одним переименовываемым каналом показывать произвольную серверную статистику.

### TOM-150 — Menu Apply: единая панель выбора между множеством Application Systems
- Отдельная Menu Apply конфигурация показывает select-menu для запуска одного из Application Systems.
- Поддерживается до `100` независимых Menu Apply конфигураций.
- Внутри одной панели можно хранить до `25` вариантов подачи заявки.
- Каждый вариант имеет value/description/emoji и связан с отдельной application-категорией/ответом.
- Панель можно повторно публиковать в выбранный канал, сохраняя message/channel IDs.

### TOM-151 — Menu Ticket: единая панель выбора между множеством Ticket Systems
- Отдельная Menu Ticket конфигурация объединяет несколько Ticket Systems в одном select-menu.
- Поддерживается до `100` независимых Menu Ticket конфигураций.
- Внутри одной панели — до `25` ticket options.
- Для option сохраняются value, description, emoji, категория и ответное сообщение.
- Настройка панели позволяет отдельно управлять общим доступом пользователей/ролей и категорией закрытых тикетов.

### TOM-152 — Настраиваемый Claim System внутри конкретной Menu Ticket конфигурации
- Для каждого Menu Ticket System Claim можно включать/выключать независимо.
- Отдельно настраивается сообщение при открытии тикета до claim.
- Отдельно настраивается сообщение после claim с placeholder `{claimer}`.
- Таким образом claim workflow и его тексты являются частью конфигурации конкретной ticket-системы.

### TOM-153 — Постоянная Music Request панель с кнопками управления
- Setup публикует в выбранный text-channel постоянную панель музыкального управления.
- Панель содержит queue embed и кнопку/интерфейс для Join/Leave, Skip, Stop, Pause, Autoplay, Shuffle, Song Loop, Queue Loop, seek ±10 секунд и Lyrics.
- Сохраняются IDs канала и сообщения панели для дальнейшего управления системой.
- Пользователь отправляет название/ссылку трека в этом канале, а панель используется как постоянный UI музыкального player.

### TOM-154 — Toggle реакции на сообщения с валидным code snippet
- Сервер может отдельно включить/выключить систему распознавания сообщений с валидным фрагментом кода.
- При включении такие сообщения обрабатываются системой Valid-Code; при выключении бот ничего не делает с ними.
- Есть отдельный просмотр текущего состояния.
- Настройка выполнена через интерактивное меню.

### TOM-155 — Joinlist: автоматические правила для новых участников по нескольким признакам
- Для события входа пользователя можно создавать правила, которые проверяют `username_contain`, `username_equal`, `userid`, `server_in_common`, `server_not_in_common` или отсутствие пользовательского avatar.
- Для каждого правила доступны действия `kick`, `ban`, `timeout` и `setnickname`.
- Правила добавляются и удаляются из guild-scoped конфигурации.
- Для ban можно задавать срок в днях, включая бессрочный вариант.
- Timeout принимает составные длительности вроде `1day+10min` и валидирует итоговое время.
- `setnickname` поддерживает произвольный новый nickname и специальный `{random}`.
- Это позволяет выполнять security/moderation действие сразу при join на основании характеристик аккаунта и внешнего состояния пользователя.

### TOM-156 — До 100 независимых Join-to-Create конфигураций
- Setup поддерживает до `100` отдельных JTC systems, каждая со своей конфигурацией.
- Для каждой системы можно автоматически создать отдельный trigger voice channel либо использовать уже существующий voice channel пользователя как trigger.
- Для каждой системы отдельно задаётся шаблон временного имени комнаты.
- При создании нового trigger канал получает базовые настройки user limit `4` и bitrate с учётом уровня server boosts.
- После создания сохраняется ID trigger channel и конфигурация конкретного JTC instance.

### TOM-157 — Переключение способа mute: timeout или роль
- Сервер может выбрать, как реализуется mute: Discord timeout либо выдача отдельной mute-role.
- При role-style можно отдельно указать роль, которая будет назначаться muted-пользователю.
- Способ mute переключается через setup без изменения самих moderation commands.

### TOM-158 — Глобальное default mute time с составными длительностями
- Можно задать время mute по умолчанию, если конкретная moderation команда не передала длительность.
- Поддерживаются составные значения вроде `1hour+5min`.
- Значение валидируется и ограничивается максимумом в `1 Week`.

### TOM-159 — Level-up announcement: отдельный канал или reply
- В leveling setup можно направлять сообщения о повышении уровня в специальный канал либо переключить систему на reply к исходному сообщению пользователя.
- Это позволяет отделить способ публикации level-up от самого начисления XP.

### TOM-160 — До 100 независимых Server Roster систем
- На одном сервере можно создать до `100` отдельных Roster System.
- Для каждой отдельно задаются канал, список отображаемых ролей, заголовок, emoji, стиль и режим отображения.
- Roster можно полностью удалить/reset без затрагивания остальных экземпляров.

### TOM-161 — Настраиваемый стиль и плотность Server Roster
- Для roster отдельно настраиваются style отображения, inline-режим полей и ограничение/полный показ участников ролей.
- Можно добавлять, удалять и просматривать roster roles поштучно.
- Изменение конфигурации обновляет опубликованное roster-сообщение.

### TOM-162 — Отдельный Report Log канал
- Сервер может назначить отдельный канал для логирования использования команды `report`.
- Лог можно отдельно включить и отключить.
- Канал выбирается интерактивно, а настройка доступна только администраторам.
