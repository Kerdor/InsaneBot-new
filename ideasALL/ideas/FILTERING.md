# Filtering / Content Control

## FILTER-001 — Серверный список фильтра
Хранить набор запрещённых слов/фраз с добавлением, удалением, просмотром и полным очищением.

## FILTER-002 — Фильтр на уровне канала
Отдельный список запрещённых слов/фраз для конкретного канала, объединяемый с серверным списком.

## FILTER-003 — Фильтр с наследованием для thread
Сообщения в thread проверяются по фильтру родительского канала, а отдельный список для thread не создаётся.

## FILTER-004 — Фильтрация имён и nickname
Опционально проверять display name/nickname участников при входе и изменении имени.

## FILTER-005 — Безопасная замена отфильтрованного nickname
Если имя нарушает фильтр, автоматически установить заранее заданное безопасное имя (по умолчанию fallback-name настраивается сервером).

## FILTER-006 — Автобан по частоте срабатываний фильтра
Настройка `count + timeframe`: пользователь получает бан, если совершил заданное число filter hits за окно времени. `0 + 0` отключает функцию.

## FILTER-007 — Счётчик фильтр-хитов на пользователя с автоматическим reset
Для каждого участника хранить количество срабатываний и время следующего сброса окна; при наступлении нового окна счётчик обнуляется.

## FILTER-008 — Фильтр по границам слов
Слово считается совпавшим только как отдельный token/phrase, чтобы фильтр не ловил случайные части других слов.

## FILTER-009 — Case-insensitive фильтр
Список нормализуется в lowercase, поиск выполняется без учёта регистра.

## FILTER-010 — Проверка не только message.content
В filter pipeline можно анализировать вопрос poll, варианты poll, descriptions вложений, forwarded snapshots, embeds и текст компонентов.

## FILTER-011 — Удаление сообщения + modlog case
При срабатывании сообщение удаляется, а событие записывается отдельным case type с найденными словами.

## FILTER-012 — Отдельный case type для автобана
Сам факт превышения лимита filter hits создаёт отдельный тип modlog case, а не смешивается с обычным filter hit.

## FILTER-013 — Проверка отредактированных сообщений
Изменение существующего сообщения повторно проходит через фильтр.

## FILTER-014 — Иммунитет automod для доверенных пользователей
Общий automod immunity должен отключать filter pipeline для защищённых участников.

## FILTER-015 — Кэш скомпилированного regex
Для каждой пары guild/channel кэшировать compiled pattern и инвалидировать его при изменении списков.

## FILTER-016 — Список фильтра можно выдавать в DM
Большой список правил отправлять автору в личные сообщения с пагинацией; при закрытых DM показывать понятную ошибку.

## FILTER-017 — Массовое добавление/удаление фраз
Команда принимает несколько слов сразу, а двойные кавычки позволяют передавать целые предложения как один элемент.

## FILTER-018 — Настройка причины и отображения filter events
Filter hit и filter ban могут иметь отдельные изображения/названия case types и независимо включаться в modlog.
