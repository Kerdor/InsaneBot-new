# CorwinDev/Discord-Bot — Batch 2

Источник: `CorwinDev/Discord-Bot`, branch `main`.

## Birthdays

### COR-081 — Personal birthday check
- Пользователь может отдельно посмотреть сохранённую дату своего дня рождения.
- Если дата не задана — понятная ошибка вместо пустого результата.

### COR-082 — Birthday board
- Все дни рождения сервера можно выводить отдельным leaderboard-представлением.
- Формат содержит пользователя и дату.

### COR-083 — Birthday overwrite
- Повторная установка дня рождения обновляет существующую запись, а не создаёт дубликат.

### COR-084 — Birthday deletion
- Для персональной даты предусмотрено отдельное удаление.

### COR-085 — Date validation before save
- День и месяц проверяются до записи в БД.
- Формат даты можно приводить к читаемому виду с порядковым суффиксом.

## Bot information / diagnostics

### COR-086 — Global bot statistics через shard broadcast
- Общая информация о боте может собираться одновременно со всех shard'ов.
- Отдельно агрегируются guilds, members, channels и voice connections.

### COR-087 — Bot info как диагностическая карточка
- Один экран может объединять имя/ID, shard count, owner/developers, command count, servers, members, uptime, latency, версии Node/Discord.js и memory usage.

### COR-088 — Разделение global и local shard statistics
- Диагностическая команда показывает как общее число серверов, так и количество серверов текущего shard'а.

### COR-089 — Runtime diagnostics для администратора
- В bot-info можно показывать uptime, API latency, version приложения, runtime version и использование памяти.

## Guild information

### COR-090 — Расширенная карточка сервера
- Серверная информация объединяет owner, verification level, boost tier/count, дату создания, members/bots и разные типы каналов.

### COR-091 — Статистика threads в server info
- Public и private threads можно считать отдельными категориями.

### COR-092 — Статистика stickers
- Помимо emoji серверная карточка показывает количество stickers.

### COR-093 — Verification level с человекочитаемыми состояниями
- Числовой Discord verification level преобразуется в понятное название.
- Для высоких уровней допустим тематический/юмористический вариант отображения.

### COR-094 — Boost tier как отдельная метрика
- Premium tier и фактическое число boosts выводятся раздельно.

## Leveling / progression

### COR-095 — Уникальная награда на конкретном уровне
- Для одного guild + level нельзя создать несколько конфликтующих role rewards.

### COR-096 — Role reward за уровень
- Достижение заданного уровня может автоматически давать Discord role.

### COR-097 — Отдельный список level rewards
- Настроенные награды можно просматривать единым списком `Level → Role`.

### COR-098 — Rank card вместо обычного текста
- Профиль прогресса можно отображать графической rank-картой с avatar, username, level, XP, required XP, rank и progress bar.

### COR-099 — Rank card учитывает позицию пользователя
- Помимо личного XP/level показывается место пользователя в серверном рейтинге.

### COR-100 — Levels feature gate
- Команды progression должны проверять, включена ли система уровней на конкретном guild.

## Message progression

### COR-101 — Награда за количество сообщений
- Можно задать threshold сообщений, после которого пользователь получает Discord role.

### COR-102 — Уникальный message threshold
- Один и тот же guild + количество сообщений не должно иметь несколько разных наград.

## Personal notes

### COR-103 — Личный серверный блокнот
- Пользователь может сохранять короткие заметки, привязанные к guild и собственному ID.

### COR-104 — Короткий числовой код заметки
- При создании заметке выдаётся небольшой числовой код, который можно использовать для последующих операций.

### COR-105 — Пространство заметок per-user
- Записи отделяются по автору, поэтому пользователь работает со своими заметками независимо от остальных.

## Sticky messages

### COR-106 — Sticky message с сохранением последнего message ID
- Для канала хранится текст sticky-сообщения и ID последнего опубликованного сообщения.
- Это позволяет отслеживать/заменять актуальный sticky message.

### COR-107 — Один sticky message на канал
- Повторная настройка канала обновляет существующую запись вместо создания нескольких независимых sticky-конфигураций.

### COR-108 — Sticky message через embed
- Закрепляемый системный текст можно визуально отделять от обычных сообщений через embed.

## Suggestions

### COR-109 — Suggestions как отдельный канал
- Сервер хранит специальный канал для предложений.

### COR-110 — Автор предложения в embed
- Предложение публикуется с username/tag и avatar автора.

### COR-111 — Upvote/downvote через reactions
- После публикации suggestion автоматически получает две реакции для голосования.

### COR-112 — Явное сообщение о незаполненном suggestions setup
- Если канал предложений не настроен, пользователь получает понятное указание выполнить setup.

## Thanks / reputation

### COR-113 — Система благодарностей
- Пользователь может публично поблагодарить другого участника.
- Полученные благодарности накапливаются как отдельный reputation counter.

### COR-114 — Запрет благодарности самому себе
- Self-target для thanks блокируется.

### COR-115 — Один thanks от одного автора одному пользователю
- Отдельная связь `target + author` не позволяет одному человеку многократно накручивать благодарность одному и тому же пользователю.

## Invites

### COR-116 — Invite leaderboard
- Приглашения можно сортировать по количеству и показывать серверным leaderboard.

### COR-117 — Стабильное хранение invite statistics
- Invite count хранится отдельно от Discord invite object, чтобы использовать его в leaderboard/reward-системах.

## Voice

### COR-118 — Управление только своим временным voice
- Перед переименованием/изменением voice проверяется, что канал действительно доступен пользователю через custom-voice ownership logic.

### COR-119 — Rename temporary voice
- Владелец временного voice может менять название канала через команду.

### COR-120 — Voice-команды проверяют bot permissions
- Перед изменением voice channel проверяется наличие у бота `ManageChannels`.

### COR-121 — Voice-команда требует нахождения в voice
- Команды управления собственным voice не выполняются, если пользователь не находится в голосовом канале.

## General UX / validation

### COR-122 — Единый стиль success/error responses
- Команды используют общие helper'ы для успешных и ошибочных ответов, сохраняя единый UX.

### COR-123 — Пустые коллекции обрабатываются явно
- Leaderboard/list команды возвращают понятное сообщение при отсутствии данных вместо пустого embed.

### COR-124 — Feature-specific database models
- Даже небольшие подсистемы получают отдельные модели БД: birthdays, notes, suggestions, thanks, invites, level rewards и т.д.

### COR-125 — Проверка конфигурации перед действием
- Функциональные команды сначала проверяют наличие требуемой guild-конфигурации, а уже затем выполняют действие.
