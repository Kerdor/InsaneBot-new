# PYTHON-DISCORD MODERATION 2 — Дополнительные модерационные механики

Уникальные механики из `python-discord/bot/exts/moderation/`, не дублирующие уже занесённые общие идеи.

## PDIS-M2-001 — DEFCON: временный порог возраста Discord-аккаунта
- В аварийном режиме сервер может требовать минимальный возраст Discord-аккаунта для входа.
- Слишком новые аккаунты автоматически отклоняются/кикаются при `on_member_join`.
- Пользователю сначала отправляется объяснение причины отказа в DM, если это возможно.
- Модераторам дополнительно логируется причина отказа и факт невозможности отправить DM.

## PDIS-M2-002 — Автоматическое истечение аварийного режима
- DEFCON threshold может иметь expiry timestamp.
- После наступления expiry scheduler автоматически снимает ограничение.
- Если ограничение включено без expiry, бот периодически напоминает модераторам, что режим всё ещё активен.
- Текущее состояние хранится в Redis и восстанавливается после перезапуска.

## PDIS-M2-003 — Аварийный server lockdown через права @everyone
- Отдельная административная операция может временно закрыть сервер, изменяя permissions роли `@everyone`.
- Одновременно блокируются отправка сообщений, реакции, сообщения в threads и подключение к voice.
- Отдельная команда возвращает эти права обратно.
- Это можно использовать как emergency-кнопку при рейдах/атаках.

## PDIS-M2-004 — Incident workflow через реакции как конечные статусы
- Сообщение в специальном incident-канале автоматически получает фиксированный набор реакций-сигналов.
- Только пользователи с разрешёнными ролями могут использовать эти сигналы; чужие реакции автоматически удаляются.
- Промежуточный сигнал вроде `investigating` не завершает incident, а финальные `actioned/rejected` запускают архивирование.
- Такой workflow позволяет использовать обычные Discord reactions как простой moderation state machine без отдельной панели.

## PDIS-M2-005 — Startup catch-up для пропущенных incident reports
- При запуске бот сканирует последние сообщения incident-канала и добавляет отсутствующие служебные реакции.
- После каждой операции выдерживается пауза, чтобы не попасть в rate limit.
- Уже полностью обработанные сообщения пропускаются.
- Основные event listeners ждут завершения catch-up, чтобы не было гонки между историческим сканированием и live-событиями.

## PDIS-M2-006 — Безопасное удаление incident только после успешного архивирования
- Перед удалением исходного incident бот сначала создаёт архивную копию через webhook.
- Если архивирование не удалось, оригинал сохраняется, чтобы информация не была потеряна.
- После удаления бот дополнительно ждёт подтверждение `message_delete` и имеет timeout на случай проблем с событием.
- Состояние параллельных reaction events защищается lock'ом, чтобы два модератора не обработали один incident одновременно.

## PDIS-M2-007 — Восстановление информации об уже удалённом сообщении по modlog
- Если incident содержит ссылку на Discord message, которую уже нельзя получить через API, бот ищет соответствующую запись среди последних modlog сообщений.
- При совпадении jump URL создаётся специальный embed, показывающий, что ссылка относится к удалённому сообщению.
- Это позволяет сохранять полезность старых ссылок даже после удаления исходного контента.

## PDIS-M2-008 — Автоматические preview embeds для ссылок на Discord-сообщения
- Incident parser извлекает Discord message links из текста и превращает их в компактные embeds с автором, каналом, временем, ID и контентом.
- Для attachments используется preview первого вложения.
- Ссылки обрабатываются максимум до лимита Discord embeds за одну отправку.
- Перед показом проверяется, может ли helper/staff-аудитория видеть исходный канал, чтобы не утечь закрытый контент.

## PDIS-M2-009 — `clean` с композиционными фильтрами
- Bulk-clean поддерживает независимые фильтры по пользователям, bot-only и regex, которые могут комбинироваться с временным диапазоном.
- Regex проверяется не только по тексту сообщения, но и по title/description/footer/author/fields embeds.
- Диапазон можно задавать двумя сообщениями, duration или ISO datetime.
- Каналы можно перечислять явно или использовать `*` для всех публичных text channels и threads.

## PDIS-M2-010 — Гибридное удаление: bulk до 14 дней + individual после 14 дней
- Clean автоматически определяет, какие сообщения можно удалить bulk API.
- До 14 дней сообщения группируются по каналам и удаляются пачками до 100 штук.
- Более старые сообщения удаляются по одному, не ломая общую команду очистки.
- Это скрывает техническое ограничение Discord за единым интерфейсом для модератора.

## PDIS-M2-011 — Отмена долгой bulk-clean операции
- Текущая операция имеет общее состояние `cleaning` и может быть прервана отдельной командой `stop/cancel/abort`.
- Поиск и удаление регулярно проверяют этот флаг и прекращают дальнейшую работу.
- Если другая очистка уже выполняется, новый запуск отклоняется вместо параллельного удаления сообщений.
- При исключении состояние автоматически сбрасывается, чтобы cog не застрял в режиме `cleaning`.

## PDIS-M2-012 — Автоматический audit log после bulk-clean
- После удаления бот загружает содержимое удалённых сообщений в отдельный просмотрщик и возвращает ссылку на лог.
- В modlog/message-log фиксируется количество удалённых сообщений, автор операции и затронутые каналы.
- Вне модерационного канала пользовательское подтверждение можно скрывать/удалять после короткой задержки, а staff получает ссылку отдельно.
- Это даёт восстановимый аудит вместо простого сообщения `Deleted N messages`.

## PDIS-M2-013 — Временные streaming permissions с восстановлением после рестарта
- Модератор может выдать участнику роль для streaming на заданный срок.
- Срок сохраняется во внешнем cache, поэтому после рестарта scheduler восстанавливает незавершённые revoke-задачи.
- Участника, покинувшего сервер до истечения срока, запись можно автоматически удалить из cache.

## PDIS-M2-014 — Upgrade временного доступа до постоянного
- Если пользователь уже получил временное право stream, отдельная команда permanent stream отменяет будущий revoke и переводит право в постоянное.
- При этом scheduler и persisted expiry очищаются.
- Это удобный общий паттерн для временных permissions: `temporary -> permanent` без повторной выдачи роли.

## PDIS-M2-015 — Revoke streaming permission одновременно завершает активный stream
- При отзыве video permission бот проверяет, стримит ли пользователь прямо сейчас.
- Если да, участника временно перемещают в AFK voice channel и обратно, чтобы фактически остановить текущую трансляцию.
- Таким образом revoke касается не только будущего доступа, но и уже активной трансляции.

## PDIS-M2-016 — Список временных и постоянных stream-разрешений с сортировкой по expiry
- Модератор может получить список не-staff пользователей с streaming permission.
- Для временных прав показывается оставшееся время до revoke, для постоянных — отдельный статус.
- Список сортируется по ближайшему истечению, а постоянные записи отправляются в конец.
