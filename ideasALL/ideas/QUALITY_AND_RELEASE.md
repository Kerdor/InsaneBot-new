# Quality / CI / Release Engineering

Не пользовательские команды, а полезные инженерные механики, замеченные в Red-DiscordBot.

## QUALITY-001 — Отдельный CI для тестов
Запускать автоматические тесты в GitHub Actions на изменения проекта.

## QUALITY-002 — Отдельный lint pipeline
Статический анализ Python вынесен в отдельный workflow, чтобы ошибки качества кода ловились независимо от функциональных тестов.

## QUALITY-003 — CodeQL security scanning
Автоматически запускать security-анализ исходников через CodeQL.

## QUALITY-004 — Dependency lock/compile check
Отдельный workflow проверяет воспроизводимость и актуальность скомпилированных Python-зависимостей.

## QUALITY-005 — Автоматические проверки метаданных contribution
CI может проверять служебные соглашения репозитория, например полноту/корректность label patterns.

## QUALITY-006 — Автоматизация переводов
Строки локализации можно автоматически выгружать в внешний translation workflow, не заставляя разработчиков вручную синхронизировать весь набор переводов.

## QUALITY-007 — Разделение подготовки и публикации релиза
Release pipeline делится на этап подготовки артефактов и отдельный этап публикации, чтобы выпуск можно было контролируемо проводить по стадиям.

## QUALITY-008 — Security-oriented repository configuration
Хранить отдельные конфиги для Bandit/других security checks и применять их в CI вместо исключительно ручной проверки.

## QUALITY-009 — Игнорирование шумных ревизий Git blame
Отдельный список массовых форматирующих/механических ревизий позволяет не засорять историю `git blame`.
