# Core Framework / Bot Lifecycle

Механики, найденные в `Cog-Creators/Red-DiscordBot`, которые не стоит смешивать с обычными пользовательскими системами.

## CORE-001 — Многоуровневые источники модулей
Бот может искать расширения не только в стандартной директории, но и в нескольких пользовательских путях. Пути имеют порядок приоритета, а дубликаты путей удаляются.

## CORE-002 — Временные пути модулей
Можно добавить путь расширений только на текущий запуск, не сохраняя его в конфигурации.

## CORE-003 — Отдельная install-директория для сторонних модулей
Установленные сторонние модули находятся в отдельном приоритетном пути, который можно заменить.

## CORE-004 — Защита путей модулей
При добавлении пути проверять существование директории и запрещать пути внутри data/core-директорий. Если пользователь указал уже сам пакет c `__init__.py`, показывать предупреждение и подтверждение.

## CORE-005 — Динамический список доступных модулей
Отдельная команда/метод показывает все доступные для загрузки модули, отбрасывая невалидные Python-имена.

## CORE-006 — Управление жизненным циклом модулей
Поддерживать load/unload/reload отдельных модулей и пакетную обработку нескольких модулей за один вызов.

## CORE-007 — Подробный результат пакетной загрузки
После массовой загрузки различать: успешно загруженные, уже загруженные, не найденные, невалидные имена, ошибки с причиной, ошибки без причины и специальные предупреждения совместимости.

## CORE-008 — Последняя ошибка для диагностики
При внутренних исключениях сохранять полный traceback последней ошибки, чтобы отдельная диагностическая команда могла показать его позже.

## CORE-009 — Проверка конфликтов команд при загрузке
Если загружаемый модуль регистрирует существующую команду или alias, загрузка отклоняется с понятным указанием конфликтующего имени.

## CORE-010 — Обновление импортов при reload
Перед загрузкой изменённого модуля очищать/обновлять уже импортированные модули, чтобы reload действительно подхватывал изменения.

## CORE-011 — Инвалидация import-кэша
После установки нового модуля отдельно инвалидировать importlib caches.

## CORE-012 — Глобальные и серверные префиксы
Префиксы можно получать и менять на глобальном уровне, а сервер может иметь собственную настройку.

## CORE-013 — Генерация invite URL с контролем публичности
Invite-команда может быть доступна владельцу всегда, а обычным пользователям только при включённой публичности. Сам invite можно отправлять в DM.

## CORE-014 — Интерактивное подтверждение потенциально опасных действий
Для операций, которые легко выполнить не на том объекте (например, добавление package-директории как cog path), сначала показывать предупреждение и подтверждение.

## CORE-015 — Защита владельца от потери доступа
Система permission overrides должна учитывать специальные уровни привилегий и не допускать случайного лишения владельца критических возможностей.

## CORE-016 — Разделение bot/user permission requirements
Команда может отдельно требовать Discord permissions от пользователя и от самого бота; bot permissions не должны переопределяться пользовательскими правилами.

## CORE-017 — Состояния permission override для групп команд
Для command tree нужны отдельные состояния allow/deny/normal/passive/cautious, чтобы разрешение родителя не ломало ограничения дочерних команд и наоборот.

## CORE-018 — Hook-aware permissions
Permission hooks могут явно разрешить/запретить выполнение, сохраняя отдельное информационное состояние результата для разработчиков.

## CORE-019 — Расширенная команда `info` с runtime-метаданными
Команда информации о боте показывает владельца/команду владельцев, версии Python/discord.py/бота, ссылки на проекты и поддержку, а также пользовательское описание конкретного инстанса.

## CORE-020 — Автоматическая проверка актуальности версии
`info` может обращаться к package registry, сравнивать установленную и последнюю версию и явно сообщать, доступно ли обновление; ошибка проверки не ломает команду.

## CORE-021 — Человекочитаемый возраст инстанса
В runtime-информации можно показывать абсолютную дату начала существования проекта и вычисленный возраст в днях.

## CORE-022 — Машиночитаемые core RPC-методы
Внутренний core слой предоставляет RPC-операции для load/unload/reload модулей, чтения/изменения имени и префиксов, получения версий и генерации invite URL.
