# PYTHON-DISCORD MODERATION 5 — Watch-channel и message relay mechanics

Новые механики из `bot/exts/moderation/watchchannels/_watchchannel.py` и `bigbrother.py`, сверенные с существующим moderation/filtering-банком.

## PDIS-M5-001 — Отложенная агрегация watch-сообщений
- Сообщения отслеживаемых пользователей не отправляются в watch-channel немедленно: они складываются в очередь и после короткой задержки обрабатываются пачкой.
- Это уменьшает количество webhook/API операций при серии сообщений.
- Если во время обработки появляются новые сообщения, они продолжают обрабатываться отдельным проходом без потери уже накопленной очереди.

## PDIS-M5-002 — Двухуровневая очередь по пользователю и каналу
- Очередь relay организована как `user → channel → messages`, поэтому сообщения разных пользователей и каналов сохраняют отдельные последовательности.
- Это позволяет одновременно учитывать автора и исходный канал при дальнейшей агрегации/оформлении.

## PDIS-M5-003 — Групповой header после смены контекста
- Перед серией relay-сообщений создаётся отдельный header только при смене пользователя, исходного канала или после достижения лимита сообщений в текущей группе.
- Header содержит автора, исходный канал/jump URL, время начала наблюдения и причину watch.
- Это делает длинные последовательности сообщений компактнее, чем отдельный полный context для каждого сообщения.

## PDIS-M5-004 — Настройка лимита сообщений на один контекстный header
- Количество сообщений, которые могут идти под одним watch-header, ограничивается отдельным параметром.
- После достижения лимита следующий message автоматически начинает новый контекстный блок.

## PDIS-M5-005 — Защита relay от bot/webhook token leakage
- Перед отправкой watched message содержимое проверяется на Discord bot tokens и webhook URLs.
- При обнаружении секретного токена оригинальный текст целиком заменяется безопасным сообщением о цензурировании.
- Это полезно как отдельный safety layer поверх обычного content filtering.

## PDIS-M5-006 — Отключение нежелательных URL embeds в relay
- Обычные URL из пересылаемого сообщения оборачиваются в inline code, чтобы Discord не создавал внешние embeds.
- Media URLs, являющиеся источниками image/video embeds, исключаются из этой обработки и остаются пригодными для отображения.

## PDIS-M5-007 — Безопасная передача attachments с fallback
- Attachments пересылаются отдельно от текстового webhook-сообщения.
- Если attachment невозможно получить из-за Forbidden/NotFound, вместо молчаливой потери отправляется явный error embed.
- Другие HTTP-ошибки логируются без остановки всего relay-процесса.

## PDIS-M5-008 — Watch-cache с режимом stale fallback
- Список отслеживаемых пользователей хранится в локальном runtime cache, который можно обновить через API.
- Если обновление не удалось, система продолжает показывать ранее закэшированный список и явно сообщает, что данные могут быть устаревшими.
- Для операций, которым нужен свежий cache, ошибка обновления блокирует действие.

## PDIS-M5-009 — Ручной выбор fresh/cache режима при просмотре watch-list
- Команда просмотра списка может явно отключить обновление API и показать текущий локальный cache.
- В результате можно быстро посмотреть состояние даже при проблемах API и отдельно контролировать стоимость/задержку обновления.

## PDIS-M5-010 — История предыдущих watch-инцидентов при повторном watch
- При добавлении пользователя в watch система может показать предыдущие причины наблюдения и их количество.
- Это даёт модератору контекст повторного инцидента прямо в момент повторного назначения watch.

## PDIS-M5-011 — Пометка ушедших участников в watch-list
- Пользователи, которых уже нет на сервере, не удаляются автоматически из исторического списка: их записи визуально перечёркиваются.
- Это сохраняет audit/history, одновременно показывая актуальный статус участника.

## PDIS-M5-012 — Безопасная отмена фонового relay при выгрузке модуля
- При unload cog текущая consumption task отменяется через callback.
- Если очередь ещё обрабатывалась, система отдельно логирует, что часть сообщений могла быть потеряна.
- Такой явный shutdown contract полезен для любых фоновых очередей.
