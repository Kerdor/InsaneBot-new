# MUSIC EVENTS — Банк идей

Дополнительные механики `ItzSudhan/Discord-MusicBot` (v5), найденные в `events/`.

- MUSIC-E001 — Voice state pipeline нормализует `JOIN`, `LEAVE` и `MOVE` в собственные типы перед обработкой музыкальной логики.
- MUSIC-E002 — При `MOVE` voice state рассматривается как `LEAVE` старого канала и `JOIN` нового, но только если соответствующий канал совпадает с каналом player.
- MUSIC-E003 — Количество слушателей считается только по не-bot участникам voice channel.
- MUSIC-E004 — `autoPause` возобновляет музыку только когда после прихода пользователя в пустой канал становится ровно один человек и player действительно был paused.
- MUSIC-E005 — При resume после прихода пользователя сохраняется предыдущий member count, чтобы не срабатывать повторно на одно и то же состояние.
- MUSIC-E006 — Автоматический resume после JOIN сопровождается отдельным короткоживущим embed-уведомлением.
- MUSIC-E007 — При уходе последнего пользователя `autoPause` может остановить воспроизведение без уничтожения player, сохраняя позицию трека.
- MUSIC-E008 — Для pause/resume уведомлений используется тот же механизм замены старого control message, чтобы в канале оставалось актуальное состояние.
- MUSIC-E009 — Автоматический `autoLeave` после ухода последнего пользователя при включённом 24/7 сначала ждёт `disconnectTime`, а затем повторно проверяет, не вернулся ли кто-нибудь.
- MUSIC-E010 — Delayed auto-leave после пустого voice channel отменяется фактически новым состоянием участников, а не отдельным флагом отмены таймера.
- MUSIC-E011 — При autoLeave без 24/7 выход выполняется сразу, а при 24/7 — после configurable grace period.
- MUSIC-E012 — Одновременные `autoPause + autoLeave + 24/7` имеют отдельную семантику: сначала pause при пустом канале, затем delayed destroy, если никто не вернулся.
- MUSIC-E013 — Одновременные `autoPause + autoLeave` без 24/7 позволяют сначала показать pause state, а затем удалить player при отсутствии участников.
- MUSIC-E014 — При autoLeave уничтожение player очищает очередь и отключает autoQueue, предотвращая автоматическое продолжение после выхода.
- MUSIC-E015 — При 24/7 + autoLeave пустой канал всё равно может привести к полному destroy player, то есть 24/7 не является абсолютной защитой от явно включённого autoLeave.
- MUSIC-E016 — Серверный mute самого бота автоматически ставит player на паузу.
- MUSIC-E017 — Снятие server mute с самого бота автоматически возобновляет player.
- MUSIC-E018 — Server mute logic обрабатывается отдельно от JOIN/LEAVE/MOVE и имеет приоритетный ранний return.
- MUSIC-E019 — `raw` Discord voice payload напрямую передаётся в audio manager через `updateVoiceState`, сохраняя низкоуровневые voice events отдельно от бизнес-логики.
- MUSIC-E020 — `ready` инициализирует audio manager bot user id перед установкой Discord presence.
- MUSIC-E021 — Presence задаётся при успешном `ready`, а не только при создании клиента.
- MUSIC-E022 — Mention-only сообщение боту (`@bot` без текста) вызывает справочную карточку с prefix/slash-инструкцией и кнопками Invite/Support.
- MUSIC-E023 — Mention-help предлагает повторно пригласить бота с правильными permissions, если slash commands не отображаются.
- MUSIC-E024 — Система отслеживания удалённых сообщений синхронизируется с реальным `messageDelete` event, чтобы асинхронные cleanup-задачи не пытались удалить уже удалённый объект.
- MUSIC-E025 — Специальный debug mention может извлекать диагностическое значение по ключу из глобального DB либо возвращать platform/architecture окружения.
