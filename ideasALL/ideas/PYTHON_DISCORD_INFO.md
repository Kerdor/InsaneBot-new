# PYTHON-DISCORD INFO — Дополнительные информационные механики

Уникальные механики из `python-discord/bot/exts/info/`, не дублирующие общие идеи банка.

## PDIS-I001 — Автоматический ревьюер Markdown code blocks
- Бот пассивно анализирует сообщения и обнаруживает неправильно оформленные блоки кода.
- Проверяет отсутствие code block, неправильные tick-символы, отсутствие языка и ошибочное указание языка.
- Анализ запускается только в разрешённых каналах и после минимального количества строк.
- Неправильный формат не исправляется молча: бот объясняет конкретную ошибку и показывает пример правильного оформления.

## PDIS-I002 — Самообновляемая подсказка после редактирования сообщения
- Для каждого проблемного сообщения хранится ID отправленной ботом подсказки.
- После редактирования исходного сообщения бот повторно анализирует его.
- Если ошибка исправлена — подсказка удаляется.
- Если ошибка осталась — существующая подсказка редактируется и показывает уже актуальную проблему.
- Подсказка автоматически удаляется через заданное время, даже если пользователь ничего не исправил.

## PDIS-I003 — Контекстная инструкция только при уверенном определении кода
- Отсутствующий code block предлагается только если содержимое похоже на реальный Python/Python REPL код.
- Используется AST-анализ с дополнительной эвристикой для REPL/IPython.
- Простые многострочные выражения/обычный текст не принимаются за код.
- Для плохой indent-ситуации применяется отдельная эвристическая нормализация перед повторным AST-анализом.

## PDIS-I004 — Определение Python REPL по последовательности prompt-строк
- Поддерживаются обычные `>>>`/`...` и IPython-подобные `In [n]:`/continuation-паттерны.
- Для подтверждения требуется несколько распознанных prompt-строк.
- После определения одного типа prompt последующие строки проверяются тем же шаблоном.

## PDIS-I005 — Антиобход Markdown-проверки через альтернативные tick-символы
- Анализатор распознаёт не только backtick, но и набор визуально похожих кавычек/prime-символов.
- Дополнительно проверяется одинаковость символа и длина последовательности.
- Неочевидные варианты неправильного оформления превращаются в точечную подсказку по использованию обычного backtick.

## PDIS-I006 — Fallback на специальный канал для слишком длинного code snippet
- Автоматически полученный из ссылки snippet может быть длиннее удобного лимита текущего канала.
- В этом случае пользователь получает уведомление и полный результат перенаправляется в специальный bot-commands канал.
- Исходное сообщение при этом сохраняет нормальный вид, а автоматически отправленный snippet удаляется по таймеру/реакции пользователя.

## PDIS-I007 — Code snippet extraction из нескольких внешних Git-сервисов
- Одно пассивное сообщение может содержать ссылки на GitHub blob, GitHub Gist, GitLab, Bitbucket и внутренний paste-сервис.
- Для каждого сервиса используется отдельный URL-парсер и fetcher, после чего результаты объединяются в порядке появления ссылок в исходном сообщении.
- Для paste-сервиса поддерживаются несколько выбранных диапазонов строк и несколько файлов из одного paste.

## PDIS-I008 — Безопасная выдача внешнего code snippet с защитой Markdown injection
- Перед публикацией содержимое code snippet дедентится и нормализуется по диапазону строк.
- Backtick внутри исходного кода заменяется безопасной последовательностью с zero-width space, чтобы код не смог закрыть Discord Markdown-блок.
- Язык подсветки выводится из расширения файла только если значение проходит безопасную валидацию.

## PDIS-I009 — Документация Python-символов через Intersphinx inventories
- Бот загружает `objects.inv` внешних проектов и строит локальный индекс символов с прямыми ссылками на документацию.
- По запросу можно искать конкретные классы/функции/символы без отдельной интеграции с каждым сайтом.
- Команда без символа показывает список всех подключённых documentation inventories.

## PDIS-I010 — Автоматическое разрешение конфликтов одинаковых имён документации
- Если разные пакеты содержат символы с одинаковым именем, индекс не теряет ни один из них.
- Система динамически переименовывает конфликтующие записи, добавляя package/group prefix.
- Для специальных групп используется приоритетная схема префиксов.
- В результате запроса исходного имени footer может показать альтернативные имена, если они существовали.

## PDIS-I011 — Ленивый batch-парсинг всей HTML-страницы по одному запросу
- При первом запросе символа загружается HTML страницы, после чего в очередь ставятся все известные символы этой страницы.
- Следующие символы той же страницы получают результат из уже разобранного набора, вместо повторного HTTP-запроса.
- Пользовательский запрос помечается как приоритетный и перемещается в начало очереди.
- Остальные символы постепенно разбираются фоновым worker'ом.

## PDIS-I012 — Приоритет пользовательского запроса внутри фоновой очереди
- Общая очередь документации обслуживает фоновые задачи, но конкретный запрос пользователя получает приоритет.
- `Future` помечается как user-requested, а соответствующий элемент переносится в начало очереди.
- При очистке/перестроении очереди система ждёт именно пользовательские незавершённые запросы, чтобы не обрывать активный ответ.

## PDIS-I013 — Stale documentation detector с ограничением частоты предупреждений
- Если символ есть в inventory, но не найден на реальной странице, бот считает inventory устаревшим.
- В dev-log отправляется предупреждение с конкретным symbol ID и URL.
- Один URL не спамится повторными предупреждениями.
- Redis-счётчик ограничивает число предупреждений и автоматически истекает через несколько недель.

## PDIS-I014 — Постраничный Redis-кэш документации с TTL от первого элемента
- Результаты символов одной HTML-страницы хранятся в общем Redis hash по странице.
- Срок жизни всего набора начинается при первом сохранении и составляет неделю, а не отдельный TTL для каждого символа.
- Внутренний локальный TTL-кэш уменьшает количество Redis TTL-запросов.
- Есть административная команда очистки кэша конкретного пакета или всех его ключей.

## PDIS-I015 — Безопасное обновление documentation inventory
- Во время полного refresh запросы символов блокируются до завершения обновления inventory.
- Старые индексы, scheduler-задачи и queued parser state очищаются согласованно.
- Если удалённый inventory временно недоступен, обновление автоматически повторяется: первый retry через короткий интервал, последующие — реже.
- Некорректный inventory header не ретраится, потому что сервер ответил, но содержимое заведомо неверно.

## PDIS-I016 — Refresh документации с diff добавленных/удалённых пакетов
- Административная команда refresh сравнивает набор inventories до и после обновления.
- Пользователь получает компактный diff с `+` для новых и `-` для исчезнувших пакетов.
- Это позволяет быстро заметить изменение источников документации без ручного просмотра всего списка.

## PDIS-I017 — PEP lookup с часовым cache refresh и fuzzy autocomplete
- Список PEP загружается из API и кешируется в памяти.
- Автоматическое обновление выполняется не чаще одного раза в час.
- Slash autocomplete поддерживает поиск по номеру и нечёткому совпадению по номеру+названию.
- Для слишком длинного числового ввода обновление списка специально не запускается.

## PDIS-I018 — Автоматический месячный список Patreon-поддержки по уровням
- Бот хранит Patreon tiers через Discord roles и определяет фактический максимальный tier участника.
- Список supporters группируется по уровням и содержит отдельный блок для пустого tier.
- В первый день месяца автоматически публикуется обновлённый список.
- Повышение tier обнаруживается через `on_member_update` и сразу публикуется как отдельное публичное событие.

## PDIS-I019 — Агрегатор Python News из RSS и mailing lists
- Фоновый worker периодически собирает новости из нескольких Python mailing lists и RSS PEP feed.
- Состояние уже опубликованных thread/PEP ID хранится во внешней БД, поэтому рестарт не вызывает повторные публикации.
- Старые записи отбрасываются по возрасту, а ответы `Re:` и старые mailing-list threads не публикуются.
- Публикация выполняется через webhook с сохранением автора, времени, ссылки на оригинал и форматированием embed.

## PDIS-I020 — Публикация в Discord News Channel после webhook send
- После отправки новости webhook-ом бот проверяет, находится ли сообщение в News Channel.
- Если да, после успешной фиксации item как `seen` выполняется отдельная публикация сообщения.
- Это позволяет использовать один pipeline для обычного канала и Discord Announcement/News канала.

## PDIS-I021 — Потоковая обработка сжатых внешних inventory без загрузки целиком
- Sphinx inventory v2 читается chunk-by-chunk через потоковый zlib reader.
- Распакованные данные выдаются построчно, поэтому большой `objects.inv` не требуется целиком держать в памяти.
- Парсер дополнительно терпимо пропускает некорректные/многострочные строки, которые не соответствуют ожидаемому формату.

## PDIS-I022 — Поддержка нескольких форматов внешнего inventory
- Documentation loader различает Sphinx inventory v1 и v2 по заголовку.
- Для v1 преобразуются старые типы и автоматически достраиваются anchors.
- Для v2 проверяется наличие zlib и разбираются приоритет, тип, location и display name, оставляя только необходимые данные.
- Неподдерживаемая версия или повреждённый заголовок считается отдельной ошибкой конфигурации.

## PDIS-I023 — Параметрическое усечение длинных сигнатур
- Если несколько сигнатур не помещаются в лимит embed, parser сначала пытается сохранить параметры, а не просто обрезать строку посередине.
- Сигнатуры получают динамический бюджет длины в зависимости от количества отображаемых сигнатур.
- При нехватке места список параметров сокращается на границе отдельных параметров с явным placeholder.

## PDIS-I024 — Усечение документации по семантическим границам Markdown
- Описание ограничивается одновременно по отображаемой длине и количеству строк.
- Parser старается обрезать текст по завершённым Markdown-элементам, а не в произвольном месте.
- Если идеальной границы нет, используются предпочтительные точки: абзац, строка, предложение, запятая или пробел.
- Перед финальным `...` отдельно проверяется, чтобы обрезка не оставила незакрытый code block.

## PDIS-I025 — Адаптивный HTML→Discord Markdown converter
- Для Discord используется собственный слой преобразования HTML вместо прямого стандартного markdownify.
- Нумерованные списки восстанавливают корректную индексацию, вложенные unordered lists получают циклические bullet-символы.
- Заголовки преобразуются в компактный bold вместо Markdown `#`.
- Relative links превращаются в абсолютные относительно исходной документационной страницы, а несовместимые HTML title убираются.
- HTML `pre` автоматически получает `py` syntax highlighting, inline code очищается от лишнего escaping.

## PDIS-I026 — Сохранение только пользовательски запрошенных futures при очистке очереди
- При сбросе batch parser ожидает завершения только futures, которые реально были запрошены пользователем.
- Фоновые элементы можно безопасно отменить и очистить, не задерживая reload/refresh ради полного разбора очереди.
- Это разделяет жизненный цикл пользовательских запросов и фонового prefetch.
