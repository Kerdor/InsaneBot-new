# GAwesomeBot — PM / DM command mechanics

Источник: `GAwesomeBot/bot`, branch `indev-4.0.2`
Область: `Commands/PM/` + связанный `Commands/Private/giveaway.js`

## Personal / AFK

- **GAB-PM-001** — Глобальное AFK-сообщение пользователя хранится в его user document.
- **GAB-PM-002** — AFK-сообщение показывается при упоминании пользователя на любом сервере.
- **GAB-PM-003** — AFK можно задать прямо через личное сообщение боту.
- **GAB-PM-004** — Специальный маркер `.` используется для удаления AFK-сообщения.
- **GAB-PM-005** — Вызов AFK без аргумента показывает текущее глобальное сообщение.
- **GAB-PM-006** — Если AFK не настроен, бот объясняет, как его установить.
- **GAB-PM-007** — После изменения AFK бот сразу показывает инструкцию по изменению/удалению.
- **GAB-PM-008** — Сохранение пользовательских настроек выполняется отдельно от отправки ответа.
- **GAB-PM-009** — Ошибка сохранения user document логируется, не ломая пользовательский ответ.

## Personal profile

- **GAB-PM-010** — Профиль имеет отдельный интерактивный `setup`-мастер в DM.
- **GAB-PM-011** — Мастер сначала спрашивает, делать ли профиль публичным.
- **GAB-PM-012** — Публичность профиля распространяется на дополнительные данные вроде mutual servers и profile fields.
- **GAB-PM-013** — Текущее состояние настройки показывается перед вопросом, чтобы пользователь понимал изменение.
- **GAB-PM-014** — Каждый шаг мастера отображает текущие значения пользователя.
- **GAB-PM-015** — Профиль позволяет задавать собственный background image URL.
- **GAB-PM-016** — Перед сменой background показывается текущая картинка.
- **GAB-PM-017** — Для background поддерживается `.` = оставить текущее значение.
- **GAB-PM-018** — Для background поддерживается `default` = вернуть стандартное изображение.
- **GAB-PM-019** — URL background предварительно проверяется helper-ом URL.
- **GAB-PM-020** — Профиль позволяет задать Bio.
- **GAB-PM-021** — Для Bio задан явный лимит 2000 символов.
- **GAB-PM-022** — Для Bio поддерживается `.` = не менять.
- **GAB-PM-023** — Для Bio поддерживается `none` = удалить поле.
- **GAB-PM-024** — При отсутствии существующего Bio `.` корректно оставляет значение null/пустым.
- **GAB-PM-025** — Мастер имеет отдельный `quit`-выход.
- **GAB-PM-026** — Пользователь может прервать мастер без сохранения текущего незавершённого шага.
- **GAB-PM-027** — Каждый интерактивный шаг имеет собственный timeout.
- **GAB-PM-028** — При timeout изменяемое значение сохраняется в прежнем состоянии.
- **GAB-PM-029** — После timeout исходное prompt-сообщение редактируется в уведомление о сохранении старого значения.
- **GAB-PM-030** — Timeout различается как отдельный тип ошибки workflow.
- **GAB-PM-031** — Время ожидания может различаться по типу данных: короткое для privacy, 2 минуты для image, 5 минут для Bio.
- **GAB-PM-032** — После завершения мастера даётся ссылка на готовый публичный профиль.
- **GAB-PM-033** — Ссылка на профиль строится с URL-encoded поисковым параметром.
- **GAB-PM-034** — В profile setup используется avatar пользователя как thumbnail каждого шага.
- **GAB-PM-035** — Мастер последовательно собирает изменения в отдельном объекте, а затем применяет их к document.

## Personal reminders

- **GAB-PM-036** — DM-команда reminder поддерживает установку напоминания через естественный duration parser.
- **GAB-PM-037** — После создания напоминания бот сообщает относительное время с human-readable формулировкой.
- **GAB-PM-038** — Вызов reminder без аргумента показывает все активные напоминания пользователя.
- **GAB-PM-039** — Каждое напоминание отображается отдельным embed field.
- **GAB-PM-040** — Время каждого напоминания показывается как относительное `from now`.
- **GAB-PM-041** — Пустой список напоминаний имеет отдельный friendly-state.
- **GAB-PM-042** — В empty-state сразу показывается usage для создания первого reminder.
- **GAB-PM-043** — Неверный duration/input приводит к стандартному invalid-usage ответу.

## Server nick / aliases

- **GAB-PM-044** — Пользователь может назначить собственный короткий alias серверу.
- **GAB-PM-045** — Alias хранится персонально, а не глобально для всего сервера.
- **GAB-PM-046** — Alias используется в последующих командах вместо полного имени сервера.
- **GAB-PM-047** — Сервер можно адресовать по имени, ID или сохранённому персональному alias.
- **GAB-PM-048** — Если имя сервера неоднозначно, бот явно сообщает о нескольких совпадениях.
- **GAB-PM-049** — Если сервер не найден, бот сообщает, что он отсутствует или бот в нём не состоит.
- **GAB-PM-050** — Повторная установка существующего alias требует подтверждения.
- **GAB-PM-051** — Для overwrite используется отдельный confirmation workflow с timeout.
- **GAB-PM-052** — Alias можно удалить специальным параметром `.`.
- **GAB-PM-053** — После удаления alias бот предупреждает, что далее потребуется полное имя сервера.
- **GAB-PM-054** — Вызов команды без аргумента показывает полный список пользовательских server aliases.
- **GAB-PM-055** — Список aliases сортируется по имени alias.
- **GAB-PM-056** — При построении списка бот дополнительно резолвит актуальное имя каждого сервера.
- **GAB-PM-057** — Недоступный/удалённый сервер в списке не ломает весь список, а получает `invalid-server`.
- **GAB-PM-058** — Empty-state aliases объясняет назначение функции и показывает usage.
- **GAB-PM-059** — Alias overwrite меняет только server ID, сохраняя сам alias.
- **GAB-PM-060** — Проверка существования сервера выполняется до записи нового alias.

## Remote server commands from DM

- **GAB-PM-061** — Некоторые серверные команды доступны пользователю через DM и затем relay-ятся в нужный guild.
- **GAB-PM-062** — Remote-команда принимает идентификатор/имя сервера и имя канала через разделитель `|`.
- **GAB-PM-063** — Перед долгой remote-операцией пользователь получает промежуточное `Preparing/Fetching Data` сообщение.
- **GAB-PM-064** — Relay получает user ID вместе с server search string.
- **GAB-PM-065** — Relay может возвращать машинные статусы `true`, `none`, `multi`.
- **GAB-PM-066** — `none` превращается в понятное сообщение о ненайденном сервере.
- **GAB-PM-067** — `multi` превращается в подсказку использовать уникальный server nick или ID.
- **GAB-PM-068** — При ошибке промежуточное сообщение редактируется вместо отправки нового сообщения.
- **GAB-PM-069** — Remote operation допускает короткую асинхронную задержку перед relay.
- **GAB-PM-070** — Некорректные параметры remote-команды получают стандартный usage error.
- **GAB-PM-071** — Poll из DM использует тот же remote relay-подход, что и say.
- **GAB-PM-072** — Giveaway из DM использует тот же remote relay-подход.
- **GAB-PM-073** — Remote-команда может ссылаться на сервер через персональный alias.
- **GAB-PM-074** — Пользовательский DM-интерфейс скрывает технические детали relay и показывает только статус операции.

## DM giveaway control

- **GAB-PM-075** — Giveaway можно полностью управлять из DM пользователя.
- **GAB-PM-076** — Поиск целевого сервера при DM giveaway учитывает точное имя.
- **GAB-PM-077** — Поиск сервера при DM giveaway учитывает case-insensitive имя.
- **GAB-PM-078** — Поиск сервера при DM giveaway учитывает server ID.
- **GAB-PM-079** — Поиск сервера при DM giveaway учитывает персональный server alias.
- **GAB-PM-080** — При remote giveaway проверяется, что пользователь действительно состоит в найденном сервере.
- **GAB-PM-081** — Пользователь, находящийся в server blocklist, не получает доступ к remote giveaway workflow.
- **GAB-PM-082** — Канал для remote giveaway разрешается отдельным channel search helper.
- **GAB-PM-083** — Некорректный канал выдаёт отдельную ошибку вместо общего failure.
- **GAB-PM-084** — Giveaway должен находиться в text channel для remote workflow.
- **GAB-PM-085** — Если giveaway уже идёт, его creator получает в DM предложение завершить его досрочно.
- **GAB-PM-086** — Creator может подтвердить досрочное завершение giveaway через DM.
- **GAB-PM-087** — Если creator отказывается, giveaway остаётся нетронутым.
- **GAB-PM-088** — Участнику текущего giveaway из DM предлагается выйти.
- **GAB-PM-089** — Отказ от выхода оставляет пользователя участником.
- **GAB-PM-090** — Если пользователь ещё не участник, DM workflow предлагает вступить.
- **GAB-PM-091** — После подтверждения вступления пользователь добавляется в participant list.
- **GAB-PM-092** — После отказа от участия бот явно сообщает, что пользователь ничего не выигрывает.
- **GAB-PM-093** — Создатель с достаточными правами может создать giveaway полностью через DM.
- **GAB-PM-094** — Создание giveaway в DM собирает secret/prize, title и duration отдельными вопросами.
- **GAB-PM-095** — Secret giveaway показывается только победителю.
- **GAB-PM-096** — Title отдельно запрашивается после secret.
- **GAB-PM-097** — Duration вводится человеком в формате, который понимает duration parser.
- **GAB-PM-098** — Для duration есть `.` как shortcut на стандартный 1 час.
- **GAB-PM-099** — Неверная duration автоматически заменяется безопасным default вместо падения workflow.
- **GAB-PM-100** — Каждый шаг создания giveaway имеет собственный timeout.
- **GAB-PM-101** — После создания пользователь получает подтверждение и имя целевого канала.
- **GAB-PM-102** — Remote giveaway permission проверяется уже на целевом сервере.
- **GAB-PM-103** — Maintainer-level access может обходить обычный server command level.
- **GAB-PM-104** — При недостатке прав remote workflow завершается понятным permission error.

## PM help / UX

- **GAB-PM-105** — Отдельная PM help-команда показывает именно доступные PM-команды.
- **GAB-PM-106** — PM help строится динамически из зарегистрированного command list.
- **GAB-PM-107** — Usage каждой PM-команды подтягивается из её metadata.
- **GAB-PM-108** — PM commands сортируются перед отображением.
- **GAB-PM-109** — Help содержит прямую ссылку на wiki с подробностями.
- **GAB-PM-110** — Deprecated PM-команда не удаляется мгновенно, а сообщает пользователю новый путь.
- **GAB-PM-111** — Deprecated config-команда перенаправляет пользователя на web dashboard.
- **GAB-PM-112** — Команда join в DM выдаёт готовую OAuth invite-ссылку.
- **GAB-PM-113** — Invite URL строится динамически из ID самого бота.
- **GAB-PM-114** — Успешные/ошибочные/ожидающие состояния DM-команд имеют разные визуальные цвета.
- **GAB-PM-115** — Длинные remote operations используют initial progress message с последующим edit.
- **GAB-PM-116** — Ошибка remote lookup содержит конкретную причину, а не только generic error.
- **GAB-PM-117** — Invalid usage всегда содержит фактический command name и usage из metadata.

## Общие выводы для InsaneBot

- **GAB-PM-118** — DM можно использовать как полноценную control-plane для серверных функций, а не только как место для личных команд.
- **GAB-PM-119** — Персональные server aliases особенно полезны как слой адресации для DM-команд.
- **GAB-PM-120** — Многошаговые DM-мастера должны иметь `quit`, timeout, сохранение предыдущих значений и edit текущего prompt.
- **GAB-PM-121** — Для remote-команд полезно разделять внутренние статусы поиска (`none/multi/success`) и пользовательские сообщения.
- **GAB-PM-122** — Remote-команды должны повторно проверять membership и permissions уже после определения целевого guild.
- **GAB-PM-123** — Secret/приватные параметры giveaway можно собирать в DM, оставляя публичным только безопасный title.
- **GAB-PM-124** — Empty-state каждого личного раздела должен сразу объяснять следующую команду/действие.
- **GAB-PM-125** — Для длинных workflow лучше редактировать одно progress-сообщение, чем создавать серию сообщений об ошибках.
