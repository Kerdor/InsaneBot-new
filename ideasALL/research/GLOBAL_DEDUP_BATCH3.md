# GLOBAL DEDUP — BATCH 3

Тематические области: Audio infrastructure / Filtering / Games / Trivia / Fun.

Правило: исходные тематические IDs сохраняются; канонический кластер объединяет одинаковую механику, а уникальные UX, ограничения и архитектурные варианты остаются внутри кластера.

## Audio / Media infrastructure

### GD-073 — Managed внешний media/audio node
Источник: AUDIO-001.
Канон: бот способен самостоятельно управлять внешним audio/media backend как дочерним процессом вместо обязательной ручной установки.

### GD-074 — Автоматическая установка runtime media-node
Источник: AUDIO-002.
Уникальная деталь GD-073: runtime backend может автоматически скачиваться в data directory модуля.

### GD-075 — Генерация конфигурации managed node
Источник: AUDIO-003.
Конфигурация внешнего node строится из настроек бота перед запуском.

### GD-076 — Preflight окружения для внешнего процесса
Источник: AUDIO-004.
Канон: до запуска проверяются runtime, версия и архитектура; это специализированный preflight для managed audio backend.

### GD-077 — Кэш результата runtime-проверки
Источник: AUDIO-005.
Уникальная оптимизация: успешные/неуспешные результаты проверки runtime кэшируются.

### GD-078 — Контроль ресурсов managed node
Источник: AUDIO-006.
Канон: настройка Xms/Xmx с проверкой доступной памяти перед запуском.

### GD-079 — Readiness по stdout/logs
Источник: AUDIO-007.
Канон: готовность внешнего процесса определяется по startup-сигналу в логах; ранний выход переводится в ошибочное состояние.

### GD-080 — Lifecycle manager внешнего процесса
Источники: AUDIO-008, AUDIO-012.
Канон: единый lifecycle с защитой от повторного запуска/shutdown, отслеживанием процесса и очисткой связанных async tasks/events.

### GD-081 — Диагностика плагинов внешнего node
Источник: AUDIO-009.
Версии/названия загруженных плагинов извлекаются из startup logs и доступны для диагностики.

### GD-082 — Managed / unmanaged backend mode
Источник: AUDIO-010.
Канон: пользователь может переключаться между встроенным управлением backend и уже существующим внешним backend через единый интерфейс настроек.

### GD-083 — Reset managed backend settings
Источник: AUDIO-011.
Специализированный reset настроек audio backend к значениям по умолчанию.

## Filtering / Content control

### GD-084 — Иерархический content filter
Источники: FILTER-001–003.
Канон: запрещённые слова/фразы могут задаваться на уровне сервера и канала; thread наследует правила родительского канала.

### GD-085 — Nickname/display-name filtering
Источники: FILTER-004–005.
Канон: тот же фильтр применяется к именам участников; при нарушении может автоматически назначаться безопасное fallback-имя.

### GD-086 — Rate-based filter enforcement
Источники: FILTER-006–007.
Канон: накопление filter hits в окне времени с автоматическим reset; превышение count/timeframe приводит к автобану.

### GD-087 — Точное и нормализованное совпадение фильтра
Источники: FILTER-008–009.
Канон: case-insensitive поиск с нормализацией и режимом word/phrase boundaries, чтобы не ловить части других слов.

### GD-088 — Расширенный filter pipeline
Источники: FILTER-010, FILTER-013.
Канон: фильтр работает не только с обычным message.content, но и с поддерживаемыми текстовыми полями Discord; edited messages проходят проверку повторно.

### GD-089 — Filter enforcement + moderation case
Источники: FILTER-011–012, FILTER-018.
Канон: filter hit удаляет сообщение и создаёт отдельный modlog case; превышение лимита создаёт отдельный filter-ban case. Для событий можно независимо настраивать reason/display.

### GD-090 — Automod immunity для filter pipeline
Источник: FILTER-014.
Интеграция с общей системой immunity/access control: доверенные участники обходят фильтр.

### GD-091 — Кэш compiled filter patterns
Источник: FILTER-015.
Уникальная техническая оптимизация: compiled regex кэшируется по guild/channel и инвалидируется при изменении правил.

### GD-092 — Управление большим списком filter rules
Источники: FILTER-016–017.
Канон: массовое добавление/удаление правил и выдача большого списка через DM с пагинацией; учитывается ошибка при закрытых DM.

## Games

### GD-093 — Каталог мини-игр как отдельный модуль
Источники: GAME-001–002, GAME-015, GAME-018.
Канон: игры выделяются в отдельный раздел/модуль и могут регистрироваться отдельными файлами, а не быть одной монолитной командой.

### GD-094 — Casino / gambling как игровой раздел
Источники: GAME-003, GAME-016; связь с GD-049.
Канон: казино может существовать как самостоятельный игровой раздел. Экономические ставки/слоты остаются частью GD-049, здесь фиксируется именно организационная модель Games/Casino.

### GD-095 — Набор независимых мини-игр
Источники: GAME-004–014, GAME-019–021.
Канон: отдельные игровые режимы вроде Chaos Words, Chess, Connect 4, Fast Type, Guess the Number, Flip, RPS, Dice и Coinflip. Названия игр не становятся отдельными глобальными системами, если их базовая игровая модель совпадает с уже имеющейся.

### GD-096 — Игровые рейтинги и статистика
Источники: GAME-022–023.
Канон: рейтинги игроков и persistent statistics по конкретным играм.

### GD-097 — Ежедневные игровые задания
Источник: GAME-024.
Уникальная механика: daily challenges привязывают игровые активности к периодическим заданиям.

### GD-098 — Игровые экономические награды
Источник: GAME-025; связь с GD-043.
Канон: победы/результаты игр могут начислять валюту через общий Economy API.

## Trivia

### GD-099 — Смешанный пул trivia-наборов
Источник: TRIVIA-001.
Несколько наборов вопросов объединяются и перемешиваются в одной сессии; настройки первого набора имеют приоритет.

### GD-100 — Пользовательские trivia-наборы
Источники: TRIVIA-002, TRIVIA-004.
Канон: загрузка собственных YAML question sets с валидацией, списком, удалением и метаданными author/description; загрузка attachment может иметь timeout/cancel.

### GD-101 — Конфигурация внутри trivia-набора
Источник: TRIVIA-003.
Уникальная возможность списка вопросов содержать собственный CONFIG с переопределением серверных настроек, при этом администратор может запретить такие overrides.

### GD-102 — Trivia victory condition
Источник: TRIVIA-005.
Сессия заканчивается при достижении заданного max score; лимит может задаваться для сервера.

### GD-103 — Два уровня trivia timers
Источник: TRIVIA-006.
Разделяются timer конкретного вопроса и inactivity timeout всей сессии; inactivity reset происходит при попытке ответа.

### GD-104 — Bot participant в Trivia
Источник: TRIVIA-007.
Если игроки не отвечают правильно за отведённое время, бот может получать очко как отдельный режим.

### GD-105 — Настраиваемый Trivia response UX
Источник: TRIVIA-008.
Канон: случайные фразы правильного/неправильного ответа, spoiler formatting для раскрытия ответа и отдельный UX перехода к следующему вопросу.

### GD-106 — Нормализованный Trivia answer matching
Источник: TRIVIA-009.
Канон: lowercase/smart-quote normalization, word/phrase matching, игнорирование других каналов и сообщений бота, человекочитаемые варианты boolean-ответов.

### GD-107 — Условная экономическая награда Trivia
Источник: TRIVIA-010; связь с GD-043.
Награда выдаётся только при минимальном числе игроков, при ничьей делится между победителями и рассчитывается от счёта; используется общий Economy API и учитывается max balance.

### GD-108 — Persistent Trivia statistics
Источник: TRIVIA-011.
Канон: wins/games/total_score хранятся отдельно от временного состояния текущей сессии.

### GD-109 — Channel-scoped concurrent Trivia sessions
Источник: TRIVIA-012.
В одном канале одновременно существует не более одной сессии; другие каналы могут иметь независимые игры.

### GD-110 — Forced Trivia stop
Источник: TRIVIA-013.
Отдельная команда принудительно завершает активную сессию и отличает нормальный итог от отмены task.

### GD-111 — Self-contained async game session lifecycle
Источники: TRIVIA-014; связь с GD-015.
Канон: игровая сессия является самостоятельной background task с безопасной обработкой ошибок и Discord NotFound/Forbidden.

## Fun

### GD-112 — Fun-команды как отдельный слой
Источники: FUN-001–0018.
Канон: развлекательные команды организуются отдельно от utility/moderation/game систем; Games при этом остаётся самостоятельным разделом.

### GD-113 — Random choice / random-response utilities
Источники: FUN-005, FUN-011, FUN-024.
Канон: команды, выбирающие случайный вариант/событие из набора. Не объединять с полноценными играми.

### GD-114 — Random media/fact fun commands
Источники: FUN-003–004, FUN-007–008, FUN-020, FUN-025.
Канон: случайные изображения, GIF, факты и поиск развлекательного медиаконтента.

### GD-115 — Fun user/media transformations
Источники: FUN-006, FUN-012–013, FUN-026.
Канон: операции над пользователем/контентом для развлечения: avatar, wanted poster, text reversal и контекстные message/image fun-команды.

## Cross-theme notes

- AUDIO-008 и GD-015 из Batch 1 пересекаются по background tasks/lifecycle, но GD-080 остаётся специализированным lifecycle внешнего OS-процесса.
- FILTER-011/012/018 используют moderation case infrastructure, но enforcement остаётся отдельной filter-механикой; общая case history из Batch 2 не поглощает filter rules.
- FILTER-014 использует общую ACL/immunity идею Batch 1, но не является новым permission layer.
- GAME-025 и TRIVIA-010 не создают отдельную экономику: выплаты идут через GD-043/GD-041.
- Trivia statistics остаются отдельной игровой статистикой и не превращаются автоматически в общий leaderboard.
- Casino organization (GD-094) не дублирует slot machine mechanics GD-049.
