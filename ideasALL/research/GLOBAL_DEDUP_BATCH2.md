# GLOBAL DEDUP — BATCH 2

Тематические области: Economy / Community / Customization.

Правило: исходные IDs сохраняются; канонический кластер объединяет одинаковую механику, а уникальные настройки и варианты поведения остаются внутри кластера.

## Economy

### GD-028 — Базовый пользовательский баланс
Источники: ECON-001, ECON-025.
Канон: личные денежные средства пользователя. Вариант с двумя балансами (кошелёк/банк) не теряется и вынесен в GD-029.

### GD-029 — Разделение кошелька и банковского счёта
Источники: ECON-025–026, ECON-037.
Канон: `Money` и `Bank` как отдельные средства с deposit/withdraw и раздельными leaderboard.

### GD-030 — Магазин и инвентарь экономики
Источники: ECON-002–003.
Канон: магазин товаров + пользовательское хранение приобретённых предметов. Вариант продажи Discord-ролей вынесен в GD-031.

### GD-031 — Магазин Discord-ролей за валюту
Источник: ECON-031.
Уникальная механика: товар магазина может быть реальной Discord-ролью; покупка через select menu выдаёт роль после проверки баланса. Fishing Rod может быть обычным предметом того же магазина.

### GD-032 — Периодические денежные награды
Источники: ECON-004, ECON-027–028, ECONA-001.
Канон: cooldown-based rewards. Сохраняются независимые daily/hourly/weekly/monthly/yearly таймеры, отдельный weekly present и per-user PayDay cooldown.

### GD-033 — Ролевой размер периодической награды
Источник: ECONA-002.
Уникальная механика: сумма PayDay зависит от роли; выбирается максимальная доступная пользователю роль с заданной выплатой.

### GD-034 — Активный заработок через работу
Источники: ECON-005, ECON-035.
Канон: work-команда выдаёт случайную профессию/сценарий и денежную награду с cooldown.

### GD-035 — Beg / случайная малая выплата
Источник: ECON-006.
Отдельный простой источник дохода через просьбу с небольшой случайной наградой.

### GD-036 — P2P-перевод валюты
Источники: ECON-007, ECON-017, ECON-032.
Канон: перевод средств между пользователями с проверкой баланса. Сохраняются защиты: нельзя платить себе, отрицательная сумма запрещена, недостаток средств блокирует операцию.

### GD-037 — Административное управление балансом
Источники: ECON-014–016.
Канон: admin set/deposit/withdraw. Уникальный UX: один интерфейс может интерпретировать число как установку, `+N` как пополнение и `-N` как снятие.

### GD-038 — Лимит максимального баланса
Источник: ECON-021.
Канон: configurable max balance для защиты экономики от неконтролируемого роста.

### GD-039 — Коррекция выплаты при достижении max balance
Источник: ECONA-007.
Отличие от GD-038: при начислении сверх лимита награда не обязательно отклоняется; баланс может быть зажат до максимума, а пользователю показывается фактический итог.

### GD-040 — Экономический leaderboard
Источники: ECON-020, ECON-037, ECONA-008.
Канон: рейтинг богатства. Сохраняются варианты: произвольный размер top, пагинация по 10, отображение позиции инициатора, embed/text, отдельные рейтинги Money/Bank.

### GD-041 — Общий Economy API
Источники: ECON-022–024.
Канон: экономика предоставляется другим модулям через API операций balance/check-spend/set/deposit/withdraw/transfer/leaderboard/purchase.

### GD-042 — Платные действия как общая интеграция
Источник: ECON-023.
Уникальная архитектурная деталь GD-041: сторонний модуль может объявить `cost`, а общая экономика выполнить оплату и корректно прервать действие при отказе.

### GD-043 — Награды из других игровых систем
Источник: ECON-024.
Интеграционный вариант GD-041: игры и другие системы начисляют валюту через общий Economy API вместо собственной валютной логики.

### GD-044 — Рискованная кража валюты
Источники: ECON-008, ECON-033.
Канон: rob как PvP-экономическая механика. Сохраняются ограничения Corwin: цель не бот, у инициатора минимум 200, cooldown 10 минут, случайная сумма, банковские средства не затрагиваются.

### GD-045 — Crime / риск-награда
Источники: ECON-009, ECON-034.
Канон: случайный сценарий преступления + вероятность успеха + случайная награда + cooldown. Сохраняется факт, что cooldown фиксируется и при провале.

### GD-046 — Mine / добыча как источник дохода
Источник: ECON-010.
Отдельный активный источник дохода; не объединять с Fishing/Hunt только из-за общей модели «мини-активность → награда».

### GD-047 — Fishing как предметно-зависимая активность
Источники: ECON-011, ECON-030.
Канон: fishing с cooldown и случайным результатом; уникальная деталь Corwin — обязательная Fishing Rod с ограниченным числом использований и поломкой.

### GD-048 — Hunt
Источник: ECON-029.
Отдельная охота с cooldown и случайной добычей. Денежную награду не считать частью канона, так как в исследованном исходнике выплата фактически не выполняется.

### GD-049 — Gambling / slot machine
Источники: ECON-012, ECONA-003–006.
Канон: азартные игры за валюту. Для slot machine сохраняются 3 барабана, таблица комбинаций/выплат, min/max bet, отдельный cooldown и отдельная команда просмотра payout table с возможностью DM.

### GD-050 — Global vs server economy mode
Источник: ECONA-009; также ECON-013.
Канон: экономика может быть глобальной или серверной. Настройки, состояние и область cooldown зависят от выбранного режима; название валюты также может задаваться отдельно для режима/области.

### GD-051 — Настраиваемое название валюты
Источник: ECON-013.
Отдельная настройка экономики: currency name с отдельными значениями для глобального/серверного банка.

### GD-052 — Экономический reset
Источники: ECON-018, ECON-036.
Канон: полный административный сброс экономики. Сохраняется более безопасный UX Corwin: кнопки confirm/cancel, только инициатор, timeout 60 секунд, отмена по истечении времени; сбрасываются экономика, cooldown и магазин.

### GD-053 — Очистка неактивных экономических записей
Источник: ECON-019.
Обслуживание экономики без полного reset: prune устаревших банковских записей.

## Community / Social / Server features

### GD-054 — Giveaway
Источники: COMM-001–003.
Канон: розыгрыш с несколькими победителями, автоматическим выбором и reroll. Количество победителей является настройкой конкретного giveaway.

### GD-055 — Join-to-create voice channels
Источник: COMM-004.
Канон: пользователь входит в специальный voice trigger и получает временный личный канал.

### GD-056 — Server counters
Источник: COMM-005.
Канон: динамические voice/channel counters с информацией о сервере, например количестве участников и пользователей в голосовых каналах.

### GD-057 — Self-service role panels
Источники: COMM-006, CUST-009–012.
Канон: пользователь сам получает/снимает роли через интерактивную панель. Сохраняются reaction roles, button roles, select-menu roles и несколько ролей в одной панели.

### GD-058 — Birthday system
Источник: COMM-007.
Канон: хранение даты рождения пользователя и автоматическое поздравление; часовой пояс пользователя учитывается при определении даты.

### GD-059 — User notes
Источник: COMM-008.
Канон: модерационные/служебные заметки о пользователе, не являющиеся наказанием.

### GD-060 — Moderation case history
Источник: COMM-009.
Канон: отдельные case-записи, связывающие модерационные действия с историей пользователя.

### GD-061 — Ticket workflow ownership
Источник: COMM-010.
Уникальная ticket-механика: сотрудник может claim-нуть тикет и стать ответственным за него.

### GD-062 — Ticket priority
Источник: COMM-011.
Уникальная ticket-механика: назначение приоритета обращению.

### GD-063 — Ticket count limits
Источник: COMM-012.
Уникальная ticket-механика: ограничение количества одновременно создаваемых тикетов.

### GD-064 — Ticket transcripts
Источник: COMM-013.
Канон: сохранение содержимого закрытого тикета для истории/аудита.

## Customization

### GD-065 — Custom commands
Источники: CUST-001, CUST-028–032.
Канон: пользовательские команды/ответы. Сохраняются fuzzy search, raw-view, metadata автора/редакторов/дат, индивидуальные cooldowns.

### GD-066 — Custom command aliases / shortcuts
Источники: CUST-026–027.
Канон: alias существующей команды с глобальной или серверной областью; alias может хранить заранее заданные аргументы, к которым добавляются аргументы вызова.

### GD-067 — Keyword / trigger auto-responses
Источники: CUST-002–003, CUST-019.
Канон: автоматические ответы на keyword/custom/regex triggers; сохраняется лимит/настройка количества независимых правил как вариант конфигурации.

### GD-068 — Custom response placeholders
Источник: CUST-004.
Канон: переменные/placeholder-и внутри пользовательских автоматических сообщений.

### GD-069 — Custom embeds
Источник: CUST-005.
Канон: пользовательские embed-сообщения как отдельный инструмент настройки ответов.

### GD-070 — Welcome / goodbye messages
Источники: CUST-006–007.
Канон: настраиваемые сообщения при входе и выходе участника.

### GD-071 — Per-server module configuration
Источники: CUST-013–018, CUST-021–025.
Канон: серверные настройки каналов, ролей, включения модулей, экономики, XP и тикетов; автосоздание базовой конфигурации; просмотр, сброс, экспорт и импорт настроек.

### GD-072 — Randomized custom command responses
Источник: CUST-029.
Уникальная возможность custom command иметь несколько вариантов ответа и случайно выбирать один; варианты должны быть совместимы по аргументам.

## Cross-theme notes

- ECON-002/003 и CUST-016 остаются разными уровнями: магазин/инвентарь — механика, server economy settings — конфигурация.
- COMM-006 и CUST-009–012 объединены в GD-057, потому что отличаются интерфейсом выдачи роли, но реализуют одну базовую self-service role-механику.
- ECON-020 и ARCH-009 из Batch 1 пересекаются только инфраструктурой пагинации: leaderboard остаётся GD-040, reusable pagination остаётся GD-014.
- ECON-022 и ARCH-008/025 из Batch 1 пересекаются архитектурно, но Economy API остаётся предметным сервисом GD-041.
